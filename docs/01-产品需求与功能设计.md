## 1. 背景、目标与首个业务闭环

### 1.1 准确产品定位

Script Tools 是面向个人用户的商业化通用脚本管理、发布、部署与付费使用平台。用户可以上传不同用途的脚本，自用或作为服务发布；消费者可购买发布者已部署好的脚本服务，填写业务参数并获得执行结果。门票预约、代抢是其中一个重要业务场景，可按城市、景点选择服务；平台不限定全部脚本都与旅行有关。

2026-11-13 用户明确纠正：不是企业ERP，不建设组织、部门或业务审批体系，不需要人工审核角色；既保留通用脚本能力，也必须有商业化交易闭环。首期只支持按次使用付费；门票场景以免费预约景点为主，脚本服务费与门票费用是两件事。本版替代此前“商业化后置、用户主要操作技术资源、共享须人工审批”的错误描述。

“任意用途脚本”表示业务动作和参数可由发布者定义，不自动意味着任意语言、宿主权限或执行环境都已支持。沿用当前Python/Node.js、HTTP/HTTPS、Docker/KVM/显式TCG技术设计；扩大运行能力需另补协议及验证，不能在页面上虚构兼容。

### 1.2 两侧用户与平台价值

- 消费者：发现服务、了解用途/价格/交付规则、按次购买、配置使用、跟踪结果、办理售后。无需自行安装依赖、部署代码或理解节点和镜像。
- 脚本发布者：上传代码与Schema、构建测试、部署、定义服务和价格、本人发布上架、维护可用性、查看销售与收益。一个个人账号可同时消费与发布。
- 平台：承载商品交易、支付、权益、执行调度、结果交付、退款、结算以及基础设施。自动校验是发布条件，人工批准不是发布步骤。

### 1.3 首期完整闭环

发布者上传脚本 → 校验封存 → 构建测试 → 部署就绪 → 配置按次服务和交付/退款规则 → 本人发布上架 → 消费者选择服务并填参 → 获取报价 → 创建服务订单 → 支付服务费 → 获得一次使用权益 → 启动完整服务执行 → 查看结果/产物/通知 → 必要的补充或核验 → 完成履约或退款 → 发布者收益结算。

门票场景增加：选择城市/景点/日期时段/票种/出行人 → 购买对应代抢服务 → 在约定窗口内轮询预约 → 核验外部预约结果 → 展示预约凭证。免费预约的门票费用为0，平台服务费按价格方案收取。无票、脚本完成、外部预约成功、退款到账分别展示。

### 1.4 不混淆的结果

支付成功只证明服务订单收款，不能证明脚本完成或预约成功。脚本正常退出不证明业务目标达成；预约成功须可信核验。一次服务执行内的接口请求、受控重试和人工接续不重复收费。产品不承诺未验证渠道可用或保证抢票成功；购买前明确一次服务范围、截止时间、成功口径和退款规则。

## 3. 范围与分期边界

### 3.1 本版包含

- 公开脚本服务市场、分类检索、服务详情、按次价格和部署可用性。
- 发布者上传/编辑/封存/构建/测试/部署、商品配置、自动检查后发布、停销及存量履约。
- 消费者报价、下单、支付、一次使用权益、配置使用、任务/结果/产物、通知、退款售后和账单。
- 发布者销售、使用质量、收益账本、结算及收款资料；平台交易对账和异常处理。
- 城市、景点、免费预约票种、代抢服务、出行人、预约授权和外部结果核验。
- 私有脚本自用、通用动作/Schema、有限/持续运行、三种执行方式及完整日志运维。

### 3.2 本版不包含

- 企业组织、部门、租户、工作流审批及人工脚本发布审核。
- 订阅收费、自动续费、自动续购、充值钱包、服务费与门票款混合代收。
- 首期门票代付与票务转售；付费景点若后续接入须另定票款及履约规则。
- 浏览器、桌面或原生小程序UI自动化，以及未经实现验证的语言/权限能力。
- 绕过外部渠道验证、未验证景点成功承诺、失败或未知结果的盲目重放。

验证码、外部登录或资料补充通过待处理入口交给本人；重新核验后继续同一次服务，不因本人点击完成就标预约成功。

## 4. 角色、权限与业务对象

<a id="role-decisions"></a>

### 4.1 角色与工作区

| 角色 | 主要目标 | 菜单及数据范围 |
| --- | --- | --- |
| 游客GUEST | 发现可用服务 | 平台首页、脚本市场、服务详情、城市景点、帮助和登录；只读公开信息 |
| 消费者USER | 按次购买并使用服务 | 本人订单、支付、权益、任务、结果、凭据、出行人、消息及售后 |
| 脚本发布者PUBLISHER | 发布部署并售卖脚本能力 | 本人代码、构建、部署、商品、价格、销售摘要、诊断、收益结算；不能读取消费者秘密或私有结果 |
| 平台管理员ADMIN | 维护交易运营和系统运行 | 服务与场景配置、订单异常、资金对账、结算、基础设施和操作审计；按具体后台能力限制 |

消费者与发布者是同一账号的两种工作区；任何有效个人账号都可进入发布者工作区。原型按实际工作区菜单出图，发布者的消费功能通过切换消费者工作区使用，不重复创建一套消费权限。管理员回个人工作区仍只操作本人数据。后台能力如commerce.manage、runtime.manage、catalog.manage、access.manage和data.diagnose是权限范围，不增加人工审核角色。

平台展示的服务使用权与源码权分开：付费使用不默认允许下载、修改或转售发布者代码。公开Schema和服务说明可读；消费者输入、凭据、日志与产物依归属保护。平台排障要有相应能力、明确对象/用途、短时凭证和访问审计，不设置人工审批流，也不开放密钥明文。

首次进入发布者工作区时，已验证账号填写公开昵称、服务简介与公开联系说明，阅读并确认当前发布者约定后开通。取消返回消费者首页，已有有效资料直接切换。资料可在发布者设置中维护，已停用资料通过当前停用处置流程处理。具体输入、修订及重复提交规则见[发布者资料协议](./03-接口协议.md#publisher-profile-api)。

### 4.2 关键业务对象

| 对象 | 含义 | 关系与边界 |
| --- | --- | --- |
| Script/ScriptVersion | 作者的代码及固定版本 | 私有自用或支撑多个服务版本，不直接等于商品 |
| Deployment | 已构建版本的托管部署能力 | 绑定制品、运行模板和健康状态；不同消费者仍按Attempt隔离 |
| Service/ServiceRelease | 可购买的服务商品及不可变成交版本 | 固定脚本、部署、动作、Schema、交付/退款规则和场景 |
| PricePlan/Quote | 按次价格与短时结算报价 | 服务端算价；发布者改价不覆盖既有报价或订单 |
| ServiceOrder/Payment/Refund | 平台脚本服务交易与资金记录 | 每单一次服务；支付、退款各有渠道回执，不由脚本写入 |
| Entitlement/UsageReservation | 已购一次使用权及消耗记录 | 同一有效逻辑Run的重试、接续、多批产物不重复扣次 |
| Task/Run/Attempt/Invocation | 配置、逻辑服务执行、技术尝试、业务动作调用 | 服务订单关联履约；私人测试使用开发配额，不伪造收费订单 |
| Result/Output/Notification | 执行结果、交付产物、消息 | 分别显示状态；通知失败不重新执行或扣费 |
| City/Attraction/Channel | 城市、景点和外部预约渠道 | 门票场景的目录与规则，通用服务不要求这些字段 |
| BookingOperation/BookingOrder | 外部预约意图及已核验事实 | 与平台ServiceOrder分开；免费票款为0/NOT_REQUIRED |
| Ledger/Settlement/Payout | 收入退款费用分成、结算及打款 | 只追加账本和冲正；打款受理不等于到账 |

## 6. 典型使用场景

| 场景 | 入口与操作 | 正常出口 | 异常出口 |
| --- | --- | --- | --- |
| 数据汇总服务 | 市场选择→按次购买→填入数据范围→启动 | 下载本次报告，消耗一次权益 | 平台未执行退回权益或退款；外部结果未知先核验 |
| 免费景点代抢 | 城市景点→服务→日期人员授权→支付服务费 | 在约定窗口执行并核验预约；展示免费预约凭证 | 无票按发布者公示规则结束或退费；资料待补接续；未知预约先核验 |
| 脚本自用 | 上传→构建测试→本人授权运行 | 个人结果与日志 | 使用开发配额，失败诊断，不生成消费者付款 |
| 发布售卖 | 部署就绪→服务介绍/单次价格→自动检查→本人发布 | 用户可购买并使用；收入进入待结算账本 | 配置不完整无法上架；部署故障停止新售卖 |
| 改价与升级 | 新价格/服务版本→发布 | 只影响新报价，旧订单履行旧快照 | 旧版本不能履行时补偿退款，不能强制静默迁移 |
| 取消退款 | 订单查看使用阶段与规则→申请停止/退款 | 权益撤销和渠道退款分别确认 | 在途结果先核验；退款未知查回执不重复退 |

## 8. 页面、菜单与角色操作清单

### 8.1 页面归属与显示规则

以下清单是当前产品页面基线，来自[机器目录](./contracts/ui-role-catalog.json)。菜单和可路由详情/编辑页均独立覆盖；对话框和同页页签不重复计页。消费者可从账户/发布入口切换发布者工作区；没有审核工作区。技术模式由服务部署决定，不把选择节点和镜像作为消费者购买步骤。

核心与交易为P0；门票场景按已验证渠道开放，并在首页/市场有发现入口，无每用户“开启旅行场景”开关。Git/URL来源同步为P1；Webhook为通知设置中的P1页签，追踪和个人API仍属后续技术能力。首期不显示订阅、自动续费、充值钱包或门票代收菜单。

## 9. 账户、个人资料与凭据

账户页提供注册、邮箱验证、登录退出、会话查看、密码找回、邮箱变更、冻结状态和注销进度。找回与改绑页面不泄露账号是否存在；注销分别展示即时访问停止、物理清理和备份淘汰进度。脚本发布者不能读取使用者的参数、凭据、运行记录或产物。

凭据页保存 Cookie、Token、API Key、必要会话字段及已验证刷新材料，展示掩码、版本、更新时间、绑定任务和有效状态；无凭据需求的脚本无需填写。检查有效性使用受控任务，不能在 Web 服务内执行用户代码。更新、撤销及账号操作的状态影响以 [账号与凭据生命周期](./02-系统架构与详细设计.md#accounts) 为准。私人资料在服务端校验归属；出行人和预约授权仅在旅行场景启用时出现。

账号页面的错误/处理中/空状态均属于交付范围。注销后仅受限回执可查清理进度，不开放原数据；解冻和更新凭据不会默默补跑旧任务。

## 10. 脚本中心与开发者体验

发布者上传脚本包或编辑草稿，填写入口、依赖锁、动作、输入输出Schema、网络/凭据声明及资源需求。自动校验后封存不可变版本，隔离构建、测试并创建部署。只有部署READY且服务介绍、单次价格、目标判定与发布者所选退款规则、收款资料完整时，发布者才能显式发布商品；不存在人工审核申请或批准节点。

脚本内容DRAFT/SEALED/READY/RETIRED/REVOKED、构建QUEUED/RUNNING/SUCCEEDED/FAILED/CANCELLED、部署状态和商品上架状态分别展示。发布服务使用权不默认公开源码；消费者不能编辑别人的代码。创建或更新服务版本不能覆盖已经售出的合同快照。

试运行创建本人完整授权的测试Task/Run，使用开发配额，不伪造交易支付。部署重试不重跑消费者业务。停销仅停止新购买；危险版本撤销可停止新调用，但须保留在途核验与受影响订单补偿。Git/URL同步为P1，来源变化只生成候选草稿，不自动上架或替换存量版本。

## 11. 任务配置、长期运行与快捷操作

消费者从已购服务生成任务：固定service_release、entitlement与参数，模式/资源由部署模板派生；首期付费服务每单只启动一次逻辑Run，内部重试和continuation沿用本次权益。manual、once以及有服务截止时间的service可售卖；不以Cron/interval自动连续扣费。下面通用计划能力同时支持发布者私有自用，不能绕过服务购买限制。发布者在S04“版本与测试→本人自用”页签选择本人READY版本，填写参数、计划及本人授权，经预览后启用PRIVATE_SELF_USE任务；仅脚本所有者可走自用配额。测试按钮另建AUTHOR_TEST一次性任务，两者都不伪造服务订单或Payment。S04显示本人自用任务摘要；进入任务/运行详情时切换到消费者工作区的C08～C11并定位同一对象。“我的任务”按付费服务/本人自用筛选，只有购买服务的任务显示收费权益；普通用户不能借自用入口运行他人未购买脚本。

1. 选择脚本及固定版本，无需先选择景点或某种预设业务类型。
2. 从发布者 actions 选择动作，默认选择 default_action；可选使用已启用业务模板。
3. 按所选动作有效 JSON Schema 动态填参，预览对应输出说明。
4. 按需绑定凭据并确认执行权限；旅行场景任务才填写出行人及预约授权。
5. 选择 finite 或 continuous；有限任务设置单次/周期/手动计划，持续任务设置 service/manual；选择适用的时区、结束条件和错过策略。
6. 选择执行方式、资源模板及允许的 TCG 行为。
7. 选择通知策略，检查任务预览后启用。

预览展示脚本版本、所选动作及有效 Schema、参数校验、授权、模式可用性和资源模板。调度设置与业务参数分区展示。“任务创建成功”仅表示配置保存，不代表脚本已执行或外部业务已完成。

购买前填参、已购服务配置、发布者测试/本人自用及人工接续共用参数编辑体验。字段和必填规则来自所选版本及动作；普通表单无法完整表达时提供JSON编辑入口，并说明切换原因。两种编辑方式保留相同输入及校验约束，不悄悄补值、删字段或转换类型；切换动作/版本先提示未保存内容，再按新规则重新校验。具体渲染、错误定位和版本绑定要求见[动态参数表单契约](./03-接口协议.md#schema-form)。

### 11.1 计划与长期运行

创建页先选择 finite 或 continuous，再展示适用的计划、截止及恢复设置。finite 支持手动、单次、五段 Cron 或秒级 interval；continuous 使用 service/manual 一次启动，在同一 Run 内持续处理业务并多次产出。界面展示未来 5 个有效触发时间、时区与 UTC、错过策略和不重叠规则；不支持的六段 Cron/宏保留原文并提示迁移，不猜测转换。

持续任务显示驻留时长、租约/节点健康、最近进度、最近产物、累计/当日用量、检查点和停止进度。无输出可能是正常等待；失联、无业务进度、输出失败及配额不足分别展示。仅支持 final 采集的旧脚本提示文件将在结束后收集，需要运行中产出时改用连续交接。

### 11.2 操作与列表

| 操作 | 对未来触发的影响 | 对当前执行的影响 |
| --- | --- | --- |
| 暂停 | 停止新计划触发并取消尚未领取的计划 Run | 已领取和显式手动 Run 不自动中断，取消当前执行为独立操作 |
| 恢复 | 从下一次有效时间继续 | 不补发已过期或副作用不确定的业务动作 |
| 取消当前运行 | 不必改变任务计划 | 撤销后续外部调用能力并停止执行；可能发生副作用时保留未知状态并核验或转人工 |
| 编辑任务 | 新配置版本应用于未来运行 | 已执行的快照不变，排队实例按新版本策略作废或重建 |
| 归档 | 停止任务 | 有未知副作用或扩展待核验对象时保留处理记录，不直接删除 |
| 手动运行 | 新建带独立触发 ID 的运行实例 | 仍受权限、配额和重复执行策略限制 |

搜索、本人标签、置顶和过滤属于展示偏好，不进入脚本 input。建议每任务最多 10 个标签，每标签 32 字符；复制任务创建 DRAFT，凭据、渠道和授权重新绑定确认，不复制密钥或运行记录。手动运行跳转准确的本次 Run；已有非终态 Run 时显示阻塞及当前运行链接。暂停后续启动、停止当前和取消当前分别提供，按钮结果不把“请求已接受”显示为“进程已停止”。

调度、错过窗口、次数、任务终态及停止的唯一规则见 [任务与调度](./02-系统架构与详细设计.md#tasks) 和 [持续运行设计](./02-系统架构与详细设计.md#continuous)。

## 12. 结果、产物与通知中心

通用结果展示脚本摘要、按动作输出 Schema 校验的数据、来源及可信程度。结果格式有效不代表外部业务已核验；纯 legacy 进程结束显示 PROCESS_EXIT。大型内容以授权产物引用呈现，不执行返回的 HTML/JavaScript。

产物区统一展示文本、JSON、各种文件和消息，按批次/序列分页。每项显示名称、种类、阶段、格式、大小、生成状态、当前可用性、期限、预览/下载及投递原因。未知格式可下载；同名文件可在不同批次保留，运行中产物可立即发布。业务执行、产物生成、附件等待、投递和清理分别显示，后生成产物不改写已接受结果。

通知中心提供站内与邮件、用户订阅、渠道绑定、已读和投递查询，覆盖运行、待处理、凭据、到期及开发者自定义事件。其他渠道按适配阶段接入。用户确认接收渠道；作者不能任意选择收件人。消息使用纯文本或受限 Markdown，附件默认是鉴权链接。渠道不支持格式时显示降级结果；文件过期与权限变化反馈明确。

“服务商接受”“用户已读”“业务已核验”是不同事实。通知失败不回滚结果，不触发业务重跑；同一次登记重传与脚本有意再次产出分开处理。具体状态、去重和附件依赖见 [通知一致性设计](./02-系统架构与详细设计.md#notifications)。

## 13. 人工处理与操作反馈

待处理页面展示原因、说明、期限、允许的恢复动作和当前阻塞。用户提交完整新输入，系统按恢复动作的 Schema 校验；原输入和历史结果不覆盖。未知外部效果优先核验或人工处理，界面不提供绕过未知状态的“重试原动作”。手工结案显示 USER_REPORTED，关闭未知保留其未解决事实；终态任务不原地重开。

恢复、停止、保存和删除显示提交中状态；412 展示修订差异并刷新，409 显示阻塞原因，422 定位字段。请求超时先查回执，不鼓励反复点击重新执行业务。任务、Run、Attempt、结果、效果、可信程度、产物、通知和清理分栏显示，错误及缺口不能统一压缩成“失败”。状态转换及原子恢复规则只在 [人工接续与结案](./02-系统架构与详细设计.md#continuations) 维护。

### 13.1 常见异常的用户反馈

| 错误类别 | 用户可见说明 | 自动行为 |
| --- | --- | --- |
| `AUTH_EXPIRED` | 登录信息失效 | 等待更新，停止无效重试 |
| `RATE_LIMITED` | 渠道暂时限流 | 尊重 Retry-After、退避和渠道预算 |
| `NETWORK_ERROR` | 请求未完成 | 查询按策略重试；提交进入核验 |
| `SCRIPT_ERROR` | 脚本执行异常 | 展示脱敏错误，限制连续失败 |
| `PROTOCOL_ERROR` | 输出不符合协议 | 不应用业务结果，提示脚本作者修复 |
| `RUNTIME_UNAVAILABLE` | 当前执行方式无可用节点 | 排队、显式回退或失败 |
| `RESOURCE_EXCEEDED` | 超出资源或时长限制 | 终止环境并回收，处理在途预约 |
| `POLICY_DENIED` | 网络、模式或权限不被允许 | 拒绝执行并记录策略版本 |
| `ORDER_UNKNOWN` | 无法确认预约结果 | 保留核验任务，通知用户 |
| `SIDE_EFFECT_UNKNOWN` | 无法确认自定义动作的外部效果 | 有核验机制则核验，否则转人工；不自动重放 |

## 14. 执行方式与资源选择

以下资源选择面向发布者部署/私有自用和平台调度。消费者的服务表单展示必要的使用限制和交付时长，默认不要求选择Docker、KVM、TCG或节点；实际模式可在技术详情只读查看。

| 页面选择 | 实际实现 | 配置规则 |
| --- | --- | --- |
| Docker | Docker+runc，脚本在独立容器内运行 | 默认模式，不能改为平台未声明的运行时 |
| QEMU+KVM | 外层 Docker 承载 QEMU，通过 `/dev/kvm` 启动客户机 | 节点完成 KVM 能力验证后才接收任务 |
| QEMU+TCG | 外层 Docker 承载 QEMU 软件模拟客户机 | 管理员允许且任务显式启用 TCG |

每次运行展示 `requested_execution_mode`、`actual_execution_mode`、回退原因、节点、镜像版本、资源模板及准备耗时。

KVM 不可用时允许的处理顺序为：选择其他 KVM 节点 → 在窗口内排队 → 满足双重许可及时间策略时转 TCG → 无可用路径时明确失败。运行已经开始或预约可能已经发出后，禁止通过切换执行方式直接重放。

资源模板由管理员维护。用户只能选择允许的模板，不能传入宿主挂载、特权容器或任意设备配置。取消完成后还应显示环境清理状态，清理失败不能隐藏为已完全回收。

## 15. 日志、监控与管理页面

展示计划时间、入队时间、准备开始、环境就绪、首次请求、提交开始、结果核验、结束和清理完成时间。记录关联的脚本版本、镜像摘要、参数摘要、凭据版本 ID、节点、租约代数和实际执行方式。

日志分为平台事件、脚本输出和受控请求摘要。默认隐藏请求头、请求体和完整响应，不将任意 HTML/ANSI 控制序列作为可执行内容展示。下载接口仍校验账号归属和有效期。运行详情标识日志缺口、截断、索引延迟和数据保留范围；详细交互见 F15。

| 子功能 | 用户侧 | 管理侧 | 规则 |
| --- | --- | --- | --- |
| 日志浏览 | 本人任务，按时间、来源、级别筛选 | 按授权查询运行和平台日志 | 客户端不能传任意查询语句；服务端强制归属过滤 |
| 实时跟随 | 运行详情自动追加、暂停跟随、断线恢复 | 多节点运行排查 | 业务事件与日志采用不同事件类型；缺口单独提示 |
| 时间线 | 查看计划、运行、订单、通知和清理 | 关联租约、节点、出口请求与故障 | 以可信业务事件为准，脚本输出不改变业务状态 |
| 导出 | 本人脱敏 JSONL 或纯文本 | 受权限约束的诊断导出 | 异步任务、大小上限、短期下载、访问审计 |
| 监控总览 | 本人检查次数、任务状态和通知记录 | API、调度、执行、预约、渠道、存储和监控自身 | 用户聚合从授权业务数据计算，不开放全局指标查询 |
| 运行方式 | 当前请求与实际执行方式 | Docker/KVM/TCG 分开展示容量和失败原因 | 外层 QEMU 资源与客户机指标分开，不重复相加 |
| 告警处置 | 查看与本人任务有关的待处理提示 | 规则、事件、确认、静默、升级、处置和恢复 | 运维告警不直接向所有用户广播，也不自动重提预约 |
| 保留和删除 | 查看保留期限、删除请求与导出过期 | 全局策略、清理进度、存储预算 | 不提供租户设置；用户不能更改平台审计保留策略 |

空状态需区分：尚未输出、没有匹配、无权访问、日志已过期、采集异常、索引追赶中、已截断和归档查询中。告警详情记录首次发现、最近发生、确认人、静默到期、处置记录、恢复与投递状态。规则阈值、接口协议、采集链路和验收步骤见 [部署运维与监控手册](./04-部署运维与监控手册.md#logging)。

## 16. 门票预约业务场景规则

通用目录保存脚本名称、说明、作者、自定义分类、版本、动作及所需权限。用户可以不选任何业务分类直接上传自定义脚本。以下景点字段和行为仅适用于旅行场景，不是脚本上传或执行的必填条件。

### 16.1 字段

景点名称、城市、介绍；渠道名称、官方入口、接口域名、时区、适配状态、支持票种、放票规则、人工操作说明、规则来源链接及核验时间。

渠道适配状态建议为 `UNVERIFIED`、`MONITOR_ONLY`、`BOOKING_SUPPORTED`、`DEGRADED`、`DISABLED`。支持自动预约必须同时具备有效的提交和结果核验能力。

### 16.2 行为

- 规则变更形成版本，已有任务展示变更提示，不静默修改预约日期或授权条件。
- 停用渠道时阻止新执行；已提交预约仍允许通过受控查询进行对账。
- 放票时间采用结构化配置；无法确认的规则以说明展示，不能伪造准确时间。
- 初始目录中的北京景点仅作为候选，首期上线清单以适配验证记录为准。

### 16.3 出行人

本节的出行人和预约授权只在门票场景使用，普通脚本不要求这些字段。免费景点门票费用为0、票款状态NOT_REQUIRED，脚本服务费仍按平台服务订单支付；首期不进行门票代收代付。

保存景点所需的最少实名字段，敏感内容加密，通知和日志只出现掩码。任务明确引用出行人快照，修改资料不静默改变已经授权的预约内容。

### 16.4 预约授权

授权表单展示景点、渠道、出行日期、时段、票种、人数、出行人、最大金额和截止时间。替代日期、替代时段和部分成功必须明确配置；默认关闭。授权撤销后不能继续发起新预约，但在途结果仍需核验。

### 16.5 库存状态

| 状态 | 含义 | 通知策略 |
| --- | --- | --- |
| `NOT_RELEASED` | 尚未放票 | 通常不重复通知 |
| `AVAILABLE` | 当前渠道存在符合条件的库存 | 满足变化和冷却条件时通知 |
| `SOLD_OUT` | 已确认无符合条件的库存 | 记录，可按用户设置通知变化 |
| `CLOSED` | 渠道关闭或目标日期不开放 | 通知并按策略停止检查 |
| `UNKNOWN` | 请求失败、结果不可解释或信息不足 | 不能当作无票；按异常策略处理 |

库存数量未知时使用 `null`，不能用 0 代替。必须保存观察时间、票种、日期、时段、数量/余量描述、渠道和结果可信程度。验证码、凭据过期、限流等放入错误类别，不与库存事实混为一类。

### 16.6 库存变化与通知

变化判断按渠道、日期、时段、票种和用户目标条件进行。连续有票默认不重复提醒；无票后再次有票可产生新事件。对重复抖动配置冷却窗口，初始建议 10 分钟，可按景点策略调整。

公共库存可在确认不依赖用户身份和私有定价后共享短时查询结果。涉及登录身份、名额资格或个人票价的结果不能在不同用户之间共享缓存。

### 16.7 预约流程

执行预检 → 查询库存 → 校验预约授权 → 获取目标锁及提交许可 → 建立预约操作记录 → 发起提交 → 查询订单 → 更新核验结果 → 通知。

提交许可绑定用户、任务、预约目标、运行实例和有效租约。支持官方幂等键的渠道同时传入稳定的业务幂等键；不支持的渠道依靠受控提交和事后查询降低重复风险，不宣称能够保证第三方只执行一次。

### 16.8 预约与支付展示

| 状态 | 用户显示 | 下一步 |
| --- | --- | --- |
| `READY` | 待提交 | 校验授权、窗口和提交许可 |
| `SUBMITTING` | 正在提交 | 等待结果；不接受重复提交 |
| `CONFIRMED` | 已核验确认 | 更新订单及支付状态，停止目标组后续提交 |
| `FAILED` | 已明确失败 | 依据明确失败原因决定是否允许新尝试 |
| `UNKNOWN` | 结果待核验 | 查询订单或人工处理，不直接重试提交 |
| `CANCELLED` | 提交前已取消 | 终止；不能用于表示已提交订单撤销成功 |
| `EXPIRED` | 授权或窗口已过期 | 停止新提交 |

支付状态单独保存为 `NOT_REQUIRED`、`PENDING`、`PAID`、`UNKNOWN`。已确认订单可以仍待支付，不能把它显示为付款成功。

### 16.9 业务成功条件

- 免费预约：可信查询确认有效预约及目标人员/日期匹配。
- 付费预约：可信查询确认订单创建，支付结果另行展示。
- 私有兼容脚本：只有脚本自报时显示“脚本报告成功，待核验”，不触发已核验成功的停止规则。

## 20. 按次商业规则与业务闭环

### 20.1 一次使用与费用边界

首期PricePlan只有PER_USE，每个ServiceOrder购买一次完整逻辑服务执行，quantity=1。一次对应一个有效逻辑Run及其重试Attempt、业务调用、接续和产物批次；内部轮询、受控恢复不另建收费单。已有效执行后创建新的独立Run必须再次购买，系统不自动续购或扣款。尚未领取就取消的Run可在未退款、权益有效、原预占已释放且无未知效果时替换，不算第二次有效使用；记录替代关联。持续服务有明确的最大时长、业务截止时间和完成条件；免费景点代抢可在该窗口内多次查询，但不是每次HTTP请求计费。

报价服务端计算，金额用整数最小币种单位，币种和服务费/平台费用承担方式固定。消费者确认前看到含税/费用展示口径、总应付、一次服务范围、输入、期限、交付标准、取消与退款规则。示例金额不得被当作真实定价。首期不引入充值余额、订阅或隐藏自动续费；免费票款为0，不与脚本服务费混成票价。

### 20.2 履约、发布者退款选项与平台保障

| 时点/原因 | 执行与权益 | 资金和用户出口 |
| --- | --- | --- |
| 未支付或订单超时 | 不创建可用权益，不执行 | 取消/过期；若发生晚到成功收款，按原交易退款，不自动重开履约 |
| 已支付，尚未领取执行或未使用权益到期 | 权益ACTIVE；用户取消时原子冻结或撤销 | 全额退脚本服务费，未使用到期自动发起；与执行领取互斥，退款回执确认后显示到账 |
| 已进入有效执行，正常交付 | 同一Run只消耗一次；轮询和接续不多扣 | 按成交标准判断执行交付与业务目标；无票不等于技术故障，是否退服务费执行发布者事先公示的规则 |
| 平台/部署/脚本技术故障且未交付 | 先确认无未决外部效果；本次结束 | 全额退服务费（平台最低保障）；不能同时退费并恢复同一次可再次使用权益 |
| 用户参数/凭据问题 | 进入待处理并保留同次接续；到期按成交规则结束 | 提交前校验失败不允许下单；执行后需用户补充的期限和退款范围在报价中固定，不能事后新增费用 |
| 用户在执行中主动停止 | 受控停止并核验已发生外部效果 | 按发布者事先公示的执行中取消规则处理；平台故障退款保障优先，未公示不得以临时规则拒退 |
| 外部预约/提交结果未知 | 保持核验和防重；不显示失败后可重抢 | 退款进入待核验，设置处理期限并通知；超出期限按事先公开规则处理服务费，外部UNKNOWN仍保留不得重放 |
| 通知发送失败 | 结果与交付记录仍保留，可单独重投通知 | 不再次运行脚本或收费；购买者可在平台直接领取结果 |

用户明确：目标未达成（如代抢结束无票）时，由发布者选择退款规则，购买前公示。首期支持“按约执行交付后无结果不退”和“约定目标未达成全退服务费”两类明确策略，不能留成“届时协商”。执行中主动取消、用户补充超时和未知结果的处理期限也必须明示。价格类型仍然都是PER_USE，不引入订阅或事后追加扣款。发布者不可削弱未执行全退、平台技术故障未交付全退及重复收款退回等最低保障；更有利约定允许。退款异常是售后处置，不是常规发布或购买审核流程。

选择目标未达成退款时，服务版本必须声明goal_definition、verification_method、evidence_requirements、no_result_policy、resolution_deadline和用户取消规则。通用服务可使用平台校验的产物/结构化交付标准；外部预约成功须可信渠道核验，不能仅凭脚本日志或退出码认定。无法自动确认的结果进入待核验且冻结结算，到公开期限按成交规则退款或处理，保留外部防重事实。页面分别展示“执行已结束”“目标达成/未达成/待核验”“服务费处理”。

### 20.3 发布者收入与平台结算

成交时固定发布者、服务版本、单次价格、退款政策、平台费规则与渠道成本承担方式。真实收款后记录待履约账本；交付完成且结算等待期、退款/争议条件满足才转可结算。收款资料须通过支付渠道的技术/账户验证，不设置平台人工入驻审批。平台费率和结算天数为版本化配置，未配置不允许开启付费售卖；本设计不编造具体分成比例。

金额以追加账本和冲正记录表达，退款减少可结算净收入；已结算后的退款形成可追踪冲正/待抵扣，不修改旧账。打款先预占可结算金额，按原请求查询回执；UNKNOWN不再发新的打款。发布者不能读取消费者原始输入、凭据、私人日志和产物，销售与故障页只提供必要掩码和摘要。
