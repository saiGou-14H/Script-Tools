## 1. 实施范围与闭环判据

平台承载任意合规用途的Python/Node.js HTTP/HTTPS脚本。发布者自行定义动作、必填input_schema、输出Schema及可选公共Hook；预约、监控、报告仅是场景。个人账号可以自用脚本、发布付费服务和购买他人服务；消费者、发布者是同一身份的工作区，管理员是单独授权。首期按次PER_USE，一单一次逻辑服务，包含其技术Attempt重试和合法接续；无自动续费、消费者充值钱包、DAG及公开Shell终端。

三种执行方式docker/qemu_kvm/qemu_tcg全部保留；finite/continuous与执行方式正交。私有continuous可以不设总运行时限，但所有执行、网络、凭据和产物操作都有可撤销短租约和资源预算；付费continuous须固定单次最大服务时长和未知结果处理期限。阶段性产物可以反复输出消息、文件和数据，不能视为Run终态。

闭环检查单位为“用户动作→鉴权与校验→事实事务→事件/作业→外部回执→页面状态→超时/失败出口→核验/补偿→审计/删除”。每条链路必须有稳定资源ID、唯一责任模块、可查询状态和终止条件。未知外部效果/资金回执不能通过重跑或改成失败绕过。本文覆盖全部66页、102类操作、61项REQ及16项CMR，并保留原验收矩阵；这属于设计覆盖，不是端到端运行验收。

P0包括通用执行、商业交易、全部三模式及日志监控。travel默认关闭，具体渠道验证后开放场景P0；远程Git/URL、Webhook、高级报表/追踪P1；个人API P2。关闭新能力不隐藏历史订单、退款、待处理、回执及删除入口。

前端固定React + TypeScript + Vite + Ant Design，RJSF为优先验证候选。控制面采用Node.js LTS + TypeScript + NestJS模块化单体；Runner/Broker为独立服务，Python/Node.js SDK和Guest Agent单独发版。PostgreSQL事实库、Redis Streams调度唤醒、S3/OCI对象制品库、Loki/Prometheus/Alertmanager/Grafana观测沿用02基线。依赖精确版本、锁文件和容器摘要在工程初始化时固化，禁止直接把文档中的LTS字样当部署版本。

## 3. 前端工程与动态参数表单

四工作区共用账号、网络客户端、错误展示、日期/金额格式、资源选择器和设计主题。路由来自ui-role-catalog，菜单按角色与feature过滤；按钮依据服务端allowed_actions及当前revision显示。前端隐藏按钮只是体验，服务端必须再次判权。切换角色视图不更换用户归属；退出/冻结清空所有私有缓存并关闭SSE。

服务端状态存查询缓存；表单草稿存组件受控状态，敏感输入默认不进localStorage。查询键包含user_id、security_revision、工作区、对象和筛选；请求取消、旧响应丢弃、分页游标和重连去重统一封装。项目首次实现可采用React Router及TanStack Query，但须与React版本一起锁定并做工程兼容验证；不因使用这些辅助库改变协议。

SchemaForm接收script_version_id、action、schema_digest、schema、ui_schema（仅允许安全布局提示）、formData、fieldErrors。发布者Schema决定业务必填项，平台字段（计划/凭据/资源/渠道）在外层独立表单；禁止把visit_date、party_size等硬编码成所有脚本必填。动作覆盖Schema按03规则确定，不深合并产生新必填。

RJSF使用Ant Design主题与AJV验证器进行原型。JSON Schema方言以清单声明为准，AJV按方言独立实例；禁止远程$ref自动联网、任意组件/HTML/JS注入。发布者Schema先通过复杂度、深度、引用和关键字支持检查。布尔Schema、oneOf/anyOf、条件分支、数组、嵌套、null与数字必须保留原JSON类型。RJSF渲染不完整但服务端支持的合法Schema提供受控JSON编辑和字段错误定位；语义或安全规则不支持则封存阶段拒绝，不能悄悄忽略关键字。[RJSF验证说明](https://rjsf-team.github.io/react-jsonschema-form/docs/usage/validation/) [AJV方言说明](https://ajv.js.org/json-schema.html)

前端校验仅提早反馈，封存、预览、报价、启用、接续、实际调用各自在服务端校验固定Schema；默认不强制类型转换、不移除额外字段、不自动补defaults改写用户输入。需应用默认值时先可见填入并由用户提交，服务端保存收到的完整快照。返回JSON Pointer错误映射至字段；隐藏分支值是否保留必须按Schema含义处理，不任意删除。

| 页面交互 | 实现规则 |
| --- | --- |
| 列表/详情 | 加载、空数据、无匹配、失效/无权、依赖降级分开；列表与详情状态均来自API |
| 保存/命令 | 一次用户意图持有同Idempotency-Key，禁双击；202跳对应资源或持续显示作业，不能提前标成功 |
| 版本冲突 | 412读取新revision并显示差异；由用户重申变更，不自动覆盖新值 |
| 超时 | 查询原ID或重放同键取回执；支付/退款/预约/打款不得创建新键盲重试 |
| 高影响操作 | 显示action_preview范围、风险及有效期；确认后提交preview_id和reason；预览过期/状态变化重新预览 |
| 运行详情 | 逻辑状态、脚本报告、外部可信度、效果、产物生成、消息投递、环境回收及日志完整性独立展示 |
| 消息/文件 | READY才可下载；权限、到期、删除每次重新校验；未知格式安全附件下载，不执行HTML/SVG |
| SSE | 签名游标、按event_id/业务revision去重；410转归档补读；15秒心跳、退避重连、离页关闭 |

前端发布由Vite输出静态dist，反向代理处理SPA回退与/api、SSE路由；VITE_*仅公开配置，任何凭据不注入浏览器包。FE-01～FE-12全部通过后才决定RJSF正式版本及最终接入方式；当前仍为待验证。

## 4. 通用API及数据访问契约

所有03及第15节路径为实施契约。GET返回200，创建完成201，后台工作202及resource_id/status_url，查询墓碑/过期按410或状态DTO；写入不使用200包装业务失败。统一成功{data,request_id}、列表{data,next_cursor,request_id}、错误{error:{code,message,field_errors,retry_after_seconds},request_id}。内部结果、Agent和产物协议按各自版本，不混用用户会话。

列表默认limit=20，范围1～100，created_at/id稳定倒序；过滤仅白名单，cursor绑定身份/条件/排序，max时间窗口由策略规定。文本检索为字面匹配，所有SQL参数化。UUID作为不透明字符串，不靠前缀识别权限；金额BIGINT输出十进制字符串并带currency。公开合同不得包含原input、凭据、完整购买者信息或产物正文。

命令处理顺序固定：认证/账号→功能与capability→对象归属→原幂等回执→If-Match→结构/Schema/业务校验→影响预览校验→按07锁序加锁复核→写事实/Outbox/审计/幂等回执→提交→响应。重放依然校验现有身份和访问权，不可借旧回执绕过注销/撤权；摘要一致且仍有权时优先原回执，不受自身新revision误伤。POST/PATCH/DELETE均持幂等键；认证初始入口用挑战与限流。预览及校验接口无外部写副作用。

幂等作用域=user+HTTP method+保留ID的规范route+key；摘要包含规范JSON及影响语义的头，不含密码日志。记录至少24小时，资金请求、Run触发、批次等业务防重长期保持。首次事务失败不保留成功回执；已提交后网络断开重放取相同资源和状态码。异体409，陈旧修订412，缺If-Match428，字段错误422，策略403，跨owner资源404。外部网络未知返回现有资源的核验状态与查询入口。

平台DTO默认additionalProperties=false；业务input按发布者Schema独立处理。通用限制：name/title≤120/200字符、reason≤1000字符、普通description≤10000字符、固定ID列表≤100项、正文/文件/日志预算遵循03/04；域名、路径、URL和JSON Pointer独立解析。密码/令牌仅写入用途，响应没有回显字段。可公开schema必须过安全展示检查。GET只返回DTO字段白名单，禁止直接serialize数据库实体。

跨领域DTO最低组成：Task含config_version/next_fire_at/holds/allowed_actions；Run含status/effect_status/verification_status/current_continuation/actual_mode/output_summary/cleanup/log_completeness；ServiceOrder含contract/payment/entitlement/fulfillment/refund摘要；Output含batch/key/kind/status/expiry/digest/delivery_summary；Job含status/progress/next_attempt/error/result_ref。DTO中的可选关联为空必须说明不存在、未到该阶段或已清除，不把未知当空数组。

### 4.1 支撑接口与内部服务交接

## 5. 身份、授权、私有数据和账号退出

每份注册挑战引用本人的AEAD注册正文，包含邮箱、待验证密码摘要和accepted_terms_version。验证事务依次锁用户与挑战，核对用途、期限和尝试预算后激活账号，初始化偏好，消费同账号其余注册挑战并擦除对应注册正文。认证挑战请求和完成事件分别写Outbox与审计，事件aggregate_revision引用实际持久化修订。注册和找回请求统一202受理，验证与重设成功分别返回200。

注册创建UNVERIFIED和单次邮箱挑战，验签并原子消费后ACTIVE。登录检查邮箱验证、密码哈希、账号状态，创建随机会话令牌，仅保存摘要；浏览器使用Secure/HttpOnly/SameSite Cookie，写请求校验Origin/CSRF。密码采用可调成本的专用密码哈希，参数通过上线安全基准确定，不自造加密算法。会话绑定security_revision、固定最长寿命和空闲期限；最近认证窗口默认15分钟，用于改绑、收款资料和注销。

找回入口对未知/已存在邮箱统一202；挑战短时有效、次数有上限、单次消费。重设密码、双向邮箱验证成功、冻结/注销增加security_revision并撤销全部旧会话/恢复挑战；邮箱新值在事务内检查活动邮箱唯一性。不能接收旧邮箱时走有审计的账号恢复case和安全证据校验，不能凭新邮箱声明直接改绑。管理恢复命令不返回原密码或凭据。

发布者开通只是保存本人的public profile及服务约定，不授予ADMIN。ADMIN grant含capabilities、期限、撤销状态；所有授权变化锁management_guard单例并检查剩余有效access.manage管理员，禁止自提权和撤掉最后管理入口。data.diagnose只允许声明具体资源/字段/动作/事由/工单的≤1小时访问会话；每次读取审计，再验证被访问数据归属和授权范围。运行发布者不能因此读取消费者参数、日志或产物。

凭据原文写入独立加密payload，credentials保存掩码，credential_versions保存不可变版本。授权绑定脚本版/动作、所需别名、目标域名、资源/通知能力和到期；执行前取平台策略∩版本声明∩用户批准∩当前权限，任何一层缩小都立即生效。选择凭据不是验证登录成功；校验操作创建正常受控测试Run。轮换不偷偷替换在途快照，撤销使相关许可失效并产生CREDENTIAL_INVALID hold，已发生外部效果独立核验。

注销事务先CLOSING、禁新购买/发布/触发、撤会话与执行许可、写删除墓碑和停止作业。未执行订单全退，已执行按合同及未知期限处理；发布者收益和债务按资金链结算，账号清除不使财务记录消失。CLOSING只持专用回执token看注销/退款进度；不能再运行脚本、下载已删除文件。数据库CLOSED保留UUID壳，敏感正文和身份字段擦除，逐存储清理及备份淘汰可查询。

## 6. 脚本、适配、构建与服务发布

上传先申请限大小/摘要的本人对象会话，完整确认后才引用；拒绝解压炸弹、路径穿越、链接和特殊文件。草稿编辑只能DRAFT；静态校验包括manifest/Schema方言、动态action handler、Hook导出、依赖锁、网络/凭据声明、adapter映射和文件边界。封存同事务写源摘要、Schema摘要、动作关系投影和SEALED；构建在隔离环境安装依赖，无法访问平台秘密，产出固定镜像/制品摘要及依赖清单。成功制品首次绑定READY后不得覆盖，重建若内容不同须新版本。

legacy以固定adapter定义argv/env/JSON文件映射，先校验原input再映射；不拼接Shell、eval或根据字段名猜参数。凭据注入独立于业务参数，argv禁止秘密。有限青龙通知桥仅支持03列出的sendNotify.send/notify.send/QLAPI.systemNotify签名，通道来自本人绑定，不透传面板管理权限。原生Hook和legacy配置都随版本封存；测试Task带AUTHOR_TEST并使用开发配额，仍经过真实租约、Broker、产物和日志链路。

导入upload属于P0，远程git/url属于P1，拒绝内网地址/跳转、校验来源授权与大小；拉取后固定commit/内容快照。用户显式materialize生成DRAFT，重复键回同版本；取消与物化锁同import，失败不产生半版本。来源更新仅提醒差异，不修改封存版本、已售合同或既有任务。

部署引用作者固定READY版、成功artifact、资源模板和三模式策略；准备/探测成功才READY，部署重试不运行买家业务。service_release固定action/Schema/交付/目标核验/退款/最长时限；price_plan固定PER_USE、use_limit=1和金额>0。本人显式publish后自动检查版本、部署、输入契约、价格/费用、收款资料及支持场景；通过则上架，不建立发布前人工审批队列。

retire/停销只禁新绑定和销售，存量订单按原合同继续；revoke/风险停用使新调用失效，已领取受控停止并核验效果，无法交付进入退款补偿。源码、部署、商品、报价、订单各有状态，不能把部署READY直接当商品ACTIVE或业务已成功。

## 7. 报价、支付、一次权益与履约

买家先选择固定release/price_plan，提交按该action Schema验证的完整input、本人凭据及授权。服务端生成限时报价并固定输入HMAC、金额/币种、费用/交付/退款/时限摘要；客户端只能接受terms_digest，不能传实付价格。未到期报价保留成交规则；新价只影响新报价。报价转单再次检查服务可售与安全撤权，quote_id唯一，一份报价只生成一个AWAITING_PAYMENT订单。

发起支付先锁订单：未过窗口、没有成功主支付、没有PENDING/UNKNOWN尝试才创建payment及稳定provider_request_id；提交后调用PaymentAdapter。返回跳转链接不是PAID。回调先验原始签名、渠道/商户、事件ID，再关联请求/订单、验证金额币种；同一provider event去重，乱序以可信状态机处理。事务写实际渠道transaction、payment event、收款账本、主收款CAS、ACTIVE订单和一次权益。不存在的订单/错误金额作为隔离待对账receipt，不能丢弃真实钱款线索或发权益。

支付请求与真实收款分表：同请求可能遇到异常多笔渠道交易，每笔交易号永久唯一。首笔匹配且订单仍可履约的记FUNDING；多扣记EXCESS，订单过期/取消后到账记LATE，均独立原路退款且不恢复订单。无法匹配记SUSPENSE，财务核实后才入对应聚合；不能强塞一条payment覆盖多笔钱款。

权益valid_until是未使用的启动期限；首个有效Run创建时reserved_count=1，首次领取时原子reserved→used=1并固定service_deadline。启用manual/once任务本身不预占，真正创建Run才预占；service激活在同事务创建一次Run并预占。首次领取定义为通过全部权限/配额校验、持久化Attempt和执行租约成功，不以HTTP请求到达或队列取出计次。执行环境准备失败已计次时走同Run安全重试或技术故障退款，不能直接把used清零。

未领取取消可释放预占并在仍有效权益内创建替代Run，supersedes_run_id串联；只允许一个RESERVED/COMMITTED使用记录。首次领取后所有Attempt、pending恢复、安全checkpoint恢复都使用同Run及原权益，不再次消费。付费任务schedule仅manual/once/有期限service，不接受cron/interval形成自动第二次服务；自用与作者测试无需伪造支付，但只能引用本人脚本。

买后参数须与报价HMAC及服务范围一致；允许的运行期补充只能经固定resume_schema及原合同授权，不改成交金额和原input。不可兼容变更在未执行时取消退款后重新报价购买。发布者换版、提价或买家复制任务都不能迁移权益。履约器读取可信结果/产物/核验证据，按delivery_policy和goal_definition产生DELIVERED/GOAL_MET/NO_RESULT/TECHNICAL_FAILURE/UNKNOWN事件；脚本exit0不能单独证明交付。

<a id="dev-execution"></a>
## 9. 任务调度、执行、接续和停止

Task DRAFT仅存不完整草稿；有效配置写不可变task_config_versions并绑定Schema/授权/原类型输入。编辑产生新config_version，暂停/归档不改历史Run。修改配置时在同Task锁下取消旧未领取计划并释放预占，已领取Run仍使用旧配置；存在未决hold时不得借改配置重新触发。前端“复制”仅复制非秘密草稿，不复制授权、权益或检查点。

计划解析与预览使用同库：manual无自动触发，once按UTC时刻，cron五段且指定IANA时区，interval≥1秒，service激活一次。DST不存在时刻跳过并计missed，重复本地时刻按不同UTC实例处理、每个UTC触发键唯一。misfire=skip记录错过；coalesce_once只合并一次，不无限补跑。continuous仅manual/service；max_runs计逻辑触发，不计Attempt。所有trigger_key持久防重，调度重启扫描DB而不是重放每条旧队列消息。

```text
CreateRun(actor, task_id, trigger_key):
  BEGIN; 依07总锁序锁账号/订单/权益/任务/并发键
  若同trigger已存在且有权→原Run；否则校验配置、窗口、hold、次数
  校验同Task无非终态Run；付费权益未消耗则预占1
  创建Run、Continuation(0)、产物系列、逻辑并发锁、Outbox及审计
  更新next_fire_at/max_runs；COMMIT

ClaimRun(node, run_id, request_id):
  BEGIN; 同锁序锁父对象后锁Run、租约、配额
  若该请求已领取→原Attempt；校验非终态、有效权限、节点模式、容量
  首次领取才把权益RESERVED变COMMITTED；安全重试仍沿用本Run
  递增lease generation，创建Attempt、短租约、配额预占及环境待办
  COMMIT; Runner准备环境，确认实际模式后启动调用
```

Redis队列只能唤醒，重复投递不能新建Run。数据库部分唯一约束包含WAITING_INPUT/RECONCILING，等待人工释放计算资源但不释放业务防重锁。compute槽仅环境停止证据后释放；无法证明旧环境停止/出口失效则节点隔离并保留资源占用，不能把它重新分给别人。

docker显式runc、非root、只读根、受限tmpfs/work、cap_drop、no_new_privileges、PID/CPU/内存/磁盘/网络限制，禁止socket/宿主网络/敏感挂载。QEMU每Attempt独立overlay，Agent与脚本不同身份，管理网与业务出口分离；KVM检查/dev/kvm及真实加速器证据。TCG须显式允许，仅KVM硬件不可用时按策略选择；管理故障不回退掩盖。strict_timing不接受不满足测试能力的节点，actual_mode与reason持久记录。

有限状态主线：QUEUED→PREPARING→READY→RUNNING；有效COMPLETED信封可SUCCEEDED，有人工动作WAITING_INPUT，有未知效果RECONCILING/WAITING_INPUT；停止先STOPPING，确认停止且无未决效果才CANCELLED/TIMED_OUT/FAILED。Attempt EXITED与Run SUCCEEDED独立；结果已接受后cleanup失败不倒退业务。CLOSED_UNRESOLVED仍保持UNKNOWN及重复执行hold，不能当普通失败自动再跑。

人工接续要求pending_action_id、允许resume_action和完整新input，按其固定Schema校验；原子消费OPEN且未过期的待处理项，新增Continuation、撤旧调用许可、同Run重新排队，只解除该来源hold。双击/多端/到期/撤权/结案竞争同锁序，只有一个生效。原结果/input不覆盖。resume不能切脚本版或借恢复动作扩大网络/凭据。无resume_action仅可核验/结案。

Task已经ARCHIVED/COMPLETED/EXPIRED时拒绝业务resume，保留独立受限核验和结案。Pending到期若无未决效果则Run EXPIRED并解除该待处理hold；若仍UNKNOWN则保留效果hold及只读历史，不创建新的无限期OPEN待处理。其他来源hold未解除时，整个接续事务回滚。

continuous每次短租约续期复核账号、当前代数、授权、资源、服务期限、停止请求；业务progress与环境heartbeat分开，无progress告警不自动证明卡死。interval产物Hook在安全让出点串行，积压有界合并。停止时间从首次请求固定，不因重复请求延期：撤销新业务许可→发stop→有限输出宽限→优雅等待→强杀→确认出口/环境回收→判断效果。源流失联且不能确认安全时按UNKNOWN处理。

safe_resume必须同时有发布者声明的resume_handler、兼容检查点、无POSSIBLE/UNKNOWN效果、旧环境/出口已隔离、仍有效授权和剩余重启预算；新Attempt复用Run/系列但新代数，读取固定检查点。普通legacy restart_policy=never。节点重启、队列重投、日志补传和通知失败均不是重跑主动作的理由。

<a id="dev-sdk"></a>
## 10. SDK、Hook、结果与副作用

清单采用manifest.schema.json，Invocation/results分别使用invocation.schema.json/result.schema.json。调用结构把input与context/runtime/credential_bindings分开；平台公共字段不塞进发布者业务Schema。on_init→validate_input→before_action→动态action→接受最终结果→final on_outputs→after_action→on_cleanup→宿主回收。错误Hook有界且不递归；声明不存在/不可调用属于协议错误，不能当未声明跳过。执行前语义Hook失败不进入主动作。

公共ctx提供HTTP/Broker、日志、progress、可取消wait、checkpoint、events、outputs和受限notify；ctx业务HTTP仅允许声明与用户授权的交集。禁止脚本连接管理DB/Redis、节点控制、宿主socket或读取平台商户密钥。DNS解析及每次跳转验证禁止地址，域名授权不能因DNS重绑定访问内网。代理模式必须控制DNS/出口/租约，HTTPS隧道只能观测连接级证据，不声称逐请求首字节/成功核验。

发送前持久化external_request及稳定请求ID，许可/代数/期限有效才由Broker发出；准备阶段确证未发可安全失败，一旦可能发送写入则effect=POSSIBLE/UNKNOWN。超时不无条件重放，即使开发者声明“幂等”也需要平台策略及目标支持证据；纯读请求只在有界次数/时间预算内重试。动作名称不能决定权限或推断请求是否有副作用。

AcceptResult在事务中锁Invocation及Run，先查已接受摘要，同摘要回原ACK、异体409；验证信封、输出Schema、授权有效期、当前代数、产物引用和pending结构，再写不可变Result及状态。已失效代数到达的证据写late_evidence，不能继续业务/复活Run。结果接收超时SDK只查询receipt或重投同信封，不重跑函数。data可以是合法任意JSON类型；产物refs是独立字段，不改变发布者output_schema。

可信核验绑定必须事先声明只读连接器/受限动作、输入映射、范围和期限；普通脚本自报status不升级为VERIFIED。核验器完成写独立证据和resolution，旧结果保持原值。人工completed/not_executed需明确确认并标USER_REPORTED；close_unresolved保留UNKNOWN。对付费服务，财务补偿可以结束售后流程，但不清除仍未知的业务副作用防重。

<a id="dev-outputs"></a>
## 11. 多次产物、检查点和消息投递

每个Run有一个output_series；同Run受控接续复用，独立新Run不能继承已提交批次防重空间。每次collect(batch_key,snapshot)或直接batch创建独立emission，支持explicit/interval/checkpoint/final；一emission只派发一次，新的键可持续产出。输出kind为text/json/file/message，任意格式字节按策略保存，不以文件后缀扩展业务枚举。SDK methods及字节/条数限额完全沿用03，文件为流式上传。

```text
Begin(series,key): 校验当前许可；已COMMITTED键回原句柄，否则创建/复用OPEN批次
Upload: 申请限定会话和预算→分片同号同摘要幂等→完整大小/SHA校验→UPLOADED
RegisterOutput: 同(batch,key)同规范内容回原ID；异体409；仅STAGED，不对外发布
Commit(batch,digest,checkpoint?,expected_revision?):
  BEGIN; 按总锁序获取系列/批次
  先检查已提交同摘要→原回执（不再执行旧checkpoint CAS）
  再校验本Invocation/阶段/租约、全部引用、必需key、配额与附件范围
  若有checkpoint，比较系列头revision，新增历史并CAS推进；失败整个事务回滚
  固定批次摘要/producer_outcome，COMMITTED；写产物处理Outbox；COMMIT
```

协议batch.phase为ACTION/OUTPUT_HOOK，权限token.phase为BUSINESS/OUTPUT等，二者明确映射，不能混用枚举。producer_outcome为COMPLETED/FAILED/TIMED_OUT/CANCELLED，与生成状态及业务结果独立。最终结果可原子携带一个末尾ACTION批次；已在运行中提交的批次只引用，不重复提交。结果接受后final Hook生成新批次，不回写原Result输出快照。

旧Invocation丢失时，已提交批次始终按原键取回执。未提交OPEN批次在确认旧代出口失效后标ABORTED/EXPIRED，保留原来源，不把旧上传会话转给新调用。safe_resume先查稳定业务键和未推进的checkpoint：仅当确认没有COMMITTED批次时，开发者恢复入口才可用带新恢复代数的显式batch_key重新生产该未交接范围；已提交范围禁止换键补发。旧代晚到提交被许可/代数检查拒绝。普通legacy不因此获得自动重跑许可。

运行中进入on_outputs先暂停业务出站许可并等待在途边界安全，签发独立OUTPUT许可，只可本系列产物/通知登记，无HTTP业务写和凭据解密；离开后重新检查租约才恢复BUSINESS。Hook内collect拒绝递归，超时独立失败，不终止已接受业务结果；是否停止仍在运行主动作按事先output_failure_policy，不能无界重试积压。

文件只能从允许目录经安全描述符读取，拒绝越界/链接/设备/管道；读取后复核元数据，服务端计量真实字节与哈希。对象上传成功不等于READY：提交后异步安全校验→VALIDATING→READY/FAILED；消息附件只能同批或同系列已提交产物，不能引用未来批次/他人内容。依赖截止前WAITING_DEPENDENCY，失败或过期明确DEPENDENCY_UNAVAILABLE，其他成功产物保留。

消息channel_binding_ids默认解析为任务已确认ID列表，空数组拒绝，禁止脚本填写任意收件地址。消息READY表示已登记，不表示SENT；每(message,binding)唯一delivery。提交后Outbox驱动，发送前复查账号/渠道/订阅/附件/删除墓碑；退订或撤权SUPPRESSED。失败重试只投递原消息，UNKNOWN先查服务商回执，无查询/幂等能力时按用户已确认重复风险策略有限重试并显示风险。附件用鉴权链接，邮件不默认附私有文件原文。

legacy final仅进程停止写入后采明确清单，manifest通过临时文件原子改名交接，读取固定摘要并复制不可变暂存；桥接通知只保证同一次登记传输防重，不替开发者猜跨运行业务去重。只有final采集的长期进程在结束前不会自动有文件产出，页面需明确说明。产物过期/删除改变可用性，不改历史生成成功/业务终态；重启恢复先核对系列批次和检查点，再决定业务续接。

<a id="dev-travel"></a>
## 12. 旅行场景接入

城市→免费预约景点→渠道→规则版本→可售脚本服务形成明确目录；渠道状态UNVERIFIED/MONITOR_ONLY/BOOKING_SUPPORTED/DEGRADED/DISABLED分别展示。库存unknown/not_released/sold_out不互相替代；库存只是观测，不保证预约。规则来源、核对时间、放票时区、最大人数、退改与核验能力必须有接入证据，未知字段不能虚构。

旅行授权固定本人渠道账号版本、景点、日期、出行人快照、票种、允许时段/替代/部分成功、费用上限和有效期；首期max_ticket_amount_minor=0、外部payment_state=NOT_REQUIRED，平台脚本服务费独立。通用input不推断旅行含义，只有显式场景adapter进行校验和上下文绑定。

booking_target以本人渠道账号稳定HMAC、景点、日期、票种、人员集合形成防重键；不同任务/脚本触及同一目标也竞争同锁。发送前创建booking_operation及提交证据，READY/SUBMITTING/UNKNOWN/CONFIRMED均占用目标；超时转UNKNOWN，可信订单查询确认后才CONFIRMED。未执行有可信证据才释放，可明确关闭未知但仍保持重复提交阻塞。用户手动修改“已预约”显示不写可信booking_order。

每个渠道实现认证获取/有效性检查、规则拉取、库存查询、授权校验、提交、订单查询及错误映射的能力表；未验证提交能力只开放监控，不伪装可购买履约。验证码/本人确认通过pending接续，不能绕过平台验证。渠道停用后保留未决订单回查和退款入口；旧授权失效不能继续业务提交。

<a id="dev-operations"></a>
## 13. 日志、管理、清理与恢复

日志schema_version=1.0独立于脚本协议。Runner/Agent按可信owner/run/attempt/source身份采集，脚本stdout中的同名字段不能覆盖。UTF-8解析→截断/预算→敏感值脱敏→安全结构化→受限WAL→对象归档→DB分段提交ACK→异步Loki及SSE投影。原文不先落盘再脱敏；多行、无效字符、巨行、堆栈和跨块秘密测试必须覆盖。已归档记录可重投索引，已丢失记录有log.gap。

7天热查询、8～30天归档查询任务按04建议执行；owner筛选在SQL定位和Loki结果中双重校验，禁止直接开放LogQL。管理员默认只看元数据；正文/输入/产物需data_access_session字段范围和每次审计。导出固定过滤/脱敏策略，执行/领取/下载都重判权；24小时到期，安全下载链接最多5分钟。SSE终态后继续显示清理和归档收尾，不能提前宣称日志完整。

指标按有限标签统计模式、阶段、错误类、队列时延、UNKNOWN、配额、产物/通知/删除积压；用户/Run/订单ID放元数据，避免高基数。业务无票不是平台故障；支付受理、成功资金、脚本退出、已核验预约分别计量。基础关联P0，高级Tempo/采样P1；审计和关键结果不采样。

告警规则版本化，FIRING→ACKNOWLEDGED仅表示有人处理，健康证据才RECOVERED；静默必须范围/理由/到期，Alertmanager同步失败可见。告警发送失败也告警，监控自监控涵盖WAL满、采集/索引/回调停滞、时间偏差、证书过期、资源泄漏。管理员操作仅限固定动作（排空/隔离/清理/核验等），禁止任意宿主命令或手写业务成功。

清理先数据库墓碑，再由deletion_steps处理对象/索引/缓存/导出/节点残留/备份到期，每步幂等并有重试期限。停用功能不取消旧清理和资金回查消费者。恢复到隔离环境先应用最新撤权和删除水位，全部旧租约失效，再核对账本、对象、Outbox及未决效果，重建缓存后开放；不能恢复旧队列导致预约或资金请求重放。RPO/RTO、调度精度、TCG性能、日志吞吐以05实测为准。

## 14. 后台作业与事件交接

Outbox与业务事实同事务，事件包含event_id/type/schema_version、aggregate_type/id/revision、owner引用、occurred_at/request_id、最小payload引用。relay只在发布成功后更新delivered_at；崩溃重投同event_id。消费者同事务插consumer_receipt和业务投影；外部调用先写稳定发送记录，调用后独立事务接受回执。系统不声称跨DB/队列/外部服务exactly once。

每个作业包含owner/scope、固定输入摘要、status、attempt_count、next_attempt_at、deadline、failure_code和result_ref。领取只占短事务，执行后CAS状态/代数；工作进程重启先查已有外部回执。通用作业最终FAILED保留人工入口，UNKNOWN资金/效果进入专用核验，不能单纯通用重试。

### 15.2 操作、请求、事务与回执


<a id="action-public-read"></a>
#### 1. public.read — 浏览平台说明与帮助

角色：GUEST, USER, PUBLISHER, ADMIN；范围：PUBLIC；能力：core；处理模块：Catalog。

路由：`GET /api/v1/public/overview`；`GET /api/v1/public/help`。

请求与数据：无body；返回公开平台能力、帮助条目、启用场景与设计/运行状态说明。

前置条件：只返回公开服务说明；商业与运行状态均如实展示。

事务/查询对象：[services](./07-完整系统数据库设计.md#table-services)、[platform_features](./07-完整系统数据库设计.md#table-platform-features)；变更遵循相应模块事务和统一Outbox/审计规则。

成功出口：展示脚本发布部署、付费使用与业务场景入口。失败出口：401重新登录；403拒绝无权限；对象越权404；409显示业务阻塞；412刷新修订；422定位字段；超时查询幂等回执，禁止重复扣款或重复外部提交。


<a id="action-catalog-read"></a>
#### 2. catalog.read — 查找服务与查看详情

角色：GUEST, USER, PUBLISHER, ADMIN；范围：PUBLIC；能力：core；处理模块：Catalog。

路由：`GET /api/v1/services`；`GET /api/v1/services/{id}`；`GET /api/v1/services/{id}/plans`。

请求与数据：q/category_id/scene_key；详情返回公开合同、有效输入Schema、schema_digest、交付/退款/费用及部署可售状态，不返回代码。

前置条件：公开已上架服务及价格、交付标准、部署可用性；不公开代码和使用者数据。

事务/查询对象：[services](./07-完整系统数据库设计.md#table-services)、[service_releases](./07-完整系统数据库设计.md#table-service-releases)、[price_plans](./07-完整系统数据库设计.md#table-price-plans)、[deployments](./07-完整系统数据库设计.md#table-deployments)；变更遵循相应模块事务和统一Outbox/审计规则。

成功出口：返回服务版本、参数表单、按次价格、一次服务范围、退款规则及使用入口。失败出口：401重新登录；403拒绝无权限；对象越权404；409显示业务阻塞；412刷新修订；422定位字段；超时查询幂等回执，禁止重复扣款或重复外部提交。


<a id="action-auth-enter"></a>
#### 3. auth.enter — 注册、验证、登录与找回

角色：GUEST, USER, PUBLISHER, ADMIN；范围：AUTH_CHALLENGE；能力：core；处理模块：Identity。

路由：`POST /api/v1/auth/register`；`POST /api/v1/auth/verify-email`；`POST /api/v1/auth/login`；`POST /api/v1/auth/password-reset-requests`；`POST /api/v1/auth/password-resets`。

请求与数据：register:{email,password,accepted_terms_version}；verify-email:{challenge_id,token}；login:{email,password}；reset-requests:{email}；password-resets:{challenge_id,token,new_password}。响应挑战受理或会话安全Cookie及me摘要。

前置条件：单次挑战、限流；邮箱存在与否统一反馈。

事务/查询对象：[users](./07-完整系统数据库设计.md#table-users)、[auth_challenges](./07-完整系统数据库设计.md#table-auth-challenges)、[auth_sessions](./07-完整系统数据库设计.md#table-auth-sessions)；变更遵循相应模块事务和统一Outbox/审计规则。

成功出口：注册待验证、验证激活或建立会话；登录后回到可访问的原页面。失败出口：401重新登录；403说明权限或能力限制；对象越权404；409展示阻塞；412刷新差异；422定位字段；超时按request_id或幂等键查回执，禁止盲目重提。


<a id="action-account-read"></a>
#### 4. account.read — 查看账号与会话

角色：USER, PUBLISHER, ADMIN；范围：OWN；能力：core；处理模块：Identity。

路由：`GET /api/v1/me`；`GET /api/v1/me/sessions`；`GET /api/v1/me/closure`。

请求与数据：无body；me仅id/display_name/掩码邮箱/status/角色能力/security_revision；会话设备及到期掩码；closure逐存储进度。

## 17. 实施顺序与完成门槛

| 阶段 | 可交付实现 | 必须通过的出口 |
| --- | --- | --- |
| A 基础工程 | 锁定Node/React依赖、SQL迁移、身份/权限、契约加载、前端路由及RJSF原型 | Schema方言与原始类型测试、跨账号拒绝、迁移干跑、FE专项结论 |
| B 执行纵切 | 私有上传→封存→构建→测试→任务→三模式Runner→Broker→结果→清理 | 同触发/租约防重、三模式真实隔离及网络许可验证；无旅行字段也能闭环 |
| C 持续产物 | 多次Hook/直接batch→文件/消息→checkpoint→接续/停止 | 同键重投、CAS冲突、消息UNKNOWN、附件过期、long-run背压及节点故障负例 |
| D 商业纵切 | 服务发布→报价→支付→权益→Run→交付→退款→账本→结算 | 支付沙箱重复/乱序/丢回调、claim与refund竞争、晚到/超额款、平衡/冲正及打款核验 |
| E 旅行及运维 | 首个真实渠道证据、待处理、日志/告警/删除/备份恢复 | 明确渠道能力边界；未知提交不重放；日志性能、恢复水位与清理实际证据 |
| F 全页面与上线 | 75角色页面交付项逐项串联、配置/价格/渠道锁定 | 全P0含商业化及三模式通过05验收；P1/P2关闭但历史只读/回查正常 |

关键集成用例必须使用至少两个账号、一个发布者和一个受限管理员；两连接并发验证扣次/退款/接续/结算/CAS，注入结果ACK丢失、回调乱序、节点失联、对象上传成功DB失败、DB恢复及删除台账回放。资金测试只用支付沙箱，不把伪造provider callback当真实渠道验签证据。

当前可复用的证据是原契约静态校验、角色/页面目录检查，以及本次DDL和约束验证，见[验证记录](./05-测试验收与验证记录.md#detailed-design-results)。当前没有实际前端、Runner、真实支付或景点验收证据。首批渠道、支付适配器/费率、生产容量和RJSF版本属于实施验证/运营配置门槛，表结构与控制流程已预留明确入口；不得通过填“已通过”跳过接入工作。
