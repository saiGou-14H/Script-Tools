## 1. 身份、响应、幂等与版本

- 用户 API 前缀 `/api/v1`，内部节点 API `/internal/v1`，管理员 API `/api/v1/admin`；不同凭据受众不可互用。时间为 RFC 3339 UTC 字符串，标识为不透明字符串；数据库使用 UUID，不从 ID 暴露个人信息。
- 成功返回 `{data, request_id}`；异步写操作返回 202 及可查询资源 ID；创建完成返回 201。列表返回 `{data: [...], next_cursor, request_id}`，limit 默认 20、范围 1～100，按 created_at/id 稳定排序。游标绑定用户、过滤和排序，越权对象统一 404。
- 错误返回 `{error:{code,message,field_errors,retry_after_seconds},request_id}`。field_errors 仅含 JSON Pointer path、rule、message，不回传原值。不能用 HTTP 200 表示失败。
- POST 创建/命令以及 PATCH/DELETE 使用 Idempotency-Key，作用域为用户、HTTP 方法、规范路由（保留资源 ID，不含查询串）及键。原始请求规范化摘要一致则返回同一资源和原状态码；同键异体 409 IDEMPOTENCY_CONFLICT。记录至少保存 24 小时；过期不解除 Run/Invocation/操作表的永久防重约束。认证初始请求另按挑战 ID 和限流处理。
- 对已有对象的变更要求 If-Match 携带 revision；缺失 428 PRECONDITION_REQUIRED，陈旧 412 REVISION_CONFLICT。幂等重放检查先于修订检查，防止已成功请求因自身更新修订而被误拒。
- 内部节点接口用 mTLS、租约代数及消息/调用 ID 防重，不套用用户 If-Match；声明的只读结果回执权限与业务出站许可分开。
- 所有命令记录 actor、对象、前后修订、原因、request_id；不记录密码、令牌和完整 input。变更失败回滚数据库事务，不发成功事件。

平台请求字段、响应投影、预览/作业/恢复及内部交接的实施补充集中见[开发API契约](./06-详细开发设计.md#dev-api)；不改变下列JSON协议文件。数据库字段、金额类型与关系以[数据库设计](./07-完整系统数据库设计.md)为准。

文档版本 V3.0 不改变脚本协议 2.0、适配/文件交接协议 1.0 或独立日志 schema_version=1.0。版本需要按各自命名空间协商，不能根据文档版本或路由前缀推断。

## 2. 平台请求类型

| 类型 | 必填内容 | 可选内容与规则 |
| --- | --- | --- |
| TaskCreate | script_version_id、action、input、schedule、execution、authorization_id | name、credential_bindings=[]、notification_policy、concurrency_key；状态默认 DRAFT |
| TaskPatch | 完整的新配置（同 TaskCreate） | 使用 PATCH 路由但不对 input 深合并；创建新的 config_version |
| Schedule | kind=manual/once/cron/interval/service、timezone | once 有 at；cron 有 expression；interval 有 interval_seconds≥1；ends_at、max_runs≥1、misfire_policy=skip/coalesce_once；互斥字段非法即拒绝；continuous 仅 service/manual，service 激活只启动一次 |
| Execution | requested_execution_mode | run_mode=finite/continuous、allow_tcg_fallback=false、resource_profile_id、strict_timing=false、not_before、deadline、retry_policy；finite 使用 max_runtime_seconds，continuous 可选 max_uptime_seconds/restart_policy/stop_grace_seconds/output_interval_seconds，详见[持续运行设计](./02-系统架构与详细设计.md#continuous)；实际模式由平台分配 |
| AuthorizationCreate | script_version_id、action、network_grants、credential_bindings、resource_profile_id、expires_at | task_id 可在绑定时回填；批准范围不得超过版本声明和本人权限；input/config 摘要在绑定时固定 |
| ResumeRequest | pending_action_id、resume_action、完整 input、authorization_id | credential_bindings；恢复 action 来自待处理项允许列表；If-Match 对应待处理项 |
| ResolutionRequest | disposition、reason、evidence_refs=[] | completed/not_executed 须 confirm_resolution=true；close_unresolved 保持 UNKNOWN；记录 USER_REPORTED，核验器用专用入口 |
| CredentialCreate | name、kind、secret_payload | kind 是受支持凭据类型；返回仅 ID/掩码/版本，不返回明文；未绑定凭据不能被脚本任意读取 |
| EventSubmit | 事件信封及稳定 event_key | 身份、归属和订阅从调用上下文校验；不接受外部任意收件地址 |

保存草稿允许不完整配置，另用 draft_payload 保存；不创建执行授权或可调度 config_version。TaskCreate 完整字段要求适用于启用或保存可执行配置，草稿编辑响应明确列出缺项。

## 3. 账号、脚本、任务与运行 API

| 接口 | 输入/条件 | 响应及事务出口 |
| --- | --- | --- |
| POST /auth/register、/auth/verify-email | 邮箱/密码/accepted_terms_version，challenge_id/token | 注册统一202受理，新账号UNVERIFIED，验证成功200 ACTIVE并创建个人默认配置 |
| POST /auth/login、/auth/logout | 有效账号；会话身份 | 会话/撤销结果，不返回可枚举账号信息 |
| POST /auth/password-reset-requests、/auth/password-resets | 邮箱，单次 challenge_id/token/new_password | 找回请求统一202，重设成功200并撤销会话及旧找回凭证 |
| POST /me/email-change-requests、/me/email-changes | 最近认证；新邮箱；双向验证凭证 | 202 挑战；完成后增加 security_revision 并撤销旧会话 |
| POST /me/closure、GET /me/closure | 最近认证、明确注销请求 | 202 CLOSING 与清理进度；关闭后以受限注销回执令牌只查进度 |
| POST /scripts、/scripts/{id}/versions | 元数据；包上传引用及清单 | 201 DRAFT；文件引用必须属于本人且已完成上传 |
| POST /script-versions/{id}/seal、/builds | 修订；固定内容 | 200 SEALED/202 Build；制品合格后 READY |
| POST /publisher/services/{id}/publish | 本人服务、自动检查、部署READY、按次价格及交付规则 | ACTIVE可售卖，无人工批准；存量订单保持原release |
| POST /script-versions/{id}/retire | 修订、原因 | RETIRED 只禁止新绑定；保留合法存量任务授权，不新增 VERSION_REVOKED 阻塞；审计及 Outbox |
| POST /script-versions/{id}/revoke | 修订、原因 | REVOKED 阻止新调用、撤销相关许可并建立 VERSION_REVOKED 阻塞；在途效果另行核验 |
| GET /script-versions/{id}/actions | 可读取版本 | 动态动作、有效 Schema 与摘要；无凭据或用户 input |
| POST /credentials、/credentials/{id}/versions、/credentials/{id}/revoke | 本人凭据；修订/密文输入 | 创建或撤销版本；相关授权失效，不删除在途使用证据 |
| POST /execution-authorizations | AuthorizationCreate | 201 固定授权，任务绑定时检查输入摘要与范围 |
| POST /tasks、PATCH /tasks/{id} | TaskCreate/TaskPatch、修订 | 201/200 Task、config_version、validation；草稿有单独 draft_payload |
| POST /tasks/{id}/activate、/pause、/resume、/archive | 修订，恢复不得存在阻塞 | 状态及 next_fire_at；归档保留待处理入口 |
| POST /tasks/{id}/runs | 幂等键；手动运行当前配置 | 201 Run；被阻塞返回 409 TASK_BLOCKED，附本人可访问的阻塞项 |
| GET /tasks、/tasks/{id}、/runs、/runs/{id} | 归属、游标 | 配置及独立运行/效果/验证/清理状态，历史输入按权限另取 |
| GET /runs/{id}/result、/runs/{id}/results | 归属 | 当前流程采用的结果及来源；results 为历次 Invocation 分页，不覆盖历史 |
| POST /runs/{id}/stop | Run 修订、原因、有限宽限期 | 202 STOPPING；默认暂停后续服务启动，已有 Task 终态不重开 |
| POST /runs/{id}/cancel | Run 修订、原因 | 202 取消请求；最终是否 CANCELLED 依效果判断 |
| GET /pending-actions、POST /runs/{id}/resume | 本人待处理项；ResumeRequest | 待处理清单/202 continuation、Run；原子消费 |
| POST /runs/{id}/resolutions、/reconcile | ResolutionRequest；已授权核验绑定 | 201 人工结案记录/202 核验；明确结论只暂停仍可运行任务，保留 ARCHIVED/COMPLETED/EXPIRED；使原计划授权失效，不自动重跑 |
| GET /notifications、POST /notifications/{id}/read | 本人；通知修订 | 站内状态；阅读不表示外部业务已确认 |
| GET /runs/{id}/events、/logs；POST /log-exports | 归属、受限筛选 | SSE/分页/202 导出；详细协议见[日志运维设计](./04-部署运维与监控手册.md#logging) |
| POST /data-deletions、GET /data-deletions/{id} | 本人范围、保留策略 | 202 删除标记及逐存储进度；归档与删除是不同操作 |
| POST /internal/v1/runs/{id}/claim | 节点 mTLS、能力、可用配额 | 原子创建租约/Attempt；请求 ID 重放返回同一领取结果 |
| POST /internal/v1/attempts/{id}/heartbeat | 身份、代数、环境摘要 | 最新期限/停止指令；旧代数 409 STALE_LEASE |
| PUT /internal/v1/invocations/{id}/result | 结果信封及摘要 | 首次 201 accepted、同摘要 200；矛盾 409 RESULT_CONFLICT |
| GET /internal/v1/invocations/{id}/receipt | 只读结果回执权限 | accepted/digest/accepted_at；不重新执行动作 |
| POST /internal/v1/invocations/{id}/events | 自定义事件信封 | 201/200 事件回执；同键异体 409 |

上表用户路由均带 `/api/v1` 前缀，内部完整路由保持原样。上传采用鉴权签发上传会话、限定对象/大小/摘要、完成确认后引用；未确认对象不能构建，孤儿定期清理。产物下载只经鉴权入口，不能接受任意宿主路径。

### 3.1 其他资源入口

服务目录与详情读取当前release的标题、说明、参数和交付规则，返回script_version、published_at、updated_at、output_schema、resolution_seconds及validity_seconds。availability由发布者、脚本版、部署状态和开发样例标记计算，包含can_purchase和reason。列表及详情共用该投影，参数说明按发布者Schema展示，报价和执行时继续重新校验状态与授权。

<a id="header-search-state"></a>

顶栏在P02市场、P06帮助、S02本人脚本、S05构建和O06管理订单中读取该页URL的q。草稿在当前输入框中编辑，回车后提交，刷新和浏览器历史恢复已提交关键词。页面级关键词修改或清除同步顶栏。构建提交保留其他筛选，移除原record并保留输入焦点。市场顶栏使用全部分类的搜索入口，帮助入口携带当前workspace。

S02顶栏匹配本人已加载脚本的名称、用途及显示版本，匹配时去除首尾空白并忽略大小写。数字开头的版本在列表显示v前缀。长列表在表格内部滚动，名称和用途截断时保留完整文本。创建服务入口为/publisher/services/new/edit?script={script_id}，新商品以该本人脚本作为初始关联，生成自身的草稿标识。未定位到所选脚本时展示不可用状态，元数据加载期间展示加载反馈。

<a id="market-page-state"></a>

P02市场页通过URL的q、category和sort恢复筛选，当前前端对已载入目录按服务名称与说明进行搜索、按分类匹配。sort接受recent和price，价格按最小币种单位整数排序，其他值采用最近更新。输入关键词更新当前历史项，分类和排序可通过浏览器历史恢复，其他查询参数保留。

P03详情通过tab恢复intro、io和rules页签，未知值显示介绍。市场进入普通服务或景点服务时，returnTo保留原市场URL，详情面包屑可返回原筛选。市场返回上下文接受/market和/market?查询路径，景点页继续支持既有/travel返回上下文。进入购买时从所选服务建立结算路径，市场筛选及页签用于页面导航。

部署文案读取deployment_status的PENDING、DEPLOYING、READY、FAILED、DEGRADED及STOPPED，未知值显示未登记。购买入口读取availability.can_purchase，旧数据缺少该值时沿用READY部署的兼容判断。当前不可售的已部署服务保留各自事实和不可售原因。Schema完整文本支持键盘滚动，true和false保持JSON布尔值，参数示例按当前发布者Schema生成。

认证挑战受理投影包含challenge_id、expires_at和delivery_status。本地开发验证模式增加development_token，由04约束启用条件，正式邮件交付继续按通知模块接入。邮箱验证成功返回verified，前端回到密码登录。重设成功返回reset与sessions_revoked。注册受理与找回受理采用统一响应结构，账号状态及邮箱存在性规则见06。

| 资源 | 路由 | 边界 |
| --- | --- | --- |
| 服务市场/代码资产 | GET /api/v1/services；GET /api/v1/me/scripts | 市场公开服务说明；代码资产仅本人，购买不授予源码 |
| 旅行目录 | GET /api/v1/attractions、/api/v1/channels、/api/v1/channels/{id} | 扩展启用后开放，能力和规则来源可查 |

### 3.2 角色页面操作与权限契约

本表与[角色目录](./contracts/ui-role-catalog.json)逐项同步。GUEST/USER/PUBLISHER/ADMIN为四工作区，发布者是个人账号创作能力，无人工入驻或发布审批；ADMIN按后台能力执行。购买服务只授予使用权，不自动授予源码。所有操作同时检查归属、状态、功能可用性、修订和业务限制；付费执行校验订单与权益。

公共能力查询`GET /api/v1/me/capabilities`返回可用工作区、能力、对象允许动作和阻塞原因，不返回秘密。异步作业通过`GET /api/v1/operations/{id}`查回执。破坏性命令的`POST /api/v1/action-previews`返回5分钟有效的范围/影响摘要，执行时仍重新检查状态。

| AdminRoleGrant | target_user_id、role=ADMIN、capabilities、reason | access.manage；禁止自提权及撤掉最后权限管理员 |
| DataAccessSession | resource_ids、fields、actions、purpose、ticket_ref、expires_at | data.diagnose；自动范围检查；最多1小时；没有人工批准接口 |

通用TaskCreate保留给PRIVATE_SELF_USE，仅脚本所有者允许；消费者付费服务使用PaidTaskCreate语义，直接传script_version_id不能绕过订单权益。测试执行使用开发配额并带execution_context=AUTHOR_TEST，不创建伪造Payment。消费者付费schedule仅manual/once/有期限service；不接受自动重复收费的cron/interval。

### 3.4 支付渠道回调、查询与稳定错误

支付适配入口`POST /api/v1/payment-provider/webhooks/{provider}`不使用用户会话，必须验证渠道签名、商户、事件ID、交易号、订单号、金额和币种。接收原文在受限保留中用于验签/争议核对，日志不输出秘密。非法签名/错金额拒绝并记录诊断；合法重复事件返回已处理回执，不重复发权益或写分录。平台主动查询通过内部`PaymentAdapter.queryPayment/queryRefund/queryPayout`，不得给消费者开放任意渠道请求。

PaymentAdapter要求createPayment、closePayment、queryPayment、refund、queryRefund、payout、queryPayout；所有写入使用稳定provider_request_id。支付渠道尚未选定/接入，字段由适配层映射，本设计不声明真实收款已可用。订单过期与晚到支付按架构第28节自动退款，不重新履约。

新增错误：SERVICE_NOT_AVAILABLE（409）、QUOTE_EXPIRED（409）、PRICE_CHANGED（409）、PAYMENT_PENDING_RECONCILIATION（409）、ENTITLEMENT_REQUIRED（403）、ENTITLEMENT_EXHAUSTED（409）、FULFILLMENT_IN_PROGRESS（409）、REFUND_BLOCKED_PENDING_VERIFICATION（409）、REFUND_AMOUNT_EXCEEDED（422）、PAYOUT_PENDING_RECONCILIATION（409）、FEATURE_DISABLED（403）、ACCESS_SCOPE_DENIED（403）、ACCESS_SESSION_EXPIRED（403）、LAST_ACCESS_MANAGER（409）。未知支付/退款/打款错误必须给原资源查询入口，不建议新交易重试。

历史订单、账单、退款、结算和外部未决查询不因停止新售卖或停用场景而消失。门票外部记录使用`/booking-orders`，平台脚本服务交易使用`/service-orders`，禁止复用同一路由混淆语义。免费预约外部票款为0、NOT_REQUIRED，首期无门票代付接口。订阅/自动续费/余额充值API不在本版开放。

### 3.5 本人发布者资料

`GET /api/v1/me/publisher-profile`返回`{profile,terms}`。尚未开通时profile为null；已有资料只返回id、public_name、description、terms_version、enabled、revision、created_at、updated_at。terms包含当前version和paragraphs供用户阅读确认。读取不创建资料，服务端从会话确定归属，拒绝查询参数。资料存在时响应ETag为带双引号的revision，revision始终为十进制字符串，响应禁止缓存。

`POST /api/v1/me/publisher-profile`只接受public_name、description、accepted_terms_version。昵称为1～120位非空文本，简介及公开联系说明为1～10000位非空文本，保存时去除两端空白，约定版本必须与GET返回的当前版本一致。首次开通显式勾选确认，成功返回201及profile；更新返回200及profile。首次创建无需If-Match，更新需携带读取时的ETag，缺少返回428，过期返回412。字段错误用JSON Pointer定位，额外字段返回422。账户已验证且状态ACTIVE，资料已停用时返回403。

POST要求会话CSRF和Idempotency-Key。同一用户、方法、规范路由和键下，以规范化请求正文的HMAC摘要判定重复，字段顺序不影响摘要。原请求回执在修订检查前回放，保持原状态码和原资料快照；同键异体返回409。24小时内回执正文加密保存在private_payloads，过期重用键时清除旧正文并保留资料唯一约束。回执无法解密时返回503，客户端沿原键重试。资料、审计、Outbox与命令回执同事务保存，按用户锁串行处理首次创建及并发更新。每个用户至多一份资料，停用资料不能通过重复开通恢复。

开通后下一次身份读取获得PUBLISHER工作区，保留USER及既有后台能力。基础实现已覆盖此资料命令，其他业务命令继续按各自实现进度接入统一幂等。profile没有独立联系邮箱字段，公开联系说明由用户写入简介。S15联系邮箱仅保留在本地原型预览中，live界面只提交当前定义的三个请求字段。

### 3.6 本人资料与会话

GET /api/v1/me返回id、display_name、email_mask、status、revision、security_revision、locale、timezone、updated_at、roles、capabilities、current_session及is_last_access_manager。邮箱保留首字符及域名，账号与安全修订均为十进制字符串，登录和bootstrap中的security_revision同步采用字符串。current_session返回当前会话的id、revision、client_summary、authenticated_at、last_seen_at、expires_at、revoked_at和is_current。client_summary保存从UA提取的固定设备与浏览器标签。is_last_access_manager表示当前账号是否为唯一有效、已验证且拥有永久access.manage授权的管理员，注销命令继续按管理锁及最后管理员保护规则实现。

PATCH /api/v1/me接受display_name、locale、timezone中的至少一项，全部为1～120位非空文字。昵称去除两端空白，语言及IANA时区通过Intl验证并规范化，旧账号缺少偏好行时读取默认值并在首次偏好修改时创建。请求携带CSRF、Idempotency-Key与If-Match账号修订，未知字段422、缺修订428、过期412、同键异体409。成功返回id、display_name、revision、locale、timezone及updated_at，同键原体回放原响应优先于修订检查。资料、偏好、审计、Outbox及加密回执同事务保存，安全修订与现有会话继续沿用。

GET /api/v1/me/sessions按created_at/id倒序分页，limit默认20且最多100，签名游标绑定本人及页大小。列表包含当前有效且未超出30分钟空闲窗口的本人会话，字段与current_session一致。邮箱原文、密码摘要、会话令牌及其摘要均保留在服务端受限数据内。读取响应禁止缓存，GET me返回账号ETag，资料及单会话写入返回相应新ETag。

DELETE /api/v1/me/sessions/{id}携带CSRF、Idempotency-Key和该会话If-Match，空正文或空对象表示撤销指定本人会话，越权404。DELETE /api/v1/me/sessions/others用于账户页退出其他会话，使用CSRF与Idempotency-Key，服务端从当前会话排除自身并原子撤销其他有效会话。返回revoked_count、current_session_id及新账号revision，重复请求回原计数。单会话响应返回id、revision、revoked和was_current，后者表示原命令发起时是否为当前会话。当前会话删除的修订比对扣除本次鉴权活动刷新带来的变化，额外并发变更仍返回412；回执跨设备读取时按本次会话ID判断Cookie处理。

资料和会话命令先锁用户并重新检查当前账号与会话有效性。退出当前通过既有POST /auth/logout撤销并清除Cookie，审计和Outbox同事务落库。后续鉴权拒绝已撤销会话，订阅中断随SSE模块继续接入。C21资料修改、会话弹窗和退出其他会话使用实际接口，邮箱双向变更、账号注销及数据清理继续按原设计实施。会话时间展示采用本人locale与timezone，其他页面的地区化接入继续推进。
### 3.7 私有源码草稿上传与读取

当前已实现以下本人发布者入口。上传文本源码包时，在同一事务中创建Script、DRAFT版本、加密源码、对象元数据、审计及Outbox。编辑保留版本号，使用If-Match和幂等键处理并发及重放。源码正文采用AES-256-GCM保存到private_payloads，storage_objects使用private-payloads存储适配关联，归属与密钥版本在读取时复核。

| 接口 | 当前请求 | 当前响应 |
| --- | --- | --- |
| POST /api/v1/scripts | name、description可选、files文本映射，Idempotency-Key必填 | 201草稿摘要，包括id、version_id、version、revision、content_status、source_digest和input_schema |
| GET /api/v1/me/scripts | 当前有效发布者身份 | 本人已有源码的最新版本摘要，按创建时间及ID倒序，当前最多100项 |
| GET /api/v1/script-versions/{id}/source | 本人版本 | files、version_id、revision、source_digest，no-store及ETag |
| PATCH /api/v1/script-versions/{id} | 完整files映射，Idempotency-Key、If-Match必填 | 200新修订摘要，仅允许DRAFT，同键重放先于修订校验 |

files包含1～64个UTF-8文本文件，序列化源码总量上限1MiB，HTTP JSON正文上限2MiB。路径使用包内相对路径。manifest.json按现行2.0结构校验，入口和锁文件必须存在，默认及恢复动作须已注册。缺失引用、路径越界和非法Schema返回422，超限返回413，跨用户版本返回404。

前端支持单文件及以.script.json结尾的多文件包。包结构为 `{format:"script-tools/source-package@1",name:string,files:{包内路径:源码字符串}}`，客户端把name和files提交上述创建命令。封存、构建、运行及部署继续由各自能力接入，DRAFT记录源码保存状态。

源码元数据的input_schema返回默认动作的有效输入Schema。动作显式声明input_schema时完整覆盖版本定义，缺省继承版本定义，布尔true和false保持原值。版本schema_digest覆盖版本输入及完整动作定义，动作Schema变化同步更新摘要。本人自用页按有效Schema生成参数表单，true使用JSON输入，false显示发布者拒绝全部输入，null、false、0、数组和字符串保持原始JSON值。

发布者自用、确认订单及已购服务配置共用参数输入组件。JSON Schema Draft 2020-12使用对应校验器，已有显式Draft-07声明沿用原方言。RJSF表单与JSON编辑器执行相同Schema约束，模式切换保留输入，提交命令读取已校验值。无可呈现类型、布尔、可空根或编译异常显示JSON编辑及校验反馈。未支持的Schema版本在上传接口返回SCHEMA_UNSUPPORTED和422状态。

确认订单的原型样例也经过当前发布者Schema校验。Schema编译失败时进入参数编辑与错误反馈，阻止生成订单。收银台金额、分类及退款规则读取该订单的成交快照，历史缺项显示资料待载入。支付剩余时间按订单返回的payment_deadline计算，客户端计时结束后继续查询可信支付与订单事实。

### 3.9 本人固定版本与动作元数据

读取要求有效的本人发布者身份，返回no-store。未知或越权脚本、版本返回404，未知或重复查询参数返回422。

| 读取入口 | 请求及响应 |
| --- | --- |
| GET /api/v1/scripts/{id}/versions | limit默认20、范围1～100，cursor及content_status可选。状态接受DRAFT、SEALED、READY、RETIRED、REVOKED，响应使用统一分页封装 |
| GET /api/v1/script-versions/{id} | 不接受查询参数，返回固定版本摘要及actions、default_action、action_source，ETag采用revision |
| GET /api/v1/script-versions/{id}/actions | 不接受查询参数，data为当前版本动作数组 |

版本摘要包含id、script_id、script_name、description、version、revision、content_status、source_digest、schema_digest、sealed_at、created_at和updated_at。revision保持十进制字符串。latest_build_id及latest_build_status读取该版本最近构建，build_artifact_id、artifact_digest、artifact_build_id、artifact_build_status及artifact_available读取版本已绑定制品，核对规则与部署查询共用。deployment_states及current_service_states各为status/count数组，count保持字符串，后者按当前服务发布记录、部署和版本关联。最近构建失败时，已绑定成功制品仍按其自身登记事实展示。

版本列表按created_at/id倒序，签名游标绑定本人、脚本、内容状态和页大小，保留微秒边界。列表仅返回摘要。动作数组按名称排序，每项包含name、title、input_schema、input_schema_digest、input_schema_available及output_schema。详情通过元数据投影提供动作参数定义，源码及完整manifest使用作者源码入口读取。

DRAFT且manifest.actions为对象时，action_source为DRAFT_MANIFEST，动作中的input_schema完整覆盖默认定义，未声明时继承manifest.input_schema。草稿动作摘要按递归排序对象键后的紧凑JSON计算SHA-256。其他状态和缺少动作对象的历史草稿读取已登记script_actions，action_source为STORED_PROJECTION，保留已登记摘要。Schema支持对象与布尔值，false保持拒绝所有输入，缺失或类型无效返回null及input_schema_available=false。动作名保留开发者声明。

S04路径id为脚本UUID，version_id为固定版本UUID，action为动作名称。首次进入可选择列表首项并将version_id固定到URL，显式无效版本或动作显示不可用。切换版本、动作和主动刷新前，存在未保存输入时提供确认。版本详情按本人、安全修订和版本缓存，后台聚焦保持当前表单，主动刷新取得新revision后重新初始化。S05及S06链接携带实际版本，试运行跳转携带动作筛选。LIVE新建草稿及创建服务按钮等待对应写入和版本编辑入口接通。

| 动作不存在、处理函数不可调用或协议版本未知 | 拒绝本次执行，报告 ACTION_NOT_FOUND/HANDLER_NOT_CALLABLE/PROTOCOL_UNSUPPORTED |
| 可选生命周期 Hook 未声明 | 跳过；已声明但导出错误不能当作未声明 |
| 输入不符或语义校验拒绝 | INPUT_SCHEMA_INVALID/INPUT_SEMANTIC_INVALID，不进入业务动作，不回显原值 |
| 主动作异常或返回无效 | ACTION_EXECUTION_ERROR/RESULT_SCHEMA_INVALID；先判断是否存在未决外部副作用 |
| 后置、错误或清理 Hook 失败 | 记录附加错误，不覆盖已接受结果、不递归 on_error、不重放主动作 |
| 超时、强杀或节点失联 | 记录运行异常，可能发生外部副作用时保存 UNKNOWN；有核验机制则 RECONCILING，否则 WAITING_INPUT |
| 结果已保存但确认丢失 | 查询 Invocation 接受记录或幂等重投结果，不能重新执行主动作来找回结果 |

## 5. 动态参数表单契约

前端已确认React + TypeScript + Vite + Ant Design；RJSF优先验证，候选包为`@rjsf/core`、`@rjsf/antd`、`@rjsf/validator-ajv8`及兼容版本的Ajv。RJSF只负责参数编辑与展示，不承担脚本执行、权限授予或业务成功判定。以下规则适用于购买前填参、已购服务配置、测试、本人自用和人工接续。

| 环节 | 必须遵循的契约 |
| --- | --- |
| Schema来源 | 使用既有版本/动作API返回的有效Schema及摘要；动作级定义完整覆盖版本级定义。表单控件不能追加固定旅行字段或隐藏必填项，也不能自行合并两个Schema |
| 版本与缓存 | 表单身份绑定script_version_id、action、schema_digest；私有输入缓存另外绑定当前账号和所属草稿/任务。切换账号清除私有状态；切换动作/版本确认未保存内容并重新校验，迟到响应不能覆盖当前表单 |
| 数据形态 | 保留根对象、数组、字符串、数值、布尔及null的原JSON形态，区分缺失、空字符串、0、false和null。布尔Schema true按平台预算允许输入，false始终阻止可执行提交；不能统一包装成对象 |
| 校验方言 | 明确启用Draft 2020-12及平台支持的format/关键字、固定包内引用和限额；前后端采用一致规则。使用RJSF的Ajv适配器时显式选择Ajv2020，不能沿用默认draft-07或只添加元Schema就宣称完成适配 |
| 输入不被校验改写 | 禁止校验器自动补默认值、类型转换或删除额外字段；Ajv实例使用useDefaults=false、coerceTypes=false、removeAdditional=false。RJSF自动填值、空对象生成、字段省略等行为须单独验证；默认值仅作为用户可见且确认的预填内容 |
| 组合与引用 | 验证oneOf/anyOf/allOf、if/then/else、依赖和本包固定引用。切换分支涉及字段移除时先提示并取得明确编辑动作；不得把不能渲染的分支当作不需要校验。禁止运行时网络获取引用 |
| JSON编辑回退 | 平台接受的合法Schema若超出可视化覆盖，或用户主动切换，则使用相同校验规则的JSON编辑器；切换保留输入和值类型。语法错误、校验器不可用或超预算时阻止可执行提交，不绕过校验。平台不支持的Schema仍在发布阶段拒绝 |
| UI元信息 | title、description、examples和错误提示按不可信内容转义。UI布局及控件映射由平台维护，发布者不能注入React组件、任意JavaScript或HTML执行。UI Schema只用于展示，不写入脚本input，也不新增manifest协议字段 |
| 提交与错误 | 最终input按原JSON类型提交，运行/调度/授权/权益等仍在平台信封。服务端再次校验；422的field_errors按JSON Pointer定位，无法映射到控件时显示路径及表单级错误，不能隐藏校验失败或回显敏感原值 |
| 恢复与重复操作 | 回显历史配置使用其固定版本及Schema；迁移版本必须显式重新校验。表单重挂载、自动保存草稿或订阅重连不触发执行；提交按既有Idempotency-Key及If-Match规则处理 |

2026-11-14核对的[RJSF校验文档](https://rjsf-team.github.io/react-jsonschema-form/docs/usage/validation/)说明：默认Ajv适配器使用draft-07，Draft 2020-12尚未在RJSF中得到完整测试。因此必须同时验证校验结果、控件渲染和数据往返，不能因Ajv支持就认定RJSF已满足项目协议。[Ajv方言说明](https://ajv.js.org/json-schema.html)

RJSF候选组合需记录精确包版本、Ant Design兼容关系、支持/回退用例和限制，按[前端专项验收](./05-测试验收与验证记录.md#frontend-tests)决定接入范围。未通过的渲染能力保留JSON编辑通路；不得为了采用候选库降低发布者Schema约束或更改既有协议样例。

内部 v2 是新增产物服务路由；既有内部 v1 路由的信封 2.0 支持由握手能力协商，不能根据路由字符串猜协议兼容。ACTION 批次支持运行中独立提交，也支持一个末尾批次随最终结果提交；不能把已经发布的阶段性批次当作未提交内容重复发布。文件完整上传可先于业务结果接受，上传成功不意味着已经对用户发布或通知。

当前已接入`GET /api/v1/outputs`、`GET /api/v1/runs/{id}/outputs`及`GET /api/v1/outputs/{id}`元数据读取。列表支持run_id、kind、kinds、phase、state、from、to、limit和cursor，未定义字段返回422。kind为text/json/file/message单项，kinds为以逗号分隔的1～4项类型，两者互斥。kinds去重并排序后参与查询与游标签名，文本页签使用kinds=text,message联合读取。state按script_outputs状态过滤，phase为ACTION或OUTPUT_HOOK。时间为含时区ISO日期时间，from包含、to排除。列表返回顶层data数组、next_cursor与request_id，默认20项、最多100项，按created_at及id倒序。游标签名绑定当前账号、规范化筛选和页大小，保留微秒时间排序，修改筛选需从首页重新查询。

仅本人已提交批次中的产物可列出及读取，运行仍在持续时可以查询已提交产物。删除记录及未提交产物返回404；历史过期或隔离产物保留元数据并返回availability。字段包括id、revision、kind、title、file_name、media_type、size_bytes、status、created_at、updated_at、expires_at、failure_code、batch_id、batch_key、phase、run_id、run_status、task_name、availability、deliveries和content_access_configured。整数字段保持十进制字符串。文件可用性进一步检查对象状态及期限，文本类检查私有正文登记，投递状态单独从本人逻辑投递记录及附件关系读取。响应不含正文、payload/object引用及存储路径，详情返回ETag，读取禁止缓存。

当前content_access_configured为false，表示正文存储与下载适配仍待接入，通知重试、批次历史读取及删除命令也按原契约继续实施。C12用元数据展示实际记录，并区分已就绪、投递未知和适配未接入状态。开发示例的文件、JSON、文本及消息内容在浏览器本地预览，工具栏使用当前选中产物。分类、选中ID和预览弹窗保存在URL，文本及消息显示各自可用性、投递状态、运行与批次关联，文件类型按MIME及名称展示相应图标。

## 9. 节点与 Guest Agent 协议

管理员登记节点 → 发放短时单次 bootstrap token（仅登记用途）→ 节点取得限定 node_id 的 mTLS 证书 → 注册能力/镜像摘要/协议版本 → 健康检查后可调度。证书轮换有短重叠窗口，撤销同步至网关；普通脚本不能读取节点或 Agent 私钥。

Runner 与 Guest Agent 的每条控制消息包含 protocol_version、message_id、node_id、attempt_id、lease_generation、sequence、sent_at、deadline、payload_digest。Agent 首次握手绑定本 Attempt 的启动随机挑战及镜像摘要；重复 message_id 同摘要返回原回执，异体拒绝；旧代数仅允许受限晚到证据，不领取新命令。指令为 prepare/start/stop/inspect/collect-result，用户不能传任意宿主命令。

心跳与状态回复只延长服务端认可的当前租约。日志按独立分段/序列上传，不能以日志心跳延长执行授权。断连时有界缓冲，网络许可到期自动失效；节点无法保证执行出口封锁时保持不可调度并隔离资源。结果 ACK 与日志 ACK 不互相替代。

建议使用专属管理网络上的 mTLS 通道，由 Agent 向 Runner 领取本次任务并回传心跳和结果。该通道只暴露给对应 Attempt，不转发到控制数据库和宿主管理接口。实现时优先复用已验证的连接机制，不让普通用户配置转发端口。

Agent 与脚本使用不同系统身份；Agent 管理凭据放在脚本不可读的目录，任务可用令牌仅有本 Attempt 的短时能力。脚本不可访问 QMP socket。即使客户机被攻破，任务级令牌也不能升级为其他用户或节点控制权限。

凭据在环境就绪后经受控通道注入内存文件系统，不写入基础镜像、qcow2 模板、cloud-init seed、容器标签或日志。请求脚本自行签名且必须接触凭据时，明确凭据暴露范围，不能声称 Agent 已完全隐藏它。

Agent 注册、单次启动挑战、mTLS 身份、message_id/sequence/lease_generation、防重及证书轮换按[节点、Guest Agent 与配置契约](./03-接口协议.md#agent)实现。旧代数不能领取新命令；日志 ACK、结果 ACK 与租约续期互相独立。失联节点若不能确认出口封锁则保持隔离，不重新分配残留环境。

### 10.1 标准字段

字段名称是本项目 JSON 协议，不声称与 OTLP 编码完全一致。时间、级别、Body、Trace 与 Attributes 按 OpenTelemetry 数据模型映射。[OTel 日志模型](https://opentelemetry.io/docs/specs/otel/logs/data-model/)

| 字段 | 类型 / 规则 | 写入者 |
| --- | --- | --- |
| `schema_version`、`event_id` | 版本字符串、稳定唯一 ID | 可信 SDK/采集端；重试保留原 ID |
| `timestamp`、`observed_at` | 来源时间可空；可信采集观察时间，UTC | 来源时间不作为订单时序依据 |
| `severity_text`、`severity_number` | TRACE/DEBUG/INFO/WARN/ERROR/FATAL，映射 1/5/9/13/17/21 | 未解析脚本 stdout 默认 INFO；stderr 不自动代表业务失败 |

| `owner_user_id` | 私有任务日志必填；平台公共诊断为空 | 根据已鉴权任务/构建映射填充 |
| `task_id`、`run_id`、`attempt_id` | 按来源可空，必须属于同一链路 | 可信任务上下文 |
| `invocation_id`、`action_name`、`hook_name`、`hook_protocol_version` | action_name 来自版本注册表，hook_name 为有限生命周期名称；无相关来源可空 | 调用归属由平台校验；名称作为结构化字段而非索引标签，SDK 观测不提升可信程度 |
| `booking_operation_id`、`notification_id` | 可空的业务关联 | 业务服务，不接受脚本覆盖 |
| `requested_execution_mode`、`actual_execution_mode` | 三种模式枚举；实际尚未分配时为空 | Dispatcher / Runner |

## 11. 日志查询、SSE、导出与运维 API

### 11.1 查询规则

用户提交任务、运行、来源、级别、关键词和时间范围等固定字段。服务端先检查会话及账号状态，再根据用户 ID 验证目标归属，生成不可被覆盖的查询条件。关键词按字面值转义，首期不开放任意正则、LogQL、PromQL 或标签表达式。

Loki 索引只使用 `environment`、`service`、`source_kind`、`actual_execution_mode` 等有限标签；用户、Run、Attempt、脚本版本、Trace 和订单 ID 放入结构化元数据或 JSON 字段。查询服务强制匹配可信 `owner_user_id` 和 `visibility`，还须校验返回记录的归属。不能把“非索引字段”理解为不需要权限过滤。[Loki 标签设计](https://grafana.com/docs/loki/latest/get-started/labels/)

用户跨全部任务检索可能需要扫描较多数据，因此先在数据库缩小本人 Run/分段范围，限制时间及扫描字节；最近 7 天优先走 Loki，8～30 天通过 `log_query_jobs` 异步扫描授权归档。若没有足够索引性能，返回排队状态或更小时间窗口，不取消权限条件换取速度。

缓存键包含账号、权限版本、过滤条件和数据版本。下载、导出执行、结果领取均重新校验权限；账号停用时终止后续订阅和下载。普通用户的 404/无权响应不得泄露其他用户对象是否存在。

### 11.2 SSE 事件协议

沿用 `GET /api/v1/runs/{id}/events`，统一承载运行详情的类型化事件：

| `event` 类型 | 内容 | 事实来源 |
| --- | --- | --- |
| `run.status` | 状态、阶段与业务版本 | 数据库事件投影 |
| `log.entry` | 脱敏日志与日志事件 ID | 已归档记录的实时投影 |
| `log.gap` | 已知丢弃或无法确定的采集缺口 | 可信采集健康信息 |
| `log.truncated` | 容量上限与受影响来源 | 配额事件 |
| `stream.degraded` | 索引、实时缓存或采集延迟 | 平台健康状态 |
| `stream.closed` | 当前订阅关闭原因 | 订阅服务 |

SSE `id` 使用服务端签名的不透明游标，绑定用户、Run、过滤条件及投影位置，日志自身 `event_id` 放在 payload。`Last-Event-ID` 必须在每次连接鉴权后验证。单连接顺序不等于跨服务因果顺序，前端按日志事件 ID 和业务版本去重。

游标仍在缓存时重放后继续订阅；缓存已淘汰则返回明确的游标过期信息（连接建立前 HTTP 410，已建立连接发送类型化提示），由客户端申请归档补读再建立新订阅。业务事件可由数据库补偿；日志未归档或采集丢失的部分必须显示缺口，不能无提示跳到末尾。

建议心跳 15 秒、每用户最多 3 个实时连接；订阅每 60 秒复核会话和权限，撤销事件主动断开。使用安全会话或请求头，不把长期令牌放在 URL。网络错误采用有上限的退避重连，用户退出页面立即关闭订阅。

Run 进入终态不立即宣告日志完整；清理和日志上传可能仍在继续。订阅展示独立的清理状态和日志收尾状态，收到来源结束及归档进度后再关闭，达到收尾超时则明确提示剩余数据待补传。用户主动离开不改变后端采集，迟到记录可以从历史页面查询。

### 11.3 导出

创建导出任务时固化用户、范围、过滤条件、格式与脱敏规则版本。后台执行时再次检查权限，分页读取授权分段；生成压缩 JSONL 或纯文本，附带时间范围、截断和缺口说明。导出文件 24 小时后清理，下载通过鉴权 API；如采用预签名 URL，最长 5 分钟且明确该链接有效期内具有持有者访问能力，删除时同步撤销可控入口。

导出任务状态为 `PENDING/RUNNING/SUCCEEDED/FAILED/CANCELLED/EXPIRED`。不提供原始未脱敏导出、全工作目录下载或虚拟机内存转储入口。

首页服务与订单各最多3条，运行动态与最近结果各最多2条，待办最多1条，按相应时间及id倒序。服务采用成交release标题与说明，订单及产物只返回本人元数据。结果来自已提交批次中仍可用的READY产物，文件还需对象登记READY且在保留期内，运行过程可以持续产出。fees按currency分别返回funded_service_fee_minor及refunded_service_fee_minor字符串，前者为窗口内已绑定主收款的服务单费用，后者为已确认退款，不汇总额外收款或钱包余额。聚合在同一查询快照完成，详情和下载继续独立鉴权。

统一错误包括 `FORBIDDEN`、`CURSOR_EXPIRED`、`LOGS_EXPIRED`、`QUERY_TOO_WIDE`、`RATE_LIMITED`、`INDEX_DELAYED`、`ARCHIVE_PENDING`、`SERVICE_UNAVAILABLE`。HTTP 状态码与提示一致，后台处理中采用 202 或状态查询，不以空数组代替故障。

P06分别采用游客横幅内说明与FAQ搜索、消费者横幅内搜索、发布者独立搜索栏、管理员横幅内搜索。类别、关键词、展开问题和支持弹窗通过页面URL的group、q、question、support恢复，接口始终读取公开目录，筛选在前端完成。q按空格分词并对标题、答案及关键词进行不区分大小写的同时匹配。未筛选时展示featured问答，指定问题也可包含对应非featured条目。question缺省展开refund，显式空字符串表示全部收起，未知编号显示不可用提示。分类及关键词无结果时提供清除筛选入口。

侧栏及首页页脚的帮助链接保留workspace，登录角色在正常导航及刷新后继续进入对应帮助布局。顶栏在帮助页提交搜索时更新本页关键词及工作区。加载失败显示重试，支持弹窗保留URL并显示配置状态。该实现覆盖公开目录、页面布局和交互，在线支持交付及75页最终视觉验收继续进行。


<a id="public-travel-implementation"></a>
### 公开城市景点目录实现

2026-11-15接入四个公开读取入口，游客、消费者、发布者及管理员读取同一份已开放目录。所有响应设置`Cache-Control: no-store`，沿用统一data/request_id信封。城市及景点列表使用next_cursor分页，默认20条、最多100条，按创建时间及UUID倒序。签名游标绑定资源、筛选、日期及页大小，额外、重复或无效参数返回422及INVALID_REQUEST。

| 入口 | 查询参数 | 返回内容 |
| --- | --- | --- |
| `GET /api/v1/cities` | q、limit、cursor | 已启用城市的id、created_at、十进制字符串revision、code、name及已开放景点数attraction_count |
| `GET /api/v1/attractions` | city_id、date、q、limit、cursor | 已启用城市下已开放景点的身份、创建时间、修订、城市、名称、说明、时区、票价类型与最小单位票价、日期、库存查询状态、渠道能力和关联服务摘要 |
| `GET /api/v1/attractions/{id}` | 可选date | 同一景点的完整公开目录记录，不存在或未开放返回404 |
| `GET /api/v1/attractions/{id}/services` | 可选date | 该景点已绑定的公开旅行服务集合，沿用公开商品的发布快照、价格、Schema、退款规则及可售状态，并核对关联渠道 |

q最多200字符，城市匹配名称和代码，景点匹配名称和城市名，通配符按字面处理。city_id为UUID。date接受真实存在且年份为0001～9999的YYYY-MM-DD日期，用于保留预约条件，响应requested_date回显该值，inventory_status固定为NOT_QUERIED。库存、票种时段的真实开放校验及预约提交继续接入。

景点返回id、created_at、revision、city_id、city_name、name、description、timezone、ticket_price_kind、ticket_price_minor、requested_date、inventory_status、channels及services。FREE票种的ticket_price_minor为字符串0，脚本服务费沿用发布者的amount_minor及currency，分别展示。channels包含id、name、adapter_status、current_rule_version、rule_verified_at、rule_verified及rule_source_url。DISABLED渠道排除，当前规则必须属于同一渠道，rule_verified按已存验证时间且时间已到核对。来源仅输出有效HTTP/HTTPS网址，含用户名密码的网址和其他协议返回null。规则正文、证据正文及账号数据保留在对应受控接口范围。

关联同时核对景点、渠道所属景点、商品所属发布者和公开旅行服务。services摘要包含id、title、amount_minor、currency及availability。重复渠道关联合并为同一商品，详情服务集合保留完整发布者Schema。can_purchase同时核对商品目录状态与该服务所关联渠道的BOOKING_SUPPORTED及当前规则验证时间。渠道能力和商品可售分别展示，前端展示与下单时状态继续由相应业务接口核对。公开商品查询同步核对当前发布属于本商品及发布者，部署、脚本版本、动作和价格方案保持同属发布关系。

P04游客采用三列卡片，消费者采用场馆配图横向列表。三张配图为内置image_gen生成的虚构示例场馆素材，保存于apps/web/src/assets/travel，提示词及来源见[素材记录](../output/verification/public-travel-pages/asset-provenance.json)。真实目录记录沿用自身名称和说明，配图配置继续接入。原型服务按声明的示例Schema及开发标记匹配唯一商品，匹配不唯一时展示服务待接入。

城市、关键词、日期及多服务选择弹窗保存在页面URL，返回P04时保留原筛选。多服务先显式选择商品，服务费使用最小单位字符串计算同币种最低值，多个币种显示查看报价。P05核对指定景点与服务关联，缺少关联、未知景点和目录失败分别展示，查询失败可重试。预约条件作为场景上下文传递，脚本表单继续仅以发布者Schema为准。
