## 1. 身份、响应、幂等与版本

- 用户 API 前缀 `/api/v1`，内部节点 API `/internal/v1`，管理员 API `/api/v1/admin`；不同凭据受众不可互用。时间为 RFC 3339 UTC 字符串，标识为不透明字符串；数据库使用 UUID，不从 ID 暴露个人信息。
- 成功返回 `{data, request_id}`；异步写操作返回 202 及可查询资源 ID；创建完成返回 201。列表返回 `{data: [...], next_cursor, request_id}`，limit 默认 20、范围 1～100，按 created_at/id 稳定排序。游标绑定用户、过滤和排序，越权对象统一 404。
- 错误返回 `{error:{code,message,field_errors,retry_after_seconds},request_id}`。field_errors 仅含 JSON Pointer path、rule、message，不回传原值。不能用 HTTP 200 表示失败。
- POST 创建/命令以及 PATCH/DELETE 使用 Idempotency-Key，作用域为用户、HTTP 方法、规范路由（保留资源 ID，不含查询串）及键。原始请求规范化摘要一致则返回同一资源和原状态码；同键异体 409 IDEMPOTENCY_CONFLICT。记录至少保存 24 小时；过期不解除 Run/Invocation/操作表的永久防重约束。认证初始请求另按挑战 ID 和限流处理。
- 对已有对象的变更要求 If-Match 携带 revision；缺失 428 PRECONDITION_REQUIRED，陈旧 412 REVISION_CONFLICT。幂等重放检查先于修订检查，防止已成功请求因自身更新修订而被误拒。
- 内部节点接口用 mTLS、租约代数及消息/调用 ID 防重，不套用用户 If-Match；声明的只读结果回执权限与业务出站许可分开。
- 所有命令记录 actor、对象、前后修订、原因、request_id；不记录密码、令牌和完整 input。变更失败回滚数据库事务，不发成功事件。

平台请求字段、响应投影、预览/作业/恢复及内部交接的实施补充集中见[开发API契约](./06-详细开发设计.md#dev-api)；不改变下列JSON协议文件。数据库字段、金额类型与关系以[数据库设计](./07-完整系统数据库设计.md)为准。

文档版本 V3.0 不改变脚本协议 2.0、适配/文件交接协议 1.0 或独立日志 schema_version=1.0。版本需要按各自命名空间协商，不能根据文档版本或路由前缀推断。

## 2. 平台请求类型

| 类型 | 必填内容 | 可选内容与规则 |
| --- | --- | --- |
| TaskCreate | script_version_id、action、input、schedule、execution、authorization_id | name、credential_bindings=[]、notification_policy、concurrency_key；状态默认 DRAFT |
| TaskPatch | 完整的新配置（同 TaskCreate） | 使用 PATCH 路由但不对 input 深合并；创建新的 config_version |
| Schedule | kind=manual/once/cron/interval/service、timezone | once 有 at；cron 有 expression；interval 有 interval_seconds≥1；ends_at、max_runs≥1、misfire_policy=skip/coalesce_once；互斥字段非法即拒绝；continuous 仅 service/manual，service 激活只启动一次 |
| Execution | requested_execution_mode | run_mode=finite/continuous、allow_tcg_fallback=false、resource_profile_id、strict_timing=false、not_before、deadline、retry_policy；finite 使用 max_runtime_seconds，continuous 可选 max_uptime_seconds/restart_policy/stop_grace_seconds/output_interval_seconds，详见[持续运行设计](./02-系统架构与详细设计.md#continuous)；实际模式由平台分配 |
| AuthorizationCreate | script_version_id、action、network_grants、credential_bindings、resource_profile_id、expires_at | task_id 可在绑定时回填；批准范围不得超过版本声明和本人权限；input/config 摘要在绑定时固定 |
| ResumeRequest | pending_action_id、resume_action、完整 input、authorization_id | credential_bindings；恢复 action 来自待处理项允许列表；If-Match 对应待处理项 |
| ResolutionRequest | disposition、reason、evidence_refs=[] | completed/not_executed 须 confirm_resolution=true；close_unresolved 保持 UNKNOWN；记录 USER_REPORTED，核验器用专用入口 |
| CredentialCreate | name、kind、secret_payload | kind 是受支持凭据类型；返回仅 ID/掩码/版本，不返回明文；未绑定凭据不能被脚本任意读取 |
| EventSubmit | 事件信封及稳定 event_key | 身份、归属和订阅从调用上下文校验；不接受外部任意收件地址 |

保存草稿允许不完整配置，另用 draft_payload 保存；不创建执行授权或可调度 config_version。TaskCreate 完整字段要求适用于启用或保存可执行配置，草稿编辑响应明确列出缺项。

## 3. 账号、脚本、任务与运行 API

| 接口 | 输入/条件 | 响应及事务出口 |
| --- | --- | --- |
| POST /auth/register、/auth/verify-email | 邮箱/密码/accepted_terms_version，challenge_id/token | 注册统一202受理，新账号UNVERIFIED，验证成功200 ACTIVE并创建个人默认配置 |
| POST /auth/login、/auth/logout | 有效账号；会话身份 | 会话/撤销结果，不返回可枚举账号信息 |
| POST /auth/password-reset-requests、/auth/password-resets | 邮箱，单次 challenge_id/token/new_password | 找回请求统一202，重设成功200并撤销会话及旧找回凭证 |
| POST /me/email-change-requests、/me/email-changes | 最近认证；新邮箱；双向验证凭证 | 202 挑战；完成后增加 security_revision 并撤销旧会话 |
| POST /me/closure、GET /me/closure | 最近认证、明确注销请求 | 202 CLOSING 与清理进度；关闭后以受限注销回执令牌只查进度 |
| POST /scripts、/scripts/{id}/versions | 元数据；包上传引用及清单 | 201 DRAFT；文件引用必须属于本人且已完成上传 |
| POST /script-versions/{id}/seal、/builds | 修订；固定内容 | 200 SEALED/202 Build；制品合格后 READY |
| POST /publisher/services/{id}/publish | 本人服务、自动检查、部署READY、按次价格及交付规则 | ACTIVE可售卖，无人工批准；存量订单保持原release |
| POST /script-versions/{id}/retire | 修订、原因 | RETIRED 只禁止新绑定；保留合法存量任务授权，不新增 VERSION_REVOKED 阻塞；审计及 Outbox |
| POST /script-versions/{id}/revoke | 修订、原因 | REVOKED 阻止新调用、撤销相关许可并建立 VERSION_REVOKED 阻塞；在途效果另行核验 |
| GET /script-versions/{id}/actions | 可读取版本 | 动态动作、有效 Schema 与摘要；无凭据或用户 input |
| POST /credentials、/credentials/{id}/versions、/credentials/{id}/revoke | 本人凭据；修订/密文输入 | 创建或撤销版本；相关授权失效，不删除在途使用证据 |
| POST /execution-authorizations | AuthorizationCreate | 201 固定授权，任务绑定时检查输入摘要与范围 |
| POST /tasks、PATCH /tasks/{id} | TaskCreate/TaskPatch、修订 | 201/200 Task、config_version、validation；草稿有单独 draft_payload |
| POST /tasks/{id}/activate、/pause、/resume、/archive | 修订，恢复不得存在阻塞 | 状态及 next_fire_at；归档保留待处理入口 |
| POST /tasks/{id}/runs | 幂等键；手动运行当前配置 | 201 Run；被阻塞返回 409 TASK_BLOCKED，附本人可访问的阻塞项 |
| GET /tasks、/tasks/{id}、/runs、/runs/{id} | 归属、游标 | 配置及独立运行/效果/验证/清理状态，历史输入按权限另取 |
| GET /runs/{id}/result、/runs/{id}/results | 归属 | 当前流程采用的结果及来源；results 为历次 Invocation 分页，不覆盖历史 |
| POST /runs/{id}/stop | Run 修订、原因、有限宽限期 | 202 STOPPING；默认暂停后续服务启动，已有 Task 终态不重开 |
| POST /runs/{id}/cancel | Run 修订、原因 | 202 取消请求；最终是否 CANCELLED 依效果判断 |
| GET /pending-actions、POST /runs/{id}/resume | 本人待处理项；ResumeRequest | 待处理清单/202 continuation、Run；原子消费 |
| POST /runs/{id}/resolutions、/reconcile | ResolutionRequest；已授权核验绑定 | 201 人工结案记录/202 核验；明确结论只暂停仍可运行任务，保留 ARCHIVED/COMPLETED/EXPIRED；使原计划授权失效，不自动重跑 |
| GET /notifications、POST /notifications/{id}/read | 本人；通知修订 | 站内状态；阅读不表示外部业务已确认 |
| GET /runs/{id}/events、/logs；POST /log-exports | 归属、受限筛选 | SSE/分页/202 导出；详细协议见[日志运维设计](./04-部署运维与监控手册.md#logging) |
| POST /data-deletions、GET /data-deletions/{id} | 本人范围、保留策略 | 202 删除标记及逐存储进度；归档与删除是不同操作 |
| POST /internal/v1/runs/{id}/claim | 节点 mTLS、能力、可用配额 | 原子创建租约/Attempt；请求 ID 重放返回同一领取结果 |
| POST /internal/v1/attempts/{id}/heartbeat | 身份、代数、环境摘要 | 最新期限/停止指令；旧代数 409 STALE_LEASE |
| PUT /internal/v1/invocations/{id}/result | 结果信封及摘要 | 首次 201 accepted、同摘要 200；矛盾 409 RESULT_CONFLICT |
| GET /internal/v1/invocations/{id}/receipt | 只读结果回执权限 | accepted/digest/accepted_at；不重新执行动作 |
| POST /internal/v1/invocations/{id}/events | 自定义事件信封 | 201/200 事件回执；同键异体 409 |

上表用户路由均带 `/api/v1` 前缀，内部完整路由保持原样。上传采用鉴权签发上传会话、限定对象/大小/摘要、完成确认后引用；未确认对象不能构建，孤儿定期清理。产物下载只经鉴权入口，不能接受任意宿主路径。

### 3.1 其他资源入口

服务目录与详情读取当前release的标题、说明、参数和交付规则，返回script_version、published_at、updated_at、output_schema、resolution_seconds及validity_seconds。availability由发布者、脚本版、部署状态和开发样例标记计算，包含can_purchase和reason。列表及详情共用该投影，参数说明按发布者Schema展示，报价和执行时继续重新校验状态与授权。

认证挑战受理投影包含challenge_id、expires_at和delivery_status。本地开发验证模式增加development_token，由04约束启用条件，正式邮件交付继续按通知模块接入。邮箱验证成功返回verified，前端回到密码登录。重设成功返回reset与sessions_revoked。注册受理与找回受理采用统一响应结构，账号状态及邮箱存在性规则见06。

| 资源 | 路由 | 边界 |
| --- | --- | --- |
| 服务市场/代码资产 | GET /api/v1/services；GET /api/v1/me/scripts | 市场公开服务说明；代码资产仅本人，购买不授予源码 |
| 旅行目录 | GET /api/v1/attractions、/api/v1/channels、/api/v1/channels/{id} | 扩展启用后开放，能力和规则来源可查 |
| 凭据校验 | POST /api/v1/credentials/{id}/validate | 本人凭据、选择的脚本版本/校验 action、完整 input 与授权；创建受控 Run，不在 API 进程执行代码，不要求动作固定命名 validate_auth |
| 出行人与订单 | /api/v1/travelers、GET /api/v1/booking-orders、POST /api/v1/booking-operations/{id}/reconcile | 本人数据与扩展授权；不能直接写已核验事实 |
| 节点和执行策略 | /api/v1/admin/nodes、/runtime-policies、/images | 管理权限及修订，不接收任意宿主命令 |

日志/观测、产物和导入的专门路由分别在本文件对应章节维护。

### 3.2 角色页面操作与权限契约

本表与[角色目录](./contracts/ui-role-catalog.json)逐项同步。GUEST/USER/PUBLISHER/ADMIN为四工作区，发布者是个人账号创作能力，无人工入驻或发布审批；ADMIN按后台能力执行。购买服务只授予使用权，不自动授予源码。所有操作同时检查归属、状态、功能可用性、修订和业务限制；付费执行校验订单与权益。

公共能力查询`GET /api/v1/me/capabilities`返回可用工作区、能力、对象允许动作和阻塞原因，不返回秘密。异步作业通过`GET /api/v1/operations/{id}`查回执。破坏性命令的`POST /api/v1/action-previews`返回5分钟有效的范围/影响摘要，执行时仍重新检查状态。

通用TaskCreate保留给PRIVATE_SELF_USE，仅脚本所有者允许；消费者付费服务使用PaidTaskCreate语义，直接传script_version_id不能绕过订单权益。测试执行使用开发配额并带execution_context=AUTHOR_TEST，不创建伪造Payment。消费者付费schedule仅manual/once/有期限service；不接受自动重复收费的cron/interval。

### 3.4 支付渠道回调、查询与稳定错误

支付适配入口`POST /api/v1/payment-provider/webhooks/{provider}`不使用用户会话，必须验证渠道签名、商户、事件ID、交易号、订单号、金额和币种。接收原文在受限保留中用于验签/争议核对，日志不输出秘密。非法签名/错金额拒绝并记录诊断；合法重复事件返回已处理回执，不重复发权益或写分录。平台主动查询通过内部`PaymentAdapter.queryPayment/queryRefund/queryPayout`，不得给消费者开放任意渠道请求。

PaymentAdapter要求createPayment、closePayment、queryPayment、refund、queryRefund、payout、queryPayout；所有写入使用稳定provider_request_id。支付渠道尚未选定/接入，字段由适配层映射，本设计不声明真实收款已可用。订单过期与晚到支付按架构第28节自动退款，不重新履约。

新增错误：SERVICE_NOT_AVAILABLE（409）、QUOTE_EXPIRED（409）、PRICE_CHANGED（409）、PAYMENT_PENDING_RECONCILIATION（409）、ENTITLEMENT_REQUIRED（403）、ENTITLEMENT_EXHAUSTED（409）、FULFILLMENT_IN_PROGRESS（409）、REFUND_BLOCKED_PENDING_VERIFICATION（409）、REFUND_AMOUNT_EXCEEDED（422）、PAYOUT_PENDING_RECONCILIATION（409）、FEATURE_DISABLED（403）、ACCESS_SCOPE_DENIED（403）、ACCESS_SESSION_EXPIRED（403）、LAST_ACCESS_MANAGER（409）。未知支付/退款/打款错误必须给原资源查询入口，不建议新交易重试。

历史订单、账单、退款、结算和外部未决查询不因停止新售卖或停用场景而消失。门票外部记录使用`/booking-orders`，平台脚本服务交易使用`/service-orders`，禁止复用同一路由混淆语义。免费预约外部票款为0、NOT_REQUIRED，首期无门票代付接口。订阅/自动续费/余额充值API不在本版开放。

<a id="publisher-profile-api"></a>

### 3.5 本人发布者资料

`GET /api/v1/me/publisher-profile`返回`{profile,terms}`。尚未开通时profile为null；已有资料只返回id、public_name、description、terms_version、enabled、revision、created_at、updated_at。terms包含当前version和paragraphs供用户阅读确认。读取不创建资料，服务端从会话确定归属，拒绝查询参数。资料存在时响应ETag为带双引号的revision，revision始终为十进制字符串，响应禁止缓存。

`POST /api/v1/me/publisher-profile`只接受public_name、description、accepted_terms_version。昵称为1～120位非空文本，简介及公开联系说明为1～10000位非空文本，保存时去除两端空白，约定版本必须与GET返回的当前版本一致。首次开通显式勾选确认，成功返回201及profile；更新返回200及profile。首次创建无需If-Match，更新需携带读取时的ETag，缺少返回428，过期返回412。字段错误用JSON Pointer定位，额外字段返回422。账户已验证且状态ACTIVE，资料已停用时返回403。

POST要求会话CSRF和Idempotency-Key。同一用户、方法、规范路由和键下，以规范化请求正文的HMAC摘要判定重复，字段顺序不影响摘要。原请求回执在修订检查前回放，保持原状态码和原资料快照；同键异体返回409。24小时内回执正文加密保存在private_payloads，过期重用键时清除旧正文并保留资料唯一约束。回执无法解密时返回503，客户端沿原键重试。资料、审计、Outbox与命令回执同事务保存，按用户锁串行处理首次创建及并发更新。每个用户至多一份资料，停用资料不能通过重复开通恢复。

开通后下一次身份读取获得PUBLISHER工作区，保留USER及既有后台能力。基础实现已覆盖此资料命令，其他业务命令继续按各自实现进度接入统一幂等。profile没有独立联系邮箱字段，公开联系说明由用户写入简介。S15联系邮箱仅保留在本地原型预览中，live界面只提交当前定义的三个请求字段。

### 3.6 本人资料与会话

GET /api/v1/me返回id、display_name、email_mask、status、revision、security_revision、locale、timezone、updated_at、roles、capabilities、current_session及is_last_access_manager。邮箱保留首字符及域名，账号与安全修订均为十进制字符串，登录和bootstrap中的security_revision同步采用字符串。current_session返回当前会话的id、revision、client_summary、authenticated_at、last_seen_at、expires_at、revoked_at和is_current。client_summary保存从UA提取的固定设备与浏览器标签。is_last_access_manager表示当前账号是否为唯一有效、已验证且拥有永久access.manage授权的管理员，注销命令继续按管理锁及最后管理员保护规则实现。

PATCH /api/v1/me接受display_name、locale、timezone中的至少一项，全部为1～120位非空文字。昵称去除两端空白，语言及IANA时区通过Intl验证并规范化，旧账号缺少偏好行时读取默认值并在首次偏好修改时创建。请求携带CSRF、Idempotency-Key与If-Match账号修订，未知字段422、缺修订428、过期412、同键异体409。成功返回id、display_name、revision、locale、timezone及updated_at，同键原体回放原响应优先于修订检查。资料、偏好、审计、Outbox及加密回执同事务保存，安全修订与现有会话继续沿用。

GET /api/v1/me/sessions按created_at/id倒序分页，limit默认20且最多100，签名游标绑定本人及页大小。列表包含当前有效且未超出30分钟空闲窗口的本人会话，字段与current_session一致。邮箱原文、密码摘要、会话令牌及其摘要均保留在服务端受限数据内。读取响应禁止缓存，GET me返回账号ETag，资料及单会话写入返回相应新ETag。

DELETE /api/v1/me/sessions/{id}携带CSRF、Idempotency-Key和该会话If-Match，空正文或空对象表示撤销指定本人会话，越权404。DELETE /api/v1/me/sessions/others用于账户页退出其他会话，使用CSRF与Idempotency-Key，服务端从当前会话排除自身并原子撤销其他有效会话。返回revoked_count、current_session_id及新账号revision，重复请求回原计数。单会话响应返回id、revision、revoked和was_current，后者表示原命令发起时是否为当前会话。当前会话删除的修订比对扣除本次鉴权活动刷新带来的变化，额外并发变更仍返回412；回执跨设备读取时按本次会话ID判断Cookie处理。

资料和会话命令先锁用户并重新检查当前账号与会话有效性。退出当前通过既有POST /auth/logout撤销并清除Cookie，审计和Outbox同事务落库。后续鉴权拒绝已撤销会话，订阅中断随SSE模块继续接入。C21资料修改、会话弹窗和退出其他会话使用实际接口，邮箱双向变更、账号注销及数据清理继续按原设计实施。会话时间展示采用本人locale与timezone，其他页面的地区化接入继续推进。

## 5. 脚本包、清单、自定义动作与输入 Schema

新协议 2.0 保留原四类信封，并增加产物登记与批次协议：[清单](./contracts/manifest.schema.json)、[调用](./contracts/invocation.schema.json)、[结果](./contracts/result.schema.json)、[自定义事件](./contracts/script-event.schema.json)。[产物登记](./contracts/output.schema.json)、[产物批次](./contracts/output-batch.schema.json)。业务 input/data 不写死在信封中，分别按发布者的有效 Schema 二次校验。1.0 Schema 见 contracts/v1.0；协商版本后分别校验，禁止把旧信封静默当作 2.0。

有效输入 Schema = `actions[action].input_schema`（若显式存在），否则 `input_schema`。版本 input_schema 始终必填，包括无参数脚本。标准 hooks 模式每个动作有 handler 和 output_schema；legacy 仅一个默认入口动作，可省结构化输出，但不能宣称存在业务结果。动作名在该版本内唯一，平台不维护业务动作枚举。

Schema 使用 JSON Schema Draft 2020-12。首期允许布尔 Schema 与对象 Schema；根业务输入可为任意 JSON 类型。上传时执行方言元校验和平台支持项检查；允许类型、对象/数组/数值/字符串约束、required、enum/const、组合/条件、依赖、局部引用和 $defs。引用仅可解析本包已固定的 Schema，禁止校验期间网络取引用；循环引用、过深结构、超出计算预算或未知校验关键字明确拒绝。发布前编译后端与前端使用的相同 Schema 配置；客户端无法渲染时使用 JSON 编辑器，不能放宽校验。

`default`、`title`、`description`、`examples` 为展示信息；后端不补值、不删字段、不转换类型。平台明确对 `date`、`date-time`、`uri`、`email` 启用格式校验，其余 format 在发布时拒绝，避免客户端与服务端理解不同。正则与输入有大小和执行预算。对 Schema 本身的约束不等于强制业务字段；清单检查器与业务校验器是不同环节。

初始限额：清单含内嵌 Schema 总计 1 MiB，业务 input 256 KiB，结果信封 1 MiB，自定义事件 data 64 KiB；更大产物走对象上传，不塞进结果 data。限额随资源策略公开，发布者 Schema 不可绕过平台资源预算；超限返回明确错误且不回显原值。表单与服务端采用同一限额，业务字段仍完全由发布者定义。

legacy 可附带独立 adapter 1.0 制品配置（不在脚本 2.0 manifest 内增加字段），并由封存索引绑定摘要；必须协商 Runner 能力后启用。它仍受唯一动作、Schema、网络/凭据边界及进程结果语义约束。声明式映射、连续文件交接、有限通知桥接和不支持的能力详见 [接口协议与脚本开发规范](./03-接口协议与脚本开发规范.md#legacy)。旧脚本的 safe_resume 不从名称、进程循环或桥接能力推断。

| 字段 | 功能要求 |
| --- | --- |
| `schema_version` | 明确协议版本，不兼容时拒绝执行 |
| `script_id`、`version` | 资产和版本标识；服务端同时生成不可变版本 ID |
| `language`、`entrypoint` | 指定语言和包内入口；Hook 模式由 SDK 在执行环境中加载其导出函数，禁止越出包目录 |
| `integration_mode` | `hooks` 标准接入或 `legacy` 兼容运行；使用 Hook 名称不自动提升结果可信程度 |
| `hook_protocol_version`、`hooks` | Hook 模式声明协议版本；hooks 仅登记可选生命周期 Hook，允许空对象 |
| `actions`、`default_action` | 发布者自定义动作注册表及默认动作；每个动作指定处理函数、名称说明、输出 Schema 与副作用声明，不限于平台预设业务枚举 |
| `input_schema` | 每个可执行版本必填，由发布者定义业务输入的字段、结构、类型、必填、枚举、长度及其他受支持约束；平台不追加统一业务字段 |
| `credential_requirements` | 所需凭据类别，不包含真实凭据 |
| `dependencies_lock` | 锁定依赖及构建输入 |
| `network_requirements` | 请求域名和所需网络方式，最终权限由平台策略自动校验及用户授权共同限制 |
| `supported_execution_modes` | 发布者声明支持的执行方式；实际验证证据单独展示，不授予节点权限 |
| `actions.*.input_schema` | 可选完整覆盖版本级 input_schema，缺省继承；不进行隐式合并，最终有效 Schema 仍由发布者定义 |
| `actions.*.output_schema` | 标准 Hook 模式每个动作必填，由发布者定义结果 data 的 JSON Schema；legacy 仅日志运行可省略，不声称有结构化业务结果 |
| `events`、`extensions` | 可选自定义事件定义及显式业务扩展绑定；普通脚本可为空 |

动作名、分类和 `side_effects` 是发布者声明，不是权限证明。动作在脚本版本内注册，不维护全平台封闭业务能力枚举；真正的网络、凭据和资源授权由平台策略控制。

输入参数按以下规则处理：

1. 版本级 `input_schema` 必须提供；动作声明完整 input_schema 时优先使用该定义，否则继承版本定义。具体必填项按有效 Schema 的 required 等约束决定。无参数脚本也须显式定义接受的输入。
2. Schema 随 ScriptVersion 固定。草稿可暂缺 Schema；进入可执行状态、私有测试或服务发布前必须校验 Schema 有效性及平台支持范围，缺失、无效或不支持的校验规则明确报错。
3. 创建、编辑和测试任务时，根据所选版本的 Schema 生成参数表单；`title`、`description` 和 `examples` 用于展示说明。复杂结构无法直接渲染时提供 JSON 编辑入口，仍执行相同校验，不忽略约束。
4. `default` 可以供表单预填，但预填值必须成为用户确认的提交内容；服务端校验不静默补默认值、不转换类型、不删除多余字段。额外字段是否允许以该 Schema 为准。[JSON Schema 对象规则](https://json-schema.org/understanding-json-schema/reference/object)、[注解与默认值](https://json-schema.org/understanding-json-schema/reference/annotations)
5. 前端即时提示，服务端在保存任务、手动测试、触发执行和人工恢复时按绑定版本再次校验最终输入；返回字段路径、规则和可读原因，避免回显敏感参数值。运行使用已校验的参数快照。
6. 修改 Schema 必须创建新版本。用户主动迁移版本时展示字段差异并重新校验；新必填项未填写时不得启用新配置。日期、人数、时段等只是某个发布者可能定义的字段，平台不得要求所有脚本包含它们。

平台运行编号、可空扩展上下文、调度和执行方式属于独立字段；input 仅包含用户按所选动作有效 Schema 提交的参数。旅行场景的预约授权与防重由对应连接器校验，普通自定义任务不要求渠道或预约目标。

<a id="schema-form"></a>

### 5.1 React动态参数表单契约

前端已确认React + TypeScript + Vite + Ant Design；RJSF优先验证，候选包为`@rjsf/core`、`@rjsf/antd`、`@rjsf/validator-ajv8`及兼容版本的Ajv。RJSF只负责参数编辑与展示，不承担脚本执行、权限授予或业务成功判定。以下规则适用于购买前填参、已购服务配置、测试、本人自用和人工接续。

| 环节 | 必须遵循的契约 |
| --- | --- |
| Schema来源 | 使用既有版本/动作API返回的有效Schema及摘要；动作级定义完整覆盖版本级定义。表单控件不能追加固定旅行字段或隐藏必填项，也不能自行合并两个Schema |
| 版本与缓存 | 表单身份绑定script_version_id、action、schema_digest；私有输入缓存另外绑定当前账号和所属草稿/任务。切换账号清除私有状态；切换动作/版本确认未保存内容并重新校验，迟到响应不能覆盖当前表单 |
| 数据形态 | 保留根对象、数组、字符串、数值、布尔及null的原JSON形态，区分缺失、空字符串、0、false和null。布尔Schema true按平台预算允许输入，false始终阻止可执行提交；不能统一包装成对象 |
| 校验方言 | 明确启用Draft 2020-12及平台支持的format/关键字、固定包内引用和限额；前后端采用一致规则。使用RJSF的Ajv适配器时显式选择Ajv2020，不能沿用默认draft-07或只添加元Schema就宣称完成适配 |
| 输入不被校验改写 | 禁止校验器自动补默认值、类型转换或删除额外字段；Ajv实例使用useDefaults=false、coerceTypes=false、removeAdditional=false。RJSF自动填值、空对象生成、字段省略等行为须单独验证；默认值仅作为用户可见且确认的预填内容 |
| 组合与引用 | 验证oneOf/anyOf/allOf、if/then/else、依赖和本包固定引用。切换分支涉及字段移除时先提示并取得明确编辑动作；不得把不能渲染的分支当作不需要校验。禁止运行时网络获取引用 |
| JSON编辑回退 | 平台接受的合法Schema若超出可视化覆盖，或用户主动切换，则使用相同校验规则的JSON编辑器；切换保留输入和值类型。语法错误、校验器不可用或超预算时阻止可执行提交，不绕过校验。平台不支持的Schema仍在发布阶段拒绝 |
| UI元信息 | title、description、examples和错误提示按不可信内容转义。UI布局及控件映射由平台维护，发布者不能注入React组件、任意JavaScript或HTML执行。UI Schema只用于展示，不写入脚本input，也不新增manifest协议字段 |
| 提交与错误 | 最终input按原JSON类型提交，运行/调度/授权/权益等仍在平台信封。服务端再次校验；422的field_errors按JSON Pointer定位，无法映射到控件时显示路径及表单级错误，不能隐藏校验失败或回显敏感原值 |
| 恢复与重复操作 | 回显历史配置使用其固定版本及Schema；迁移版本必须显式重新校验。表单重挂载、自动保存草稿或订阅重连不触发执行；提交按既有Idempotency-Key及If-Match规则处理 |

2026-11-14核对的[RJSF校验文档](https://rjsf-team.github.io/react-jsonschema-form/docs/usage/validation/)说明：默认Ajv适配器使用draft-07，Draft 2020-12尚未在RJSF中得到完整测试。因此必须同时验证校验结果、控件渲染和数据往返，不能因Ajv支持就认定RJSF已满足项目协议。[Ajv方言说明](https://ajv.js.org/json-schema.html)

RJSF候选组合需记录精确包版本、Ant Design兼容关系、支持/回退用例和限制，按[前端专项验收](./05-测试验收与验证记录.md#frontend-tests)决定接入范围。未通过的渲染能力保留JSON编辑通路；不得为了采用候选库降低发布者Schema约束或更改既有协议样例。

## 7. 结果、回执与待处理协议

```json
{
  "protocol_version": "2.0",
  "run_id": "run_demo_001",
  "attempt_id": "attempt_demo_001",
  "invocation_id": "inv_demo_001",
  "action": "summarize_records",
  "outcome": "COMPLETED",
  "summary": "已汇总 1 条记录",
  "data": {
    "item_count": 1,
    "records": [
      {
        "id": "record_demo",
        "status": "active"
      }
    ]
  },
  "action_required": null,
  "error": null,
  "outputs": []
}
```

| 字段 | 约定 |
| --- | --- |
| `outcome` | COMPLETED、ACTION_REQUIRED、ERROR；表示协议执行结果，不保证外部业务事实已核验 |
| `data` | COMPLETED 时必须符合该动作发布者 output_schema；其他 outcome 可为 null，非 null 时仍校验 |
| `summary` | 可选、限长且脱敏的纯文本说明，不执行 HTML/JS |
| `outputs` | 接受时的引用快照，来自当前授权产物系列已提交项或末尾 ACTION 批次；后续/历史通过独立集合分页查询，不嵌入文件正文或任意下载地址 |
| `action_required` | ACTION_REQUIRED 时必填，包含允许的处理类型、说明、期限和恢复动作；恢复动作必须属于该版本注册表，仍需权限与参数校验 |
| `error` | ERROR 时必填，包含代码、脱敏消息及有限详情；不能由脚本决定平台自动重试 |
| 运行关联字段 | SDK 封装，服务端与实际派发记录核对，脚本自报值不能覆盖归属 |

通用界面按 Schema 展示自定义 data，至少提供 JSON 与摘要视图。数据格式有效与业务真实性分开，通用脚本结果默认标明来自脚本报告。需要 VERIFIED 等领域事实时由已绑定扩展的可信核验器处理，普通脚本不用返回 availability、booking 或任何特定业务结构。

Hook 模式由 SDK 封装结果并提交，开发者无需管理结果文件。文件通道按 Invocation 分配独立路径，检查大小、越界和符号链接；兼容模式按独立执行分配路径。stdout/stderr 仅为日志。平台收到并持久化有效结果后返回接受确认，重复结果按调用 ID 幂等；矛盾结果报告协议错误，不覆盖已接受事实。

### 7.1 待处理与多次调用

| outcome | data | action_required / error | 平台行为 |
| --- | --- | --- | --- |
| COMPLETED | 必须通过 output_schema；允许 Schema 明确接受的 null | 均为 null | 保存脚本报告；没有未决效果且流程已完成时 SUCCEEDED |
| ACTION_REQUIRED | null 或通过 output_schema | action_required 必填，error 为 null | 建立 PendingAction，释放环境并阻塞后续触发 |
| ERROR | null 或通过 output_schema | error 必填，action_required 为 null | 无未决效果时 FAILED；否则核验或转人工 |

`action_required` 含 reason、instructions、expires_at、resume_action。resume_action 可为 null（仅外部处理/人工说明），非空时必须在当前动作的 `resume_actions` 声明和该版本注册表中；其网络与凭据权限重新授权，不能通过恢复扩大原授权。恢复动作输入以该动作固定 Schema 为准，不接受结果临时追加必填业务字段。

action_required 是创建待处理项的请求，不是直接修改 Run 的授权。平台可缩短期限、拒绝非法跳转或将未知副作用限制为核验。外部链接需校验协议与目标策略，页面不执行发布者 HTML/JS。

新结果的 `outputs` 仅为接受时的引用快照（本授权系列已提交项或一个末尾 ACTION 批次），不存文件正文或任意下载 URL，也不要求包含全部历史。运行中和 final Hook 都可产生独立批次，结果信封不改写。`on_outputs` 和 `ctx.outputs.batch/collect/text/json/file/bytes/message/get` 的完整输入、阶段、错误、格式、状态及权限见[接口协议与脚本开发规范](./03-接口协议与脚本开发规范.md#outputs)。业务 input_schema 与 output_schema 不因产物功能改成固定业务结构。


结果接受、Outbox、待处理项和批次的原子边界见[架构事务设计](./02-系统架构与详细设计.md#transactions)；效果与可信状态见[结果可信度](./02-系统架构与详细设计.md#effects)。

## 8. 生命周期 Hook、SDK 与调用顺序

以下为待实现的协议，未声称已有可安装 SDK。业务函数由发布者在 actions 中注册，名称不限于平台预设业务；生命周期 Hook 采用固定名称，全部可选。

| 接口 | 返回与用途 | 约束 |
| --- | --- | --- |
| `actions.<name>.handler(ctx)` | 执行任意受支持的自定义 HTTP 业务，返回 outcome、data 等 | 至少一个动作；输入输出按发布者有效 Schema 校验 |
| `on_init(ctx)` | 无返回值，准备本次调用的局部资源 | 可重复执行，不负责主要业务写入 |
| `validate_input(ctx)` | 返回 valid 与脱敏 issues，补充领域语义检查 | 不放宽 Schema，不增加隐藏必填项，不改写输入 |
| `before_action(ctx)` | 无返回值，动作前准备 | 异常阻止本次主动作 |
| `on_outputs(ctx, trigger)` | 无业务返回值；可反复为不同 emission 生成产物 | 可选；运行中/间隔/检查点/final 触发串行处理；受独立 OUTPUT 权限和每次期限约束 |
| `after_action(ctx, result)` | 无返回值，处理已接受结果的副本 | 不能改写已保存结果或触发主动作重放 |
| `on_error(ctx, error)` | 无返回值，记录脱敏诊断 | 保留主错误，不递归调用，不自行申请自动重试 |
| `on_cleanup(ctx)` | 无返回值，释放局部资源 | 尽力执行，宿主回收不依赖其一定运行 |

`check_availability`、`book`、`query_order`、`validate_auth` 可以作为旅行场景动作模板。只有显式选择该扩展时才检查相应动作组合与结果格式；自定义脚本不必实现这些函数。核心不根据动作恰好名为 book 而授予权限或启用订单状态机。

| SDK 上下文 / 能力 | 通用约定 |
| --- | --- |
| `ctx.input` | 对应动作有效 Schema 校验后的只读业务输入快照 |
| `ctx.action`、运行关联字段 | 本次注册动作、Run、Attempt、Invocation、脚本版本及租约引用 |
| `ctx.context`、`ctx.runtime` | 可空扩展上下文、执行窗口、运行模式；实际授权取自服务端记录 |
| `ctx.http.request(request)` | 通用 HTTP/HTTPS 请求，允许在批准的网络与凭据范围内自行构造方法、URL、请求头和请求体；不要求平台为每种业务实现连接器 |
| `ctx.connectors.invoke(operation, payload)` | 可选已注册的可信领域操作；使用该扩展时才需要对应操作定义与授权 |
| `ctx.logger` | 受限结构化日志，进入统一脱敏与配额链路 |
| `ctx.checkpoint` | 本任务范围的检查点读写，不提供任意数据库或文件系统管理能力 |
| `ctx.events`、`ctx.notify` | 提交已声明事件和通知请求，由平台校验订阅、去重和投递 |
| `ctx.outputs` | batch/collect/text/json/file/bytes/message/get；多格式输出与每批幂等，可在同 Run 多次提交 |
| `ctx.artifacts` | 旧文件输出适配接口，新实现统一走 outputs 的上传、校验、权限与保留 |
| `ctx.progress`、`ctx.wait` | 持续任务进度及可取消等待；运行心跳由 Runner/Agent 独立维持 |
| `ctx.signal`、`ctx.deadline` | 协作取消与截止时间，Runner 另行实施硬限制 |
| `ctx.state` | 同一次调用的 Hook 之间共享临时对象，不保证跨调用或恢复保存 |

函数名、SDK 只读对象及发布者声明不能作为安全边界。任意业务逻辑仍在任务专属容器或客户机中执行；通用网关检查实际网络目标、凭据绑定与预算，平台不直接执行用户提供的业务解析代码。请求体可以是发布者自定义结构，不要求统一旅游字段；是否符合某项业务授权由主动绑定的领域连接器另行判断。

### 8.1 唯一调用顺序

1. 控制面校验版本、动作、完整输入、权限、窗口与并发；固定 Schema 摘要及输入摘要。
2. 领取租约并准备环境；SDK 加载代码后执行可选 `on_init → validate_input → before_action`。
3. 执行所选 `actions.<name>.handler(ctx)`；平台不额外调用查票或预约函数。
4. SDK 提交结果；服务端校验信封、注册动作、实际归属及 data Schema，持久化接受记录。
5. 运行期间可通过 collect/batch 多次产出；SDK 得到最终结果接受确认后可触发一次 final `on_outputs(ctx, trigger)` 并提交对应批次；随后执行 `after_action`，最后尽力 `on_cleanup`。产物 Hook 不改业务结果；前置/主动作异常只调用一次 on_error，不递归，若能形成有效 ERROR 结果仍可按授权生成错误报告。
6. 宿主独立停止并回收环境。进程崩溃、强杀、失联不保证任何末尾 Hook 执行。

on_init/before_action/validate_input 不承担主要外部写入；after_action/on_error/on_cleanup 不追加主要业务副作用或修改结果。它们仍是不可信代码，网关不能仅凭 Hook 名证明安全。结果接受后撤销业务出站能力，仅保留有界结果回执/诊断及专用 OUTPUT 上传登记权限；运行中 on_outputs 的临时阶段切换则按[持续运行设计](./02-系统架构与详细设计.md#continuous)暂停业务许可，返回后重新校验并恢复；Hook 本身不取得业务 HTTP 或凭据访问；需要可靠后续业务操作时应在主动作完成前执行，或显式创建下一业务调用。

一次 Run 选择一个注册动作，动作内可以执行多个 HTTP 请求。可选业务扩展可明确编排多次调用，每次独立 Invocation 并持久化推进状态；核心不因动作名称为 book 自动启用旅行流程。跨 Attempt 不依赖 Hook 临时内存。

## 9. 检查点、进度、自定义事件与通知

检查点只保存允许的业务进度，绑定账号、脚本版本、动作和任务，限制大小并加密；不能保存整个进程内存或跨用户恢复环境。读取旧检查点必须验证版本及动作兼容性。检查点不能充当外部操作已成功或可安全重试的证明。

开发者可在 `events` 注册自定义事件及数据 Schema，通过 `ctx.events.emit(name, data)` 或 `ctx.notify.request(...)` 请求通知。服务端校验当前调用、事件声明、数据、用户订阅、收件范围和限额，持久化后进入统一投递链路。去重作用域包含用户、脚本版本、调用、事件及事件键，不能接受脚本任意指定其他用户或邮件地址。事件传输允许重投，跨多次调用的业务去重由用户策略及发布者事件键共同确定。

自定义事件在脚本作用域内命名，界面标明来源；名称相同也不能覆盖平台错误、权限、审计或已核验业务事件。原始参数、凭据不自动进入通知。自定义事件不会自动触发其他脚本或重跑当前动作；外部事件触发与通用 DAG 编排需要另行确定范围。

`ctx.progress.report(stage, cursor_summary=None)` 上报有界脱敏进度，`ctx.wait(seconds)` 可被取消；它们不替代 Runner/Agent 心跳。`ctx.checkpoint.save(value, expected_revision=n)` 只保存检查点，不宣称与此前产物原子提交。需要同步交接时使用 `out.commit(checkpoint=value, expected_checkpoint_revision=n)` 或同参数的 outputs.collect；原子规则见 [检查点事务](./02-系统架构与详细设计.md#checkpoints)。

<a id="outputs"></a>

## 10. 产物 Hook 与公共方法

### 10.1 可多次调用的产物 Hook

发布者可声明 `on_outputs(ctx, trigger)`，每个产出触发对应一个独立批次。trigger 包含 emission_id、batch_key、sequence、reason（explicit/interval/checkpoint/final）、snapshot、result、deadline。运行中 result=null；final 触发携带已经接受的最终业务结果。snapshot 是发布者提供的本次数据，不改写业务 input 或伪造最终结果。

脚本可反复调用 `await ctx.outputs.collect(batch_key, snapshot=...)` 执行 Hook；也可以通过批次公共方法直接输出，不必实现 Hook。可选间隔触发由 SDK 在可让出的安全点串行处理，队列有界、积压合并，不并发调用同一脚本的产物 Hook、不强行中断业务函数。Hook 内嵌套 collect 拒绝，避免递归。每个独立 emission 最多派发一次，但新的 emission 可不断触发。

运行中发布的批次即时进入产物及通知链路，界面标为阶段性产出；它们不结束 Run，也不表示业务已最终成功。主动作结束后的顺序为：接受最终结果及可选末尾 ACTION 批次 → final on_outputs → after_action → on_cleanup → 宿主回收。没有 Hook 或产物不影响原执行流程。

Hook 阶段使用独立 OUTPUT 权限，允许本系列产物操作和平台通知登记，不授予业务 HTTP、连接器或凭据解密。持续执行中切换到 Hook 前，受信任 Runner/网关暂停主动作出站许可并使旧业务令牌失效；等待已登记请求收敛，不能收敛则延后触发或报告 OUTPUT_PHASE_BUSY，不据此认定外部请求失败。Hook 返回后只在租约、账号和任务权限仍有效时发放新的业务许可；final Hook 后不恢复业务许可。直接在主动作使用批次方法不切换阶段，仍受原业务权限约束。函数名和 ctx 对象本身不是安全边界。

每次 Hook 有独立有界 deadline，初始预算 30 秒；持续脚本不会因首次产物 deadline 到期而终止。后台没有可抢占的安全点时，间隔 Hook 可延迟并显示延迟状态，不能宣称按间隔必然准时执行。Hook 失败只影响本次批次，默认继续主动作；显式 output_failure_policy=stop 可请求受控停止，不自动重跑业务。

批次和接受回执丢失只重传已持久化内容/查询回执。默认不重新执行同一 emission 的 Hook；生成失败可使用新的 emission 请求重新生成，必须具有当前授权、输入快照及独立产物权限，不重跑主动作。节点失联且原内存/文件未持久化时明确说明内容不可恢复。最终业务结果接受后的 Hook 失败也不能反转业务结果。

### 10.2 SDK 方法

下表为待实现 SDK 的公共方法。on_outputs 中 ctx.outputs 已绑定本次 emission；主动作可通过 `async with ctx.outputs.batch(batch_key) as out` 建立批次，out 提供相同 text/json/file/bytes/message/get 方法，正常退出提交，异常退出保留明确失败并回收未提交项。显式 `await out.commit(checkpoint=..., expected_checkpoint_revision=...)` 可提前提交本批次；提交后继续输出须创建新批次。after_action/on_cleanup 不再生成正式产物。

| 方法 | 参数 | 返回与作用 |
| --- | --- | --- |
| `ctx.outputs.batch(batch_key)` | 稳定批次键 | 批次上下文/句柄；同 key 查询原状态，新 key 开始一次新产出 |
| `ctx.outputs.collect(batch_key, *, snapshot=None, checkpoint=None, expected_checkpoint_revision=None)` | 触发键、本次数据和可选原子检查点 | 串行执行本次 on_outputs，提交/返回独立批次回执；可以多次调用 |
| `ctx.outputs.text(key, text, *, title=None, media_type="text/plain")` | 稳定 key、字符串；支持 text/plain、text/markdown | OutputRef；保存文本并支持 UTF-8 下载 |
| `ctx.outputs.json(key, data, *, title=None)` | 稳定 key、任意合法 JSON 值 | OutputRef；保存结构化内容，可下载 JSON；不要求旅游字段 |
| `ctx.outputs.file(key, path, *, file_name=None, media_type=None, title=None)` | 本次允许输出目录中的普通文件路径；可指定下载名和 MIME | OutputRef；SDK 流式上传，平台校验实际字节与摘要 |
| `ctx.outputs.bytes(key, content_or_stream, *, file_name, media_type="application/octet-stream", title=None)` | 字节数组或有界流，不把 base64 塞进业务结果 | OutputRef；用于动态生成文件或无法先落盘的内容 |
| `ctx.outputs.message(key, *, title, body, channel_binding_ids=None, format="text/plain", attachments=[])` | 消息内容、本人已绑定渠道 ID、已有 OutputRef | OutputRef；持久化消息，满足条件后进入统一通知链路 |
| `ctx.outputs.get(output_id)` | 本次调用允许访问的已登记 ID | 当前状态、大小、摘要和回执；不返回其他用户对象 |

`key` 在 batch 内唯一；相同文件名或 key 可出现在不同 batch。batch_key 在 output_series_id 内唯一，同一 batch/key 同内容返回原引用，异体报冲突。不同 batch_key 表示新的真实产出，即使字节相同也可以再次通知。受控接续复用系列及稳定业务批次键，可防止已提交批次在重启后重复推送；新任务/配置使用新系列，不自动跨用户/跨任务去重。

`channel_binding_ids=None` 表示读取任务已确认的默认通知绑定，由 SDK 解析成明确 ID 后提交；没有默认绑定返回 CHANNEL_BINDING_REQUIRED。明确空数组不是“全渠道”，应拒绝。脚本不填写任意收件地址、Webhook URL 或设备令牌。用户配置、校验和停用渠道的操作独立于业务 input；脚本可以选择其授权范围内的绑定。

兼容说明：旧 `ctx.artifacts` 文件接口适配为 file/bytes，保留既有文件归属限制；旧 `ctx.notify.request` 走同一消息登记与去重服务。`ctx.events.emit` 仍是自定义事件，不会与同 key 的 message 自动合并；开发者选择一种通知来源或配置明确去重策略，避免同时订阅事件又重复发送消息。legacy 可使用 SDK 包装器产物能力，未接入时保持仅日志行为，不自动扫描整个目录当作输出。

## 11. 产物声明与必需项

发布者可在 `actions.<name>.output_contract` 声明 `required_keys`、`allowed_kinds`、`max_items`，均随版本固定且不能扩大平台限额。不声明时 required_keys=[]、允许四种 kind、max_items=100。required_keys 按每个声明 scope 的批次检查：output_contract.required_scope=batch（默认）或 final。不同批次可反复使用相同必需 key，不实施整个长任务唯一；final scope 只在最终 emission/末尾批次检查。未产生任何批次而声明 final 必需项时，在结束时明确报缺失。

<a id="output-formats"></a>

## 12. 格式、文件处理与产物限额

| 形式 | 示例 | 首期平台行为 |
| --- | --- | --- |
| 文本与数据 | TXT、Markdown、CSV、JSON、JSONL、XML、YAML、日志片段 | 文本/JSON 安全预览；其他可作为文件下载，超大内容截断预览 |
| 办公及报告 | PDF、DOCX、XLSX、PPTX | 保存原文件并下载；没有预览能力时明确显示“下载查看”，不承诺在线编辑或转换 |
| 图像 | PNG、JPEG、WebP、GIF、SVG | 受支持的栅格图像可预览；SVG 默认附件下载，不执行其活动内容 |
| 音视频 | MP3、WAV、MP4、WebM | 原文件下载；可选支持的浏览器媒体预览，不默认转码 |
| 压缩与二进制 | ZIP、GZ、任意自定义扩展名/二进制 | 保留字节、摘要和下载名；不自动解压、运行或安装 |
| 通知消息 | 纯文本、受限 Markdown、附件链接 | 站内与邮件首期可用；其他渠道走注册适配器，不限制脚本业务类别 |

文件类型不是封闭业务枚举。扩展名未知时允许以 application/octet-stream 保存下载；不因为平台不会预览而要求修改脚本业务。MIME 与文件名只是声明，服务器检查实际大小、摘要、基础类型一致性及平台策略，不据扩展名执行内容。HTML/脚本/带活动内容格式默认下载，预览在隔离域或安全渲染器中进行，不共享业务页面执行上下文。

初始可配置限额：单文件 100 MiB、单批次文件总量 500 MiB、单批次最多 100 个产物、文本/JSON 单项 1 MiB、消息正文 16 KiB、标题 200 字符、单消息附件最多 10 个。按 UTF-8 实际字节计正文/JSON 限额；持续任务按批次、账号日预算、总存储、产出速率和并发上传分别限额，不设置“整段长期运行只能有 100 个产物”。用户剩余额度、租约时间和上传期限仍可进一步限制，SDK 上传前提示、服务端持续计量。超限明确失败，不能占满磁盘后才发现。

文件入口默认位于 `/work/outputs`，拒绝越界、路径穿越、符号链接、设备文件和管道；Windows/宿主路径不得成为下载地址。文件打开后按文件描述符读取并复核元数据，避免检查路径后被替换。字节流执行等价大小/摘要校验。输入、输出数据与文件内容按用户私有数据加密存储，不默认写日志或发送到外部通知。

<a id="output-errors"></a>

当前已接入`GET /api/v1/outputs`、`GET /api/v1/runs/{id}/outputs`及`GET /api/v1/outputs/{id}`元数据读取。列表支持run_id、kind、phase、state、from、to、limit和cursor，拒绝其他字段；kind为text/json/file/message，state按script_outputs状态过滤，phase为ACTION或OUTPUT_HOOK。时间为含时区ISO日期时间，from包含、to排除。列表返回顶层data数组、next_cursor与request_id，默认20项、最多100项，按created_at及id倒序。游标签名绑定当前账号、规范化筛选和页大小，保留微秒时间排序，修改筛选需从首页重新查询。

仅本人已提交批次中的产物可列出及读取，运行仍在持续时可以查询已提交产物。删除记录及未提交产物返回404；历史过期或隔离产物保留元数据并返回availability。字段包括id、revision、kind、title、file_name、media_type、size_bytes、status、created_at、updated_at、expires_at、failure_code、batch_id、batch_key、phase、run_id、run_status、task_name、availability、deliveries和content_access_configured。整数字段保持十进制字符串。文件可用性进一步检查对象状态及期限，文本类检查私有正文登记，投递状态单独从本人逻辑投递记录及附件关系读取。响应不含正文、payload/object引用及存储路径，详情返回ETag，读取禁止缓存。

当前content_access_configured为false，表示正文存储与下载适配仍待接入，通知重试、批次历史读取及删除命令也按原契约继续实施。C12用元数据展示实际记录，并区分已就绪、投递未知和适配未接入状态。开发示例的文件、JSON和文本内容在浏览器本地预览，工具栏使用当前选中产物，分类与选中ID保留在URL。

## 14. 产物错误与取消反馈

| 错误/场景 | 处理 |
| --- | --- |
| OUTPUT_KEY_CONFLICT / OUTPUT_BATCH_CONFLICT | 409；查询原回执，禁止覆盖已发布内容 |
| OUTPUT_SCHEMA_INVALID / OUTPUT_REFERENCE_INVALID | 422；提示字段/引用类别，不回显文件正文 |
| OUTPUT_TOO_LARGE / OUTPUT_QUOTA_EXCEEDED | 413/429；停止读取/上传，释放本会话未使用预算；不重跑主动作 |
| OUTPUT_PHASE_CLOSED / OUTPUT_PERMISSION_REVOKED | 409/403；禁止新增，已接受对象保留原记录或按注销流程清理 |
| UPLOAD_CHECKSUM_MISMATCH / UPLOAD_EXPIRED | 422/410；只重传仍授权且可恢复的内容，不能伪造完成 |
| CHANNEL_BINDING_REQUIRED / CHANNEL_BINDING_UNAVAILABLE | 422/409；用户绑定/启用允许渠道，脚本不自行创建收件人 |
| DEPENDENCY_UNAVAILABLE | 消息失败并列出本人可见附件原因；不发送坏链接，不自动删其他成功产物 |
| 结果已接受后 Hook 超时/崩溃 | 生成阶段失败/部分完成，业务结果不变；宿主继续回收 |
| 取消、冻结、注销或版本撤销 | 撤销相应生成/上传/投递权限；停止未开始 Hook；在途上传回执可核对，不能以补传重新获得执行权限 |

## 15. 开发者产物示例

以下为待实现 Python SDK 的接口示意；`ctx.outputs` 由平台提供，不是本仓库已发布的软件包。业务参数来自脚本自己的 Schema，通知渠道来自用户配置。下面的 fetch_next_page/make_csv_bytes 是开发者业务函数；ctx.wait 为可取消等待，collect 同事务提交本批产物及检查点。示例为接口伪代码，没有连接真实来源。

```python
async def watch_records(ctx):
    cursor_record = await ctx.checkpoint.load()
    while not ctx.signal.cancelled:
        page = await fetch_next_page(ctx.http, ctx.input, cursor_record.value)
        if not page.changed:
            await ctx.wait(5)  # SDK 可中断等待，不忙轮询
            continue
        receipt = await ctx.outputs.collect(
            f"page.{page.stable_id}", snapshot={"records": page.records},
            checkpoint=page.next_cursor,
            expected_checkpoint_revision=cursor_record.revision)
        cursor_record = await ctx.checkpoint.load()  # 重投旧批次也不回退当前游标
    return {"outcome": "COMPLETED", "data": {"stopped": True}}

async def produce_report(ctx, trigger):
    if trigger.reason == "final":
        summary = await ctx.outputs.text("summary", "持续执行已结束")
        await ctx.outputs.message("notice", title="执行已结束",
                                  body="末尾产物已保存。", attachments=[summary])
        return
    records = trigger.snapshot["records"]
    report = await ctx.outputs.json("records", records)
    csv_file = await ctx.outputs.bytes(
        "csv_report", make_csv_bytes(records),
        file_name="report.csv", media_type="text/csv")
    await ctx.outputs.text("summary", f"本批 {len(records)} 条记录")
    await ctx.outputs.message(
        "notice", title="本批报告已生成", body="请登录平台查看。",
        attachments=[report, csv_file])
```


清单将 `hooks.on_outputs` 映射为 `produce_report`，两个方法可在整个 Run 中反复触发多个批次。生成 XLSX/PDF/图片等文件时，开发者先用锁定依赖在 `/work/outputs` 写文件，再调用 file；无须平台为每个扩展名新增业务 API。文件生成所需额外外部数据应在主动作阶段获取并按预算保存，不能在产物 Hook 中重新调用业务接口。

<a id="continuous-config"></a>

## 16. 持续运行与恢复字段

持续运行配置包括 run_mode、restart_policy、可选 max_uptime_seconds、stop_grace_seconds、output_failure_policy、可选 output_interval_seconds 和 idle_policy。interval 仅决定产物 Hook 请求频率，不是创建新 Run 的 Cron。具体秒数受管理员最小间隔/资源策略限制，积压合并且可观测。

runtime 包含 run_mode、deadline、lease_expires_at、output_deadline、output_series_id 及请求/实际模式。finite 的业务和末尾期限有界；continuous 业务/产物流总期限可空，但当前租约与每次 Hook/上传期限不能省略。恢复要求动作声明固定的 resume_handler 与 checkpoint_schema；普通 legacy 不从循环或通知桥接推断恢复能力。具体约束见 [持续运行状态和恢复](./02-系统架构与详细设计.md#continuous)。

## 17. 已有脚本适配与有限青龙兼容

标准 hooks 脚本继续使用脚本协议 2.0。legacy 仍只有一个默认动作；可在封存包中附带 [legacy-adapter.schema.json](./contracts/legacy-adapter.schema.json) 所描述的配置，独立 `adapter_protocol_version=1.0`。不修改脚本协议 2.0，也不向其严格 manifest 增加未知字段。

发布服务将适配文件登记到封存制品索引，固定 `adapter_path`、`adapter_digest`、`adapter_protocol_version`、`source_digest`、`manifest_digest`、`runner_adapter_digest`。无适配登记的旧版本保持原行为，Runner 不根据目录中存在某个文件自行启用适配。构建、调度和 Agent 均检查能力 `legacy-adapter/1.0`；不支持时在派发前拒绝，不能降级忽略参数、文件或通知。

| 配置 | 语义 |
| --- | --- |
| `action` | 必须等于 legacy manifest 的唯一 default_action |
| `argv` | 参数 token 数组；每项为固定 literal 或 input 的 JSON Pointer 与 encoding，不含解释器/入口，禁止 shell=true 或模板 eval |
| `env` | 显式变量名映射；来源为 input 或已声明并由本人绑定的 credential_alias |
| `config_files` | 从 input 的 JSON Pointer 生成 JSON 文件，路径相对 `/work/input`；0600、独立目录、只读交付脚本 |
| `outputs` | none、final 指定文件清单，或 manifest 连续交接；不扫描整个工作区 |
| `notification_bridge` | disabled 或 qinglong_subset；只启用逐项选择的通知方法 |

解释器由固定镜像和 manifest.language 选择，程序入口由 manifest.entrypoint 选择；参数单独传递。副作用声明与真实出站授权仍由 manifest/任务控制，适配不能授予额外权限。包内入口、锁文件及适配路径都不能越界。

能力页分别显示输入映射、日志、文件产物、通知、结构化结果、检查点恢复的实际支持情况。附加适配不自动获得结构化结果；有效结果必须通过原 2.0 协议和发布者 output_schema 校验。没有结构化结果时只显示 PROCESS_EXIT。普通 legacy 不具备合格 resume_handler，restart_policy 固定 never；希望安全恢复须发布标准 hooks 封装版本并实现既有恢复契约。

### 17.1 参数、环境与依赖边界

先按发布者有效 Schema 校验原 input，再进行映射；映射是传输编码，不改变原输入、必填规则或保存的类型。JSON Pointer 按 RFC 6901 解码，空串指向根；不存在与值为 null 分开。argv 映射可带 `flag`，有值时生成相邻的标志和值两个 token，缺失时整组省略，避免留下孤立选项；无 flag 的可省略位置参数须由发布者确认入口语义。`on_missing=omit` 省略该参数组/变量/文件；`error` 产生 ADAPTER_MAPPING_ERROR，不能由适配配置新增隐藏的用户必填项。发布检查须证明 error 对应路径在所有允许输入分支存在；无法证明时要求 omit 或由发布者显式修改 Schema。

`encoding=string` 只接受字符串；`json` 将任何合法 JSON 值编码一次为紧凑 JSON，布尔值/数字不被猜测成字符串类型。argv 中 `$()`、反引号、空格、引号都作为普通参数字符，不经过 Shell。argv 不接受 credential_alias；含敏感业务字段的输入必须映射到受限文件或凭据绑定，不能展示到命令预览和进程参数。

env 不继承全站或宿主业务环境。系统只注入平台固定并自动校验的基础环境与本次租约上下文；发布者不能覆盖 PATH、HOME、TMPDIR、PYTHONPATH、PYTHONHOME、PYTHONSTARTUP、NODE_OPTIONS、NODE_PATH、LD_*、DYLD_*、TT_* 等执行/加载器变量。变量重名拒绝，不以覆盖顺序解决。凭据 alias 必须在 manifest 声明并由该用户授权绑定，缺失可选绑定仅在 omit 时省略；值带 NUL 或超过编码预算拒绝。密钥轮换不在运行中的进程里静默替换旧环境；旧授权失效时按撤权流程处理。

config_files 路径只能是受控相对路径，不允许 `..`、绝对路径、反斜杠、设备或链接；重复和父子路径冲突均拒绝。首期只生成 JSON，不处理 Shell/YAML 模板表达式。示例与参考映射检查见 [适配样例](./contracts/examples/mapped.adapter.json) 和 [校验脚本](./checks/validate-adapter-contracts.py)。映射总大小建议 1 MiB，单变量建议 32 KiB，仍服从系统进程参数实际限制。

### 17.2 Hook、通知桥接与文件交接

标准脚本中心提供 on_init/before_action/on_outputs/after_action/on_cleanup 模板以及每阶段测试反馈，Hook 可选且随版本封存。旧脚本若需要自定义前后处理，可由开发者封装为标准 hooks 脚本；首期兼容描述文件不接受任意 task_before/task_after Shell 字符串。前置失败不运行主动作；已接受结果后的后置失败只记录阶段错误。

通知桥接是本项目拟实现的有限兼容层：JS `sendNotify.send(title, content)`、Python `notify.send(title, content)`、JS/Python `QLAPI.systemNotify({title, content})`。只能使用匹配语言且在配置中显式列出的入口；已有同名模块冲突时要求发布者迁移导入路径或明确替换，不能悄悄覆盖依赖。未列签名、第三个配置参数、notificationInfo、任意收件人及 QLAPI.getEnvs/createCron/runCrons 等管理方法返回 ADAPTER_UNSUPPORTED，不透传面板 token。

桥接在当前 Invocation 内给每次有意调用分配递增事件号，先持久化本地受限队列，再用稳定键向产物服务登记 message；同一次传输重试复用键，不同调用可再次发送。通知渠道仅来自任务用户绑定；返回 registered 表示登记接受，实际 SENT/FAILED/UNKNOWN 在通知页查看，不声称用户已收到。接收回执丢失只查回执或重投，不重跑主脚本。这里去重仅覆盖桥接器对同一次登记的传输重试；脚本主动再次调用通知方法会创建新消息，桥接器不猜测是否为业务重试。进程/节点丢失且未完成登记的消息可能丢失，明确显示待确认范围；不得为了补通知自动重启 legacy。需要跨故障业务级去重时改用原生批次键与检查点。

文件采集两种方式：

- `final`：仅在主进程及子进程停止写入后，读取配置中的明确文件清单，建立 `final.<invocation_id>` 批次。文件不存在标记缺项；发生进程错误仍可按授权保存已有诊断产物，不改变业务终态。超时/取消并不保证末尾采集完成。
- `manifest`：脚本先写完整文件并关闭，再把符合 [legacy-emission.schema.json](./contracts/legacy-emission.schema.json) 的清单从临时文件原子改名到 `/work/outputs/<manifest_dir>` 下的 `.json` 文件。每份清单显式 batch_key、output_key、相对文件路径、媒体类型、字节数和 SHA-256；同一个进程可反复交接多个批次。Runner 只消费已完成交接的清单，不按文件 mtime 或日志关键词推断产物。

两种方式均通过既有上传/批次服务登记。交接清单本身也须拒绝链接/特殊文件、限定读取目录和单份 1 MiB 上限；读取后固定清单摘要，不能再次信任同一路径被替换的内容。Runner 对文件使用受限目录句柄、拒绝链接/特殊文件、核验采集前后元数据及真实字节摘要并复制到不可变暂存；发生修改则拒绝本次交接。禁止把仍在增长的同一文件直接暴露给下载端。manifest 模式按既有 `(output_series_id,batch_key)` 幂等，同键异体冲突；每批只能出现一次 output_key，可在新批复用。

交接队列、待采字节与目录有配额和背压；产物服务不可用时有界重试，超额按 output_failure_policy 继续并报错或受控停止，不无限占用内存/磁盘。消费 ACK 查询和同键重传不产生新文件/消息。采集授权随租约检查，晚到清单不能越过撤权。普通 legacy 的文件清单不提供检查点原子提交承诺；需要该能力时用原生 SDK 的 batch+checkpoint。

### 17.3 长期兼容脚本

已有脚本可在同一专属环境内持续循环，使用 adapter manifest 清单或有限通知桥接多次产出。它沿用本文件 service/manual、短租约、滚动用量、背压和停止规则，不使用高频 Cron 反复启动。只有 final 文件采集的脚本，在进程结束前不会自动产生文件批次；界面应提示改用连续交接或原生产物 SDK。

普通 legacy 未实现标准 resume_handler 时，restart_policy=never；桥接队列只重试产物登记，不在失联后重跑整个脚本以补消息。停止先撤销新业务许可，在独立有界产物宽限期内处理已完成交接，强制结束不保证最后批次成功。阶段性产物发布不会结束 Run，也不证明业务进度正常。适配约束见 [接口协议与脚本开发规范](./03-接口协议与脚本开发规范.md#legacy)。

<a id="agent"></a>

## 20. 节点与 Guest Agent 协议

管理员登记节点 → 发放短时单次 bootstrap token（仅登记用途）→ 节点取得限定 node_id 的 mTLS 证书 → 注册能力/镜像摘要/协议版本 → 健康检查后可调度。证书轮换有短重叠窗口，撤销同步至网关；普通脚本不能读取节点或 Agent 私钥。

Runner 与 Guest Agent 的每条控制消息包含 protocol_version、message_id、node_id、attempt_id、lease_generation、sequence、sent_at、deadline、payload_digest。Agent 首次握手绑定本 Attempt 的启动随机挑战及镜像摘要；重复 message_id 同摘要返回原回执，异体拒绝；旧代数仅允许受限晚到证据，不领取新命令。指令为 prepare/start/stop/inspect/collect-result，用户不能传任意宿主命令。

心跳与状态回复只延长服务端认可的当前租约。日志按独立分段/序列上传，不能以日志心跳延长执行授权。断连时有界缓冲，网络许可到期自动失效；节点无法保证执行出口封锁时保持不可调度并隔离资源。结果 ACK 与日志 ACK 不互相替代。

建议使用专属管理网络上的 mTLS 通道，由 Agent 向 Runner 领取本次任务并回传心跳和结果。该通道只暴露给对应 Attempt，不转发到控制数据库和宿主管理接口。实现时优先复用已验证的连接机制，不让普通用户配置转发端口。

Agent 与脚本使用不同系统身份；Agent 管理凭据放在脚本不可读的目录，任务可用令牌仅有本 Attempt 的短时能力。脚本不可访问 QMP socket。即使客户机被攻破，任务级令牌也不能升级为其他用户或节点控制权限。

凭据在环境就绪后经受控通道注入内存文件系统，不写入基础镜像、qcow2 模板、cloud-init seed、容器标签或日志。请求脚本自行签名且必须接触凭据时，明确凭据暴露范围，不能声称 Agent 已完全隐藏它。

Agent 注册、单次启动挑战、mTLS 身份、message_id/sequence/lease_generation、防重及证书轮换按[节点、Guest Agent 与配置契约](./03-接口协议与脚本开发规范.md#agent)实现。旧代数不能领取新命令；日志 ACK、结果 ACK 与租约续期互相独立。失联节点若不能确认出口封锁则保持隔离，不重新分配残留环境。

## 21. 日志类别、事件字段与独立版本

| 来源 | 主要内容 | 普通用户可见内容 |
| --- | --- | --- |
| API / 鉴权 | 模板路由、耗时、状态、受控错误码 | 与本人操作有关的简明错误与请求编号 |
| Scheduler / Dispatcher | 触发、排队、配额、模式解析和分配 | 本人任务的阶段、等待原因和模式 |
| 构建 | 依赖下载、构建结果和制品摘要 | 发布者本人的脱敏构建日志；服务仅公开发布者明确公开的说明和能力信息 |
| Runner / 运行时 | 启动、退出、OOM、超时、租约和清理 | 本人运行的可解释结果；内部节点细节按管理权限展示 |
| 脚本 stdout/stderr | 原始程序输出经规范化和脱敏 | 本人输出，明确标识脚本自报 |
| HTTP Broker | 连接器动作、状态类别、耗时、限流和提交许可 | 本人请求摘要，不含完整报文 |
| 兼容代理 | 目标类别、连接、字节、拒绝原因 | 本人连接摘要；不能声称看到 HTTPS 内每次请求 |
| Reconciler | 查询订单、核验结果和下次处理时间 | 本人的订单核验时间线 |
| Notifier | 投递尝试、服务商状态、重试和去重 | 本人通知的投递状态 |
| 审计与安全 | 权限变更、凭据授权、管理查询、策略拒绝 | 与本人相关的安全记录摘要；不暴露全平台攻击详情 |
| 监控自身 | WAL、接入、索引、丢弃、查询和告警投递 | 与本人运行有关的缺口提示，其余为管理员数据 |

### 21.1 标准字段

字段名称是本项目 JSON 协议，不声称与 OTLP 编码完全一致。时间、级别、Body、Trace 与 Attributes 按 OpenTelemetry 数据模型映射。[OTel 日志模型](https://opentelemetry.io/docs/specs/otel/logs/data-model/)

| 字段 | 类型 / 规则 | 写入者 |
| --- | --- | --- |
| `schema_version`、`event_id` | 版本字符串、稳定唯一 ID | 可信 SDK/采集端；重试保留原 ID |
| `timestamp`、`observed_at` | 来源时间可空；可信采集观察时间，UTC | 来源时间不作为订单时序依据 |
| `severity_text`、`severity_number` | TRACE/DEBUG/INFO/WARN/ERROR/FATAL，映射 1/5/9/13/17/21 | 未解析脚本 stdout 默认 INFO；stderr 不自动代表业务失败 |
| `service`、`environment`、`source_kind` | 服务与来源枚举 | 采集配置；不可由脚本任意增加标签 |
| `trust_level`、`visibility` | PLATFORM/SCRIPT；USER/PLATFORM/SECURITY | 可信服务端分配 |
| `owner_user_id` | 私有任务日志必填；平台公共诊断为空 | 根据已鉴权任务/构建映射填充 |
| `task_id`、`run_id`、`attempt_id` | 按来源可空，必须属于同一链路 | 可信任务上下文 |
| `invocation_id`、`action_name`、`hook_name`、`hook_protocol_version` | action_name 来自版本注册表，hook_name 为有限生命周期名称；无相关来源可空 | 调用归属由平台校验；名称作为结构化字段而非索引标签，SDK 观测不提升可信程度 |
| `booking_operation_id`、`notification_id` | 可空的业务关联 | 业务服务，不接受脚本覆盖 |
| `requested_execution_mode`、`actual_execution_mode` | 三种模式枚举；实际尚未分配时为空 | Dispatcher / Runner |
| `node_id`、`script_version_id`、`image_digest` | 管理与版本关联 | 可信执行上下文 |
| `trace_id`、`span_id` | 可空的有效追踪标识 | 平台上下文；不盲信脚本字段 |
| `source_instance_id`、`source_seq` | 采集会话 ID 与递增序号 | 每次源连接独立计数 |
| `event_name`、`message`、`attributes` | 受控事件名、文本、限额字段 | 模板字段允许列表；脚本内容放入受限命名空间 |
| `redaction_version`、`truncated` | 脱敏规则版本、截断标记 | 采集与接入服务 |

## 22. 日志查询、SSE、导出与运维 API

### 22.1 查询规则

用户提交任务、运行、来源、级别、关键词和时间范围等固定字段。服务端先检查会话及账号状态，再根据用户 ID 验证目标归属，生成不可被覆盖的查询条件。关键词按字面值转义，首期不开放任意正则、LogQL、PromQL 或标签表达式。

Loki 索引只使用 `environment`、`service`、`source_kind`、`actual_execution_mode` 等有限标签；用户、Run、Attempt、脚本版本、Trace 和订单 ID 放入结构化元数据或 JSON 字段。查询服务强制匹配可信 `owner_user_id` 和 `visibility`，还须校验返回记录的归属。不能把“非索引字段”理解为不需要权限过滤。[Loki 标签设计](https://grafana.com/docs/loki/latest/get-started/labels/)

用户跨全部任务检索可能需要扫描较多数据，因此先在数据库缩小本人 Run/分段范围，限制时间及扫描字节；最近 7 天优先走 Loki，8～30 天通过 `log_query_jobs` 异步扫描授权归档。若没有足够索引性能，返回排队状态或更小时间窗口，不取消权限条件换取速度。

缓存键包含账号、权限版本、过滤条件和数据版本。下载、导出执行、结果领取均重新校验权限；账号停用时终止后续订阅和下载。普通用户的 404/无权响应不得泄露其他用户对象是否存在。

### 22.2 SSE 事件协议

沿用 `GET /api/v1/runs/{id}/events`，统一承载运行详情的类型化事件：

| `event` 类型 | 内容 | 事实来源 |
| --- | --- | --- |
| `run.status` | 状态、阶段与业务版本 | 数据库事件投影 |
| `log.entry` | 脱敏日志与日志事件 ID | 已归档记录的实时投影 |
| `log.gap` | 已知丢弃或无法确定的采集缺口 | 可信采集健康信息 |
| `log.truncated` | 容量上限与受影响来源 | 配额事件 |
| `stream.degraded` | 索引、实时缓存或采集延迟 | 平台健康状态 |
| `stream.closed` | 当前订阅关闭原因 | 订阅服务 |

SSE `id` 使用服务端签名的不透明游标，绑定用户、Run、过滤条件及投影位置，日志自身 `event_id` 放在 payload。`Last-Event-ID` 必须在每次连接鉴权后验证。单连接顺序不等于跨服务因果顺序，前端按日志事件 ID 和业务版本去重。

游标仍在缓存时重放后继续订阅；缓存已淘汰则返回明确的游标过期信息（连接建立前 HTTP 410，已建立连接发送类型化提示），由客户端申请归档补读再建立新订阅。业务事件可由数据库补偿；日志未归档或采集丢失的部分必须显示缺口，不能无提示跳到末尾。

建议心跳 15 秒、每用户最多 3 个实时连接；订阅每 60 秒复核会话和权限，撤销事件主动断开。使用安全会话或请求头，不把长期令牌放在 URL。网络错误采用有上限的退避重连，用户退出页面立即关闭订阅。

Run 进入终态不立即宣告日志完整；清理和日志上传可能仍在继续。订阅展示独立的清理状态和日志收尾状态，收到来源结束及归档进度后再关闭，达到收尾超时则明确提示剩余数据待补传。用户主动离开不改变后端采集，迟到记录可以从历史页面查询。

### 22.3 导出

创建导出任务时固化用户、范围、过滤条件、格式与脱敏规则版本。后台执行时再次检查权限，分页读取授权分段；生成压缩 JSONL 或纯文本，附带时间范围、截断和缺口说明。导出文件 24 小时后清理，下载通过鉴权 API；如采用预签名 URL，最长 5 分钟且明确该链接有效期内具有持有者访问能力，删除时同步撤销可控入口。

导出任务状态为 `PENDING/RUNNING/SUCCEEDED/FAILED/CANCELLED/EXPIRED`。不提供原始未脱敏导出、全工作目录下载或虚拟机内存转储入口。

个人概况`GET /api/v1/monitoring/overview`接受可选from、to，使用含时区的ISO日期时间，窗口为from包含、to排除，默认截至请求时刻的最近30天。拒绝owner及其他筛选键。响应含as_of、window、counts、services、orders、activity、pending、results、fees。counts含unused_entitlements、in_progress、pending_actions、processing_refunds、tasks、runs、ready_outputs、entitlements，均为十进制整数字符串。当前可用权益、活跃Run、待办、退款处理和可用产物按查询时刻汇总，tasks及runs历史计数采用窗口，较早创建的长期Run继续计入当前进行中。

首页服务与订单各最多3条，运行动态与最近结果各最多2条，待办最多1条，按相应时间及id倒序。服务采用成交release标题与说明，订单及产物只返回本人元数据。结果来自已提交批次中仍可用的READY产物，文件还需对象登记READY且在保留期内，运行过程可以持续产出。fees按currency分别返回funded_service_fee_minor及refunded_service_fee_minor字符串，前者为窗口内已绑定主收款的服务单费用，后者为已确认退款，不汇总额外收款或钱包余额。聚合在同一查询快照完成，详情和下载继续独立鉴权。

统一错误包括 `FORBIDDEN`、`CURSOR_EXPIRED`、`LOGS_EXPIRED`、`QUERY_TOO_WIDE`、`RATE_LIMITED`、`INDEX_DELAYED`、`ARCHIVE_PENDING`、`SERVICE_UNAVAILABLE`。HTTP 状态码与提示一致，后台处理中采用 202 或状态查询，不以空数组代替故障。

| `GET /api/v1/admin/services` | `catalog.manage`，`view`支持`services`或`versions`，默认`services`，支持`q`、`status`、`limit`和`cursor` | `id`、`kind`、`title`、`owner_user_id`、`status`、`revision`、`created_at`、`publisher`、`release_id`、`script_version_id`、`script_id`、`version`、`content_status`、`deployment_status`、`development_fixture`、`entitlement_count` |

`entitlement_count`按商品全部发布版本或所选脚本版本统计PENDING、ACTIVE、RESERVED权益，校验订单、消费者、发布者及发布版本关联，保留已预留权益和有效期内待使用权益。响应限定于上述字段。风险核验、冻结、配额修改、停销恢复和执行撤销接口继续实施，LIVE页面显示其接入状态。本地管理预览使用独立记录修订，重复确认保留一次处理记录，撤销版本通过新版本完成后续修复。

| 查询 | 参数 | 返回字段 |
| --- | --- | --- |
| `GET /api/v1/admin/cities` | `q`匹配名称、代码或UUID，`enabled`为`true`或`false`，支持`limit`、`cursor` | `id`、`code`、`name`、`enabled`、`revision`、`created_at`、`attraction_count` |
| `GET /api/v1/admin/attractions` | `q`匹配名称或UUID，可按`city_id`及`enabled`筛选，支持`limit`、`cursor` | `id`、`city_id`、`name`、`description`、`timezone`、`enabled`、`ticket_price_kind`、`revision`、`created_at`、`city_name`、`city_enabled`、`channel_count`、`rule_source_count`、`linked_service_count` |
| `GET /api/v1/admin/channels` | `q`匹配渠道名、渠道UUID或景点名，可按`attraction_id`及`status`筛选，支持`limit`、`cursor` | `id`、`attraction_id`、`name`、`official_url`、`timezone`、`adapter_status`、`revision`、`created_at`、`attraction_name`、`city_id`、`current_rule_version_id`、`rule_version`、`source_url`、`verified_at`、`has_evidence`、`rule_binding_state` |
| `GET /api/v1/admin/channels/{id}/rules` | `id`为渠道UUID，支持`limit`、`cursor`，不存在的渠道返回404 | `id`、`channel_id`、`version`、`revision`、`created_at`、`source_url`、`verified_at`、`has_evidence`、`is_current` |

渠道筛选`status`使用数据库的UNVERIFIED、MONITOR_ONLY、BOOKING_SUPPORTED、DEGRADED、DISABLED，分别展示为未验证、仅监控、支持预约、降级、已禁用。规则关联同时校验当前版本编号与所属渠道，`rule_binding_state`取BOUND、UNBOUND、INVALID。未绑定和关联异常时，规则版本、来源及验证时间为null。规则历史按创建时间和编号倒序分页，`is_current`仅标记当前绑定版本，较高版本号和较新创建时间分别保留各自事实。`has_evidence`仅表示存在非空证据元数据，验证文件和规则正文查询继续实施。

修订与计数采用十进制字符串，规则`version`为正整数。景点票价类型沿用FREE，页面将门票0元与脚本服务价格分开。城市字段读取`code/name/enabled`，时区读取景点与渠道的`timezone`。`rule_source_count`统计各渠道有效当前规则的不同非空来源，`linked_service_count`按服务去重并校验发布者及渠道所属景点，关联异常的记录继续留在数据库供排障核验。目录启用、渠道能力与商品可售检查分别展示。

`GET /api/v1/admin/services`增加可选`attraction_id`，服务视图只返回该景点的有效商品关联，版本视图返回相关商品历史发布所用版本，并校验发布者及渠道所属景点。签名游标绑定该筛选。景点资料中的渠道、规则及服务页签使用上述分页查询，直接访问位于后续城市分页中的UUID可单独定位城市。规则来源链接使用HTTP或HTTPS地址并排除URL用户信息。城市景点维护、渠道能力升级、适配器绑定、验证内容及未决预约敏感查询继续接入，界面保留对应状态说明。


<a id="admin-runtime-metadata-reads"></a>
### 节点镜像与调度元数据查询实现

2026-11-15接入以下基础设施查询，要求ADMIN角色及`runtime.manage`。接口使用会话鉴权和`Cache-Control: no-store`，分页沿用签名游标、默认20条、最多100条及严格参数校验。游标绑定当前账号、安全修订、资源与筛选。`q`最长200字符，通配符按字面匹配。非法参数返回422，能力不足返回403，节点UUID不存在返回404。

| 查询 | 参数与范围 | 返回字段 |
| --- | --- | --- |
| `GET /api/v1/admin/nodes` | 无参数时为兼容列表入口，按创建时间倒序最多100条 | `id`、`name`、`status`、`capabilities`、`last_heartbeat_at` |
| `GET /api/v1/admin/nodes?view=metadata` | 分页查询显式携带`view=metadata`，支持`q`、`status`、`limit`、`cursor` | `id`、`name`、`status`、`revision`、`created_at`、`last_heartbeat_at`、`clock_offset_ms`、`isolation_epoch`、`cpu_cores`、`memory_mib`、`active_leases`、`expired_unrevoked_leases`、`cleanup_pending`、`cleanup_failed` |
| `GET /api/v1/admin/nodes/{id}` | `id`为UUID，读取单个节点元数据 | 与节点分页视图相同 |
| `GET /api/v1/admin/images` | `q`匹配镜像名、摘要或UUID，`status`取DRAFT、READY、RETIRED、REVOKED，`mode`取docker、qemu_kvm、qemu_tcg，支持`limit`、`cursor` | `id`、`name`、`digest`、`language`、`version`、`architecture`、`modes`、`status`、`revision`、`created_at`、`has_evidence`、`development_fixture` |
| `GET /api/v1/admin/scheduling` | 无查询参数，一条SQL读取当前状态快照 | `as_of`、`counts`及`modes` |
| `GET /api/v1/admin/scheduling/quotas` | 读取GLOBAL、NODE范围，`q`匹配`resource_key`或`scope_key`，支持`limit`、`cursor` | `id`、`scope`、`scope_key`、`resource_key`、`window_start`、`revision`、`created_at`、`limit_amount`、`reserved_amount`、`consumed_amount`、`available_amount` |

节点`status`读取REGISTERING、ONLINE、DRAINING、OFFLINE、QUARANTINED。分页及详情视图限定于上述字段，硬件上报读取可选`capabilities.cpu_cores`和`capabilities.memory_mib`，分别表示核数及MiB。支持非负整数或规范十进制整数字符串，范围至有符号64位上限，缺失或格式无效时返回null。0保留为已报告数值。硬件数量、修订、隔离纪元、时钟偏差及计数使用十进制字符串，空心跳或偏差保留null。

`active_leases`校验Run、Attempt及所有者关联与租约代数，要求未撤销且未过期，Attempt处于CREATED、PREPARING、RUNNING、STOPPING，Run处于PREPARING、READY、RUNNING、STOPPING、WAITING_INPUT、RECONCILING。`expired_unrevoked_leases`统计关联及代数有效、已过期且未撤销的租约。环境回收计数校验Attempt、所有者和节点关系，`cleanup_pending`统计已停止且处于PENDING或RUNNING的环境，`cleanup_failed`统计FAILED记录。清理证明和恢复资格继续通过工作节点证据查询接入。

调度`as_of`表示数据库查询快照时间。`counts.queued_runs`统计QUEUED，`active_runs`统计PREPARING、READY、RUNNING、STOPPING，`waiting_bookings`统计READY、SUBMITTING、UNKNOWN预约操作。统计覆盖当前所有记录，包含历史创建且持续运行的Run。`modes`按实际docker、qemu_kvm、qemu_tcg分别返回`active_leases`及`expired_unrevoked_leases`，`counts.unreported_mode_leases`保留实际模式为空的有效租约。页面提供快照时间与手动刷新入口。

容量配额按`scope/scope_key/resource_key`分别选取最近已开始的窗口，可用量为上限减预留及消耗，各项均为十进制字符串。不同范围、资源及窗口分别展示。镜像`status`和`has_evidence`分别展示，证据存在标记仅表示非空元数据。按模式容量总量、使用率、调度控制、TCG许可、环境清理证明和镜像验证内容继续接入。原型中的摘要复制使用明确标识的固定本地镜像样例，实际镜像查询读取存储摘要。

<a id="admin-diagnostics-metadata-reads"></a>
### 运行与可观测性元数据查询实现

2026-11-15接入以下管理查询。运行接口沿用O15的ADMIN及`runtime.manage`，平台日志分段和告警查询要求ADMIN及`runtime.observe`。各接口设置`Cache-Control: no-store`，分页默认20条、最多100条，按创建时间及UUID倒序。签名游标绑定账号、安全修订、查询资源、筛选和页大小。参数严格校验，重复参数、未知参数、无效状态和时间返回422，能力不足返回403，运行不存在返回404。

| 查询 | 参数与范围 | 返回内容 |
| --- | --- | --- |
| `GET /api/v1/admin/runs` | `q`按字面匹配运行、任务或脚本版本UUID，`status`使用13种Run状态，`node_id`匹配最近尝试的节点，`run_mode`取finite或continuous，支持`limit/cursor` | 运行编号、修订、任务及脚本版本编号、运行类型与状态、外部效果及核验状态、完成方式、结束及进展时间、停止请求及期限、重启数、当前接续序号和`latest_attempt` |
| `GET /api/v1/admin/runs/{id}` | UUID直接定位，详情不接受查询参数 | 与运行列表相同的单条元数据 |
| `GET /api/v1/admin/observability/logs?view=segments` | 显式指定segments，查询平台分段清单；`q`匹配来源实例或UUID，`status`取COMMITTED、MISSING、DELETED，支持`from/to/limit/cursor` | 分段编号、修订、来源实例、序列起止、字节数、日志起止时间、归档及索引状态、过期时间与`expired` |
| `GET /api/v1/admin/observability/alerts` | `q`匹配规则键或告警UUID，`status`取FIRING、ACKNOWLEDGED、RECOVERED，`severity`取INFO、WARNING、CRITICAL，支持`from/to/limit/cursor` | 告警编号、修订、规则编号及键、规则版本、发生次数、状态、首次及最近出现时间、恢复记录时间、处置事件数及附证据事件数 |

`latest_attempt`按同属运行及用户的`attempt_no`倒序取最新尝试，缺失时为null。返回尝试编号、序号及状态、节点编号、请求与实际执行方式、起止时间、退出码、租约代数及状态、过期与心跳时间，以及环境停止时间和清理状态。租约校验同属用户、运行、尝试及代数，状态取ABSENT、MISMATCHED、REVOKED、EXPIRED、ACTIVE、INACTIVE。ACTIVE沿用节点统计的有效租约生命周期。代数或尝试不匹配时，租约时间保留null。清理关联同时校验用户和节点，未建立环境记录时状态为null。运行结果、外部效果、核验、租约和清理分别展示。

日志及告警时间参数接受含时区ISO时间，显式指定两端时要求from早于to。分段采用`ended_at>=from`及`started_at<to`重叠范围，告警采用`last_seen_at>=from`及`first_seen_at<to`。未指定时间时覆盖全部现存记录。页面时间选择将查询时刻固定为URL中的from和to，分页与刷新沿用该时间范围，清除后恢复全部时间。运行查询覆盖历史创建的持续运行。

修订、接续序号、租约代数、日志序列及字节数、告警发生次数和计数使用十进制字符串。运行查询限定于控制面字段。平台分段字段使用上述投影，正文检索和导出继续接入。分段成功读取追加`ops.logs.segments.read`审计事件，包含请求编号、视图、返回条数和时间边界。告警的`evidence_event_count`表示存在非空附证据事件的数量，恢复状态直接读取告警实例，恢复证据正文查询继续接入。

运行停止、隔离、独立核验、关联告警定位、敏感正文及限时排障会话签发继续接入。告警确认、静默持久化、规则同步及日志正文读取和导出继续实施。O15/O16本地原型保留示例交互，运行选择和日志/告警筛选保存在URL，规则草稿按所选规则恢复完整字段并逐版保存，有限静默到期自动更新界面。
